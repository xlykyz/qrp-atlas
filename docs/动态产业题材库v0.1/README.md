>
> 基准日期：2026-07-15
>
> 适用范围：QRP v1.0 之后的产品增量，不改变已封版的核心架构
>
> 数据说明：本成果仅定义需求与契约，不读取、修改或生成本地数据库及行情数据

## 1. 一句话定义

动态产业-题材库不是“概念板块列表”，而是一套把 **产业结构、题材叙事、事件催化、标的证据和市场反馈** 按时间组织起来的个人 A 股研究工作台。

用户应能回答五个连续问题：

```text
现在什么在发生？
→ 为什么发生？
→ 沿产业链影响谁？
→ 哪些公司真的相关，证据是什么？
→ 热度、强度和逻辑正在增强还是衰减？
```

## 2. 核心产品决策

1. **行业、产业链、题材分模建库**：行业是稳定分类，产业链是多对多关系图，题材是事件驱动、可分歧、会衰减的动态对象。
2. **证据优先于标签**：每条“公司属于题材”的关系必须能回到来源、原文片段、时间和判断理由；未知比错误归类更可接受。
3. **事实层与评分层分离**：原始来源、成员快照、行情事实不可被 AI 改写；热度、强度、生命周期和相关度属于可重算的派生结果。
4. **动态监测不等于荐股**：系统输出变化、异常、证据和风险，不输出买卖指令，不用大模型直接产生不可解释分数。
5. **先日频闭环，再盘中增强**：MVP 使用盘后数据完成可回放、可复现的发现与复盘；盘中监测在数据授权、延迟和稳定性达标后进入第二阶段。
6. **AI Agent 是研究副驾驶，不是事实管理员**：Agent 默认只读，只能生成带引用的提案；合并题材、修改成员和发布结论需要规则校验或人工批准。

## 4. 建议立项范围

### MVP：盘后动态题材研究闭环

- 建立行业、产业链、题材三类实体及别名映射；
- 接入至少一个可回放的日频题材/成员来源；
- 建立来源文档、证据片段和成员关系版本；
- 生成日频热度、市场强度、扩散度、拥挤度和生命周期；
- 提供题材库、题材详情、成员证据、事件时间轴、变更审计；
- 支持订阅、盘后摘要和证据审核；
- AI Agent 完成“检索 → 引用 → 生成提案”，不自动发布。

### 第二阶段：盘中监测

- 竞价、盘中异动、板块/个股热榜和资金变化；
- 分级告警、去重合并和冷却窗口；
- 盘中叙事变化与盘后确认分离；
- 延迟、缺口、数据源降级和补算可观测。

### 暂不进入

- 实盘自动交易或荐股；
- 无证据的自动题材成员扩张；
- 依赖今天成员回看历史的伪回测；
- 将新闻摘要直接当作结构化事实；
- 无评测门禁的开放式多 Agent 自主写库；
- 首期建设通用图数据库或流式计算集群。

## 5. 与 QRP 现有架构的关系

遵循现有单向依赖，不新增第二套事实系统：

```text
外部来源
  → pipeline：采集、快照、去重、标准化
  → contracts：实体、时间、来源和版本契约
  → DuckDB：原始快照 + 标准事实 + 派生指标
  → indicators：热度、强度、扩散、拥挤、生命周期
  → API：查询、订阅、审核、Agent 工具
  → web：题材研究与复盘工作台
```

AI Agent 位于 API/应用编排层，只通过受控工具读取事实、创建提案和审核任务，不直接连接 DuckDB，不绕过 contracts/pipeline 写入标准事实。

## 6. 立项门槛

进入实现前应同时满足：

- 明确首期授权数据源、频率、历史起点和持久化权利；
- 确认题材历史成员可按交易日回放，或明确标记仅支持“自接入日起”的历史；
- 确认来源文档原文/片段的存储合规边界；
- 选定 20～30 个种子题材和 200～300 条人工金标准成员关系；
- 明确“监测告警”而非“投资建议”的产品文案与责任边界；
- 完成数据成本、模型成本和每日运行时长预算。

## 7. 成功判定

MVP 不是以“页面上线”验收，而是以下闭环可重复运行：

```text
盘后采集完成
→ 新事件触发候选题材或已有题材更新
→ 成员与证据形成版本
→ 指标和生命周期按同一快照重算
→ 用户打开摘要看到变化原因
→ 用户可追溯到证据并批准/驳回提案
→ 任意历史日可按当时可见信息重放
```
