# 动态产业-题材库：产品调研与机会判断

> 调研日期：2026-07-15
>
> 方法：公开产品页、官方应用商店描述、官方数据接口文档、QRP 仓库能力审计
>
> 限制：未登录付费版逐屏体验；竞品结论以公开可验证能力为准，不推断未公开实现

## 1. 调研问题

本次调研不回答“谁的概念板块最多”，而回答：

1. 个人 A 股研究者如何发现一个新题材？
2. 市场产品如何解释题材、产业链和公司之间的关系？
3. 哪些能力解决盘中效率，哪些能力形成长期研究资产？
4. QRP 已有什么底座，缺什么关键对象与工作流？
5. AI Agent 在哪里能提高效率，又不破坏可追溯性？

## 2. 对象定义

| 对象 | 稳定性 | 关系 | 时间语义 | 示例 | 产品用途 |
| --- | --- | --- | --- | --- | --- |
| 行业 | 高 | 单票在同一分类层级通常唯一 | 生效区间、历史归属 | 申万一级“电子” | 基准、归因、中性化、同业比较 |
| 产业链 | 中 | 公司可处于多个环节 | 业务关系随产能/产品变化 | 人形机器人：减速器→丝杠→整机 | 结构化研究、上下游传导 |
| 题材 | 低 | 多对多且相关度有分歧 | 催化、扩散、衰减、复燃 | “人形机器人量产预期” | 机会发现、盘面跟踪、事件复盘 |
| 事件 | 瞬时/持续 | 可影响多个题材和公司 | 发布时间、可用时间、事件窗口 | 政策、产品发布、涨价、订单 | 解释变化、触发监测 |

核心结论：**不能把题材当作另一个行业字段**。题材成员事实必须保存证据、有效期和判断状态；业务相关度与核心/跟随等市场身份通过可重算 observation 单独计算。同一公司可同时属于多个题材，同一题材会合并、分裂、沉寂和复燃。

## 3. 竞品观察

### 3.1 能力对比

| 产品 | 公开可验证的强项 | 主要用户任务 | 对 QRP 的启发 | 不应直接照搬 |
| --- | --- | --- | --- | --- |
| 同花顺 | 热门板块、热榜、涨停强度、连板天梯、智能盯盘、动态股票池 | 快速看盘与发现市场共识 | 把题材强度与市场情绪放在第一屏；支持动态订阅 | 只呈现热榜会强化追涨，缺少来源和历史口径解释 |
| 东方财富 | 概念板块行情、资金流向、成分股；App 强调热点提醒、主题投资、AI 与社区 | 行情/资金/资讯/讨论一站式 | 题材详情需要行情、资金、成员和事件统一上下文 | 不复制门户式信息堆叠；QRP 应保持研究工作台密度 |
| 财联社 | 24 小时电报、人工筛选、热门题材、异动原因、事件时间轴 | 事件发现与快速解释 | “催化 → 题材 → 标的”的解释链是关键；时间轴应是一级视图 | 不把编辑结论当作不可质疑事实，应保存来源和反证 |
| 开盘啦 | 竞价、区间统计、题材库、产业链小表格、板块强度、情绪、复盘、异动提醒 | 超短题材跟踪与每日复盘 | 题材生命周期、强度排行、核心/跟随梯队适合盘面工作流 | 专家精选口径不可直接成为量化真值；需版本和证据 |
| 萝卜投研 | 金融搜索、公告/研报/新闻/产业链聚合、知识图谱、研究框架、订阅与异动提醒 | 中长期基本面与产业研究 | 产业链应成为可持续更新的研究资产；Agent 可做跨源检索 | 首期不要建设泛化知识图谱平台，先解决题材闭环 |

### 3.2 竞品提供的共同价值

五类共同能力构成用户预期：

```text
发现：热榜 / 电报 / 异动 / 竞价
解释：题材逻辑 / 涨停原因 / 产业链
映射：板块 → 成分 → 核心标的
跟踪：价格 / 资金 / 人气 / 情绪 / 提醒
复盘：时间轴 / 区间统计 / 当日摘要
```

但公开产品普遍把“速度”和“覆盖”放在前面，较少公开展示：

- 为什么某公司属于某题材的完整证据；
- 成员是在什么时候、基于当时什么信息加入的；
- 题材名称变化、合并、分裂和成员修订历史；
- 供应商成员、AI 判断和人工判断之间的差异；
- 任意历史日能否按当时已知信息回放。

这正是 QRP 的差异化入口。

## 4. 数据供给变化

### 4.1 可快速利用的供应商数据

Tushare 公开文档在本次调研时已提供以下相关接口：

| 数据 | 接口 | 时间能力 | 可用字段/价值 | 关键约束 |
| --- | --- | --- | --- | --- |
| THS 概念分类 | `ths_index` | 当前目录 | 名称、成分数、类型 | 不能单独证明历史成员 |
| THS 概念成员 | `ths_member` | 当前快照为主 | 概念-股票关系 | 文档仍标注 `in_date/out_date` 暂无 |
| DC 概念分类 | `dc_index` | 支持交易日查询 | 概念代码、领涨股、涨跌、换手、市值等 | 属于供应商分类，需保留原始口径 |
| DC 概念成员 | `dc_member` | 按交易日历史成分 | 概念-股票日快照 | 日快照不等于真实生效事件，需本地差分 |
| DC 题材 | `dc_concept` | 2026-02-03 起日频 | 热度、强度、排名、涨停数、主力净流入、领涨股 | 历史较短；评分定义为供应商黑盒 |
| DC 题材成员 | `dc_concept_cons` | 2026-02-03 起日频 | 题材成员、行业、入选原因、热度排行 | “原因”需作为来源声明保存，不能直接视为 QRP 结论 |
| KP 题材成员 | `kpl_concept_cons` | 按交易日 | 题材、成员、描述、人气值 | 权限和供应商稳定性需实测 |
| 强势板块 | `limit_cpt_list` | 日频历史 | 涨停数、连板数、板块热点排名 | 偏涨停风格，不能代表全部产业趋势 |
| 热榜 | `ths_hot` / `dc_hot` | 日内多快照 | 排名、人气、标签、上榜解读 | 热度易受用户行为影响，需标注口径 |
| 板块行情 | `dc_daily` | 2020 年起 | OHLC、成交额、换手、涨跌幅 | 指数编制与成员口径需随源保存 |

### 4.2 数据策略结论

1. **MVP 可以日频起步**：DC/KP 题材与成员能加速建立自接入日起的可回放底座。
2. **供应商不是标准事实唯一来源**：所有供应商字段先进入 source snapshot，再映射为 QRP 候选实体和候选关系。
3. **历史起点必须逐表声明**：例如 DC 题材数据从 2026-02-03 开始，产品不可暗示更早历史完整。
4. **成员关系要做日快照差分**：生成“首次观察、最后观察、加入候选、退出候选”，但不能把首次观察伪装为真实业务生效日。
5. **来源文档是证据主线**：公告、互动问答、官网、监管文件、研报/新闻授权摘要用于解释成员关系和催化，不由价格共振反推公司业务事实。

## 5. QRP 现有能力与缺口

### 5.1 可复用能力

- 标准 contracts、pipeline、DuckDB 和数据源映射边界；
- `published_at / available_trade_date / revision` 等 PIT 语义；
- 申万历史行业归属和 `query_industry_as_of`；
- 日线、估值、市值、涨跌停、研报、机构调研等数据；
- 横截面算子、行业/市值暴露、市场阶段与风险指标；
- FastAPI 查询层和 React 复盘工作台；
- 回测快照、可复现和“不允许未来函数”的工程纪律。

### 5.2 关键缺口

| 缺口 | 当前影响 | 本方案补齐方式 |
| --- | --- | --- |
| 无独立题材实体与生命周期 | 只能看到供应商标签，不能跟踪演化 | `theme + theme_version + theme_cycle + theme_lifecycle_transition` |
| 无产业链节点/边模型 | 无法区分上游、核心部件、整机、应用 | `taxonomy_node + chain_edge + asset_chain_relation + theme_chain_link` |
| 无成员证据契约 | 无法判断“真相关/蹭概念/待验证” | `theme_membership + evidence_claim + evidence_link + review_status` |
| 无来源级变更审计 | 修订后不能解释历史差异 | 双时态版本、内容哈希、决策日志 |
| 无题材派生指标 | 热度、强度和扩散不可复算 | indicators 统一计算和版本化 |
| 无订阅与告警去重 | 监测只能靠人工扫页面 | 规则、事件、通知和冷却窗口 |
| 无受控 Agent 工具 | AI 输出难以引用、评测和审计 | 只读工具 + 提案队列 + 人工门禁 |

## 6. 目标用户与高价值任务

主用户是使用 QRP 做个人 A 股研究、愿意核验证据、需要量化复盘的主动研究者。优先任务按价值排序：

1. 盘后 10 分钟内知道今日新出现、增强、分歧和退潮的题材；
2. 打开题材即可理解催化、产业链位置、核心/跟随标的和入选证据；
3. 区分“业务相关性强”与“市场共振强”，避免把涨停等同于基本面相关；
4. 订阅少量题材，只在发生实质变化时收到告警；
5. 回到任意历史日复盘当时的成员、证据、指标和判断，而非用今天口径解释过去；
6. 让 Agent 完成跨源查找、摘要和矛盾整理，自己做最终判断。

## 7. 差异化定位

建议定位：

> **面向可验证研究的动态题材操作系统：比新闻列表更结构化，比概念榜单更可解释，比静态产业链更贴近市场变化。**

差异化不是更快的实时行情，而是四个可验证能力：

- **Evidence-first**：关系有证据，结论有反证和置信度；
- **Point-in-time**：历史可回放，不使用今天成员解释过去；
- **Dual lens**：业务相关度与市场共振度分别评分；
- **Human + Agent**：AI 提高检索和整理效率，发布权仍受控。

## 8. 风险与对策

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 标签污染 | 同名异义、蹭概念、供应商互相抄录 | 别名实体化；来源独立性；反证；人工金标准 |
| 未来信息泄漏 | 当前成员回填到历史 | 每日快照、PIT 查询、接入前历史标记不完整 |
| 评分伪精确 | 黑盒热度被误解为预测 | 展示构成、覆盖率、数据质量和版本；不输出收益概率 |
| 告警疲劳 | 同一事件多源重复推送 | 事件聚类、严重度、冷却、每日预算 |
| AI 幻觉 | 编造关系或引用不匹配 | 工具返回 source id；逐主张引用；无证据不得发布 |
| 版权/授权 | 抓取全文、二次分发受限 | 来源白名单；仅存允许字段/摘要；保留链接和授权元数据 |
| 供应商依赖 | 字段或权限变化导致断流 | source adapter、原始快照、契约测试、降级和替代源 |
