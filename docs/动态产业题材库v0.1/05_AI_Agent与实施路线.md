# 动态产业-题材库：AI Agent 与实施路线

## 1. Agent 的产品角色

Agent 是“带证据的研究副驾驶”，适合处理高文本量、跨来源、需要迭代检索的任务：

- 解释一个题材本周发生了什么变化；
- 从公告、互动、研报/新闻摘要中抽取公司-产品-产业环节主张；
- 为供应商新增成员寻找支持证据和反证；
- 识别题材别名、潜在重复、父子题材或边界漂移；
- 比较两个时间点的题材成员、逻辑与指标变化；
- 生成盘后简报和待核查清单；
- 把研究结果转为结构化提案供人审核。

Agent 不负责：

- 计算行情指标或生命周期分数；
- 直接访问数据库、文件系统或任意网络；
- 自动批准题材、成员、别名和产业链关系；
- 生成买卖指令、目标价或收益概率；
- 在缺少来源时用常识补齐事实；
- 把模型记忆当作当前数据。

## 2. 设计原则

1. **工具先于自由生成**：关键事实只能来自工具返回的结构化记录。
2. **逐主张引用**：输出中的可核查主张必须带 `document_id/excerpt_id` 或 `metric observation id`。
3. **提案而非写库**：Agent 输出 `proposal`，审核器和 contracts 决定是否形成新版本。
4. **规则结果不可被改写**：Agent 可以解释指标，不能修改分数或生命周期状态。
5. **显式未知与冲突**：无证据返回 `unknown`；相反证据并列，不强行选边。
6. **最小权限和预算**：每类任务有工具白名单、最大轮次、最大文档数和成本上限。
7. **可关闭**：Agent 故障或停用时，数据、指标、状态机、告警和人工审核继续工作。
8. **owner / workspace 隔离**：`agent_run`、未提交 `proposal`、研究笔记属于用户私有对象，必须带 `owner_id`；Agent 不得跨用户读取私有笔记或私有提案。

## 3. 架构

```text
用户 / 定时任务
  → Agent Orchestrator
      → Task policy（工具、范围、预算、输出 schema）
      → Retrieval tools（只读）
      → Analysis loop
      → Citation verifier
      → Policy / schema validator
  → Research result
      ├── 带引用摘要
      ├── 未知项 / 冲突项
      └── Proposal（可选）
  → 人工审核 / 确定性提交器
  → 新 canonical version
```

模型供应商可替换；业务契约、工具 schema、引用验证和评测集保持稳定。首期用单 Agent + 多工具，不引入多 Agent 角色网络。

## 4. 受控工具

### 4.1 读取工具

| 工具 | 作用 | 关键限制 |
| --- | --- | --- |
| `search_themes` | 查题材、别名和供应商映射 | 最多返回 20 个候选，不做自动合并 |
| `get_theme_as_of` | 获取某时点题材定义/状态 | 必须传 `as_of`，并声明 `strict_effective` 或 `observed_as_of` |
| `get_theme_members` | 获取成员、角色、双轴分数 | 返回 coverage、版本与 `effective_time_quality` |
| `get_theme_metrics` | 获取结构化指标与贡献项 | Agent 不自行重算；指标绑定 `available_trade_date` |
| `get_theme_changes` | 比较两个版本/时点或两个 `theme_cycle` | 返回标准 diff |
| `search_documents` | 按实体、时间、来源级别检索 | 来源白名单、权限过滤 |
| `get_document_excerpt` | 读取允许的证据片段 | 返回定位、授权标签和时间 |
| `get_claim_evidence` | 获取主张的支持/反对证据 | 保留独立来源分组 |
| `get_chain_context` | 获取产业节点与关系 | 限制跳数和节点数 |
| `find_similar_decisions` | 查相似人工审核历史 | 不泄露不必要用户信息 |

### 4.2 写入型工具

写入型工具只写工作区对象，并继承当前用户 `owner_id`：

| 工具 | 允许写入 | 禁止写入 |
| --- | --- | --- |
| `create_research_note` | 用户私有研究笔记 | canonical fact |
| `create_theme_proposal` | 新题材/定义/别名提案 | 正式 theme version |
| `create_membership_proposal` | 题材成员事实关系提案 | 正式 membership、相关度分数、角色观察 |
| `create_chain_node_proposal` | 产业节点提案 | 正式 chain_node |
| `create_chain_edge_proposal` | 产业边提案 | 正式 chain_edge |
| `create_asset_chain_relation_proposal` | 公司—产业环节关系提案 | 正式 asset_chain_relation |
| `create_theme_chain_link_proposal` | 题材—产业环节影响提案 | 正式 theme_chain_link |
| `request_more_evidence` | 审核任务 | 自动采集白名单外来源 |
| `create_monitor_rule_draft` | 未启用的订阅规则草案 | 自动启用通知 |

边界：

- 未提交提案 / 研究笔记 / `agent_run`：`visibility=private`，仅 `owner_id` 可见；
- 用户提交后提案进入受控共享审核队列，不再仅靠 `requester_id` 间接隔离；
- 产业库维护必须走独立提案工具，禁止把公司—产业关系塞进 `theme_membership` 提案。

每次工具调用记录 `agent_run`（含 `owner_id`）、参数摘要、结果 ID、耗时和错误。敏感/授权内容不进入模型日志的自由文本字段。

## 5. 标准任务

### 5.1 题材周报

输入：`theme_id`、时间区间、as-of、最大来源数。

流程：

```text
读取题材前后版本
→ 获取指标与状态迁移
→ 获取变化事件
→ 检索关键支持/反对证据
→ 生成驱动、扩散、分歧、风险、未知项
→ 引用验证
```

输出 schema：

```json
{
  "theme_id": "thm_xxx",
  "as_of": "2026-07-15T15:30:00+08:00",
  "summary": "...",
  "drivers": [{"claim": "...", "citations": ["doc_1#p3"]}],
  "market_changes": [{"claim": "...", "observations": ["metric_42"]}],
  "contradictions": [{"claim": "...", "citations": ["doc_9#p2"]}],
  "unknowns": ["..."],
  "suggested_actions": [{"type": "review_membership", "target_id": "..."}]
}
```

### 5.2 成员验证

输入：`theme_id + asset_id + proposed_role + as_of`。

输出：

- 支持主张和证据；
- 反对/澄清证据；
- 产业链角色；
- 业务相关度建议区间和覆盖率；
- `approve_as_watch / request_evidence / reject / conflict` 建议；
- 可提交的 membership proposal。

Agent 不给出单点伪精确分数，只建议区间；正式分数由确定性规则基于已审核 evidence claim 计算。

### 5.3 题材去重

召回信号：名称/别名相似、成员 Jaccard、共同催化、产业节点重叠。

Agent 只回答：

- 是否同义、父子、相关但不同、或无法判断；
- 两者边界差异；
- 建议 canonical name 和保留别名；
- 支撑判断的来源与版本。

合并必须由 Reviewer 执行，且生成 redirect 和版本审计。

## 6. 提示与输出约束

系统提示必须包含：

```text
- 你不是投资顾问，不输出交易指令。
- 只使用工具在给定 as_of 返回的信息。
- 每个外部可验证主张必须引用来源 ID。
- 缺少证据时写“未知”，不能用常识补齐。
- 区分供应商声明、QRP 已审核事实、规则指标和你的提案。
- 发现冲突时同时保留支持与反对证据。
- 不得声称已修改题材或成员；你只能创建提案。
```

输出由 JSON Schema 校验。自然语言只作为结构化字段的展示层，不能绕过枚举和 ID。

## 7. 引用验证

提交前执行确定性检查：

1. citation ID 存在且属于本次允许范围；
2. 引用 `available_at <= as_of` 且 `available_trade_date <= business_date`；
3. 引用片段确实包含实体/数值/关系关键词；
4. 数值和单位与来源一致；
5. 多来源是否属于同一转载独立性组；
6. 输出中的事实句是否都有引用或 observation ID；
7. 授权标签是否允许当前展示范围；
8. 不得读取其他 `owner_id` 的私有笔记、私有提案或 `agent_run`。

验证失败时，不生成 proposal；结果以草稿返回并标出失败主张。

## 8. 评测体系

### 8.1 金标准数据集

首期建立：

- 20～30 个种子题材；
- 200～300 条公司-题材关系；
- 每条含角色、支持证据、反证/无证据、as-of 和人工结论；
- 至少 30 组别名/重复/父子题材；
- 至少 20 个未来信息泄漏陷阱；
- 至少 20 个来源转载去重样本；
- 至少 20 个数字/单位/否定句抽取样本。

### 8.2 离线指标

| 能力 | 指标 | MVP 门槛建议 |
| --- | --- | --- |
| 引用完整 | 有事实主张的句子带引用比例 | 100% |
| 引用支持 | 人工判断引用确实支持主张 | ≥ 95% |
| PIT 合规 | 使用 as-of 后来源的比例 | 0% |
| 成员判断 | 宏平均 F1 | ≥ 0.85 |
| 角色抽取 | 准确率 | ≥ 0.85 |
| 冲突识别 | 召回率 | ≥ 0.90 |
| 别名合并建议 | 高风险误合并率 | ≤ 1% |
| Schema 合规 | 一次通过率 | ≥ 99% |

“建议门槛”需在真实金标准上校准，不达标时 Agent 只能生成研究笔记，不能创建结构化提案。

### 8.3 在线指标

- 提案采纳/驳回/补证比例；
- 审核者修改字段比例；
- 单条提案平均审核时间；
- 重复检索减少量；
- 引用打开率；
- 每次任务成本、P50/P95 延迟、工具失败率；
- 被撤销版本中 Agent 提案占比。

## 9. 安全与治理

- 来源内容视为不可信输入，防止文档中的提示注入改变工具策略；
- 工具参数由 schema 和服务端 ACL 校验，模型不能拼任意 SQL/URL；
- 模型只看到任务需要的最小内容，授权原文按字段脱敏/截断；
- 写入工具需要 idempotency key，重复运行不重复建提案；
- Agent run、模型、提示、工具策略和输入版本全部审计；
- 模型升级必须跑固定评测集和回放对比；
- 提案自动过期，避免旧结论长期占用审核队列；
- 用户笔记、未提交提案与 `agent_run` 按 `owner_id` 与 canonical knowledge 分区存储；
- 审核队列可见性按 Researcher / Reviewer / Maintainer / Admin 角色定义，不依赖 `requester_id` 间接隔离。

## 10. 实施路线与版本归属

本能力**不属于当前 QRP v1.0 蓝图主线**。返修后的文档继续作为 Open 预研 PR，不进入 v1.0 合并队列。

| 版本 | 范围 | 说明 |
| --- | --- | --- |
| v1.0 | 不实施 | 已封版主线不并入产业-题材库 |
| v1.1 | 数据基座 + 日频闭环 | contracts、PIT、成员/产业事实、指标、生命周期、Web 闭环 |
| v1.1 后段或 v2.0 入口 | Agent 副驾驶 | 受控工具、引用校验、提案审核；不自动写标准事实 |
| v2.0 | 盘中增强 | 竞价/分钟、provisional 状态、实时告警与产业高频 |

### Phase 0：口径与金标准（v1.1 入口）

交付：

- 对象定义、枚举、来源等级、时间契约封板；
- 行业 / 产业链 / 题材分模与 owner 边界确认；
- 20～30 个种子题材、`theme_cycle` 与人工版本；
- 200～300 条成员金标准 + 独立 `asset_chain_relation` 金标准；
- 数据授权与存储边界清单；
- 生命周期与分数回放 notebook/报告（实现时可放研究目录，不在本任务创建）。

退出条件：行业/产业链/题材边界无重大分歧；`strict_effective` / `observed_as_of` 示例通过；关键数据源可用。

### Phase 1：日频数据基座（v1.1）

建议任务包：

1. contracts：来源、题材、`theme_cycle`、成员事实、产业关系、证据、版本和时间字段；
2. pipeline：DC/KP/THS adapter、原始快照、schema 契约和幂等；
3. canonicalization：供应商映射、别名、日快照差分、产业关系提案提交器；
4. PIT query：题材/成员/产业关系/证据 as-of 服务，含 `available_trade_date`；
5. quality：水位、覆盖率、批次隔离和版本 manifest。

退出条件：至少 60 个交易日可回放，或产品明确展示真实历史起点；三类未来函数测试为 0 泄漏。

### Phase 2：指标与生命周期（v1.1）

建议任务包：

1. 题材市场面板准备；
2. 一级指标与 coverage；
3. 成员双轴相关度与角色观察（derived）；
4. 状态机、滞回、人工覆盖与 `theme_cycle`；
5. 变化事件、告警聚类和盘后摘要；
6. 60 日种子题材回放与阈值校准。

退出条件：所有分数可解释到组件；断源不制造批量退出；状态迁移人工抽检达标。

### Phase 3：Web 产品闭环（v1.1）

建议任务包：

1. 题材目录/详情 API；
2. 今日总览与题材详情；
3. 成员证据、产业关系审核入口、时间轴、历史周期切换与版本差异；
4. 订阅、告警流和运行状态；
5. 审核队列、提案差异和决策审计；
6. 响应式与可访问性、性能和空/错/缺失状态。

退出条件：PRD 四个 MVP 场景可重复演示，历史日页面与 API 输出一致。

### Phase 4：Agent 副驾驶（v1.1 后段 / v2.0 入口）

建议任务包：

1. 只读检索/指标/证据/产业上下文工具；
2. 题材周报、成员验证与产业关系验证标准任务；
3. citation verifier 与 JSON Schema；
4. 题材/成员/产业关系 proposal 写入工具和人工审核；
5. 金标准离线评测、成本/延迟/审计；
6. 模型切换和 Agent 全局关闭开关。

退出条件：PIT 泄漏为 0；引用完整率 100%；核心流程在 Agent 关闭后仍正常。

### Phase 5：盘中增强（v2.0）

在授权、频率、SLA 和日频质量稳定后再进入：

- 竞价/分钟快照；
- 盘中 provisional 状态与收盘确认；
- 实时告警预算和多级冷却；
- 商品/期货等产业高频信号；
- 盘中容量、延迟和断流演练。

## 11. 依赖与决策清单

立项会需要明确：

| 决策 | 推荐默认 | 原因 |
| --- | --- | --- |
| 首期频率 | 盘后日频 | 先保证 PIT、证据和回放正确 |
| 首期题材数 | 20～30 个种子 + 候选队列 | 可建立高质量金标准 |
| 首选供应商口径 | DC/KP 日快照，THS 作补充 | 当前公开文档提供按日成员和入选原因 |
| 自有 canonical | 必须建立 | 避免供应商锁定和口径污染 |
| 图数据库 | 暂不引入 | DuckDB 关系表足够覆盖 MVP 查询 |
| Agent 形态 | 单 Agent + 受控工具 | 更易审计、评测和限权 |
| 自动写事实 | 禁止 | 错误成本高，破坏可追溯性 |
| 实时通知 | 二期 | 数据频率、稳定性和噪声尚需验证 |

## 12. 总体验收清单

### 产品

- [ ] 今日总览能解释变化，不只是按涨幅排行；
- [ ] 题材详情同时展示产业、事件、成员、市场与证据；
- [ ] 成员业务相关度和市场共振度分离；
- [ ] 缺失、延迟、冲突和来源权限状态明确；
- [ ] 告警可解释、可去重、可确认。

### 数据

- [ ] 来源快照、canonical fact、派生指标分层；
- [ ] 题材/成员/产业关系/证据支持 as-of 和双时态；
- [ ] `asset_chain_relation` / `theme_chain_link` 独立于 `theme_membership`；
- [ ] `theme_membership` 不含相关度分数与 core/follower 角色字段；
- [ ] `theme_cycle` 支持本轮/上轮比较，生命周期不含 reactivated/archived；
- [ ] 私有对象带 `owner_id`，审核队列按角色可见；
- [ ] 供应商成员不直接成为 QRP 核心成员；
- [ ] 任何分数和状态可回到 input manifest；
- [ ] 断源/补数/修订不会静默改写历史。

### Agent

- [ ] 无任意 SQL、URL、数据库或文件权限；
- [ ] 每个外部主张逐条引用；
- [ ] 无证据明确返回未知；
- [ ] 只创建提案，不能批准；
- [ ] 具备产业节点/边/公司产业关系/题材产业影响提案工具；
- [ ] `agent_run` 与未提交提案带 `owner_id`，不可跨用户读取；
- [ ] PIT、引用、Schema 和误合并评测达门槛；
- [ ] Agent 关闭后核心产品可用。

### 工程

- [ ] 日终 SLA、覆盖、schema 漂移和分布异常可监控；
- [ ] 全链路幂等、可重跑和可回放；
- [ ] API 带 as-of、版本、coverage、freshness 和 warning；
- [ ] 测试覆盖未来泄漏、来源中断、批量退出和告警重复；
- [ ] 数据授权、日志和模型成本有预算与审计。
