# 动态产业-题材库 PRD 与产品原型

> 版本：v0.1
>
> 产品形态：QRP Web 内的研究工作台
>
> 交付顺序：桌面端优先，移动端保证查询与告警处理，不追求完整盘面操作

## 1. 产品目标

### 1.1 目标

- 将分散在行情、涨停池、新闻、公告、研报和互动问答中的题材信息组织为可持续更新的研究对象；
- 用产业链角色和证据解释“为什么相关”，用市场数据解释“当前如何交易”；
- 让用户在一个页面完成发现、验证、订阅与复盘；
- 建立可回放的数据资产，为后续题材事件研究、因子研究和策略验证提供 PIT 输入；
- 让 Agent 处理检索与整理，把人工时间留给判断和审核。

### 1.2 非目标

- 不提供目标价、收益预测、买卖评级或自动交易；
- 不承诺实时资讯首发速度超过专业通讯社；
- 不把供应商概念指数等同于 QRP 自有题材定义；
- 不在 MVP 覆盖所有上市公司和所有题材；
- 不把大模型生成文字作为无来源的产品事实。

## 2. 用户与场景

### 2.1 核心用户

**主动研究者**：每日盘后复盘，兼顾基本面和市场反馈，愿意核查公告/互动/研报，重视历史可复现。

次要用户：

- 盘中观察者：只订阅少量题材，需要低噪声异动提醒；
- 量化研究者：需要历史成员、事件、指标和版本快照用于研究；
- 数据维护者：处理实体合并、成员证据、来源异常和 Agent 提案。

### 2.2 Jobs to be done

| 场景 | 用户任务 | 成功结果 |
| --- | --- | --- |
| 盘后总览 | 找到今日发生实质变化的题材 | 10 分钟内完成新增/增强/分歧/退潮扫描 |
| 题材理解 | 搞清催化和产业链传导 | 3 次点击内看到逻辑、事件、链路和关键标的 |
| 标的验证 | 判断公司是否真的相关 | 每个结论有角色、理由、证据、反证和更新时间 |
| 动态跟踪 | 只关注重要变化 | 订阅后相同事件不重复轰炸，告警可解释 |
| 历史复盘 | 回看某日当时的认知 | 页面和 API 均可按 as-of 恢复成员与指标版本 |
| 研究辅助 | 汇总多源材料 | Agent 输出逐主张引用，未知项明确列出 |

## 3. 核心概念与产品语言

### 3.1 双轴相关度

成员不能只有“属于/不属于”。产品同时展示：

- **业务相关度**：主营/产品/客户/订单/产能对题材的真实暴露，来源于证据；
- **市场共振度**：价格、成交、涨停、资金、人气与题材同步程度，来源于市场事实。

四象限用于解释，不用于直接荐股：

| 象限 | 业务相关度 | 市场共振度 | 产品解释 |
| --- | --- | --- | --- |
| 核心兑现 | 高 | 高 | 业务证据强且市场已识别 |
| 潜在映射 | 高 | 低 | 业务相关但尚未形成明显市场共振 |
| 情绪映射 | 低/待证 | 高 | 市场交易明显，基本面证据不足 |
| 弱关联 | 低 | 低 | 默认降权，不进入核心列表 |

### 3.2 生命周期

题材在产品上使用有限状态，不用“永远热门”的静态标签：

```text
候选 → 萌芽 → 活跃 → 加速 → 分歧 → 退潮 → 沉寂
          ↑                         │       │
          └──────── 复燃 ──────────┴───────┘
```

状态由可解释指标和事件规则计算；人工可以覆盖展示状态，但覆盖必须有原因和有效期。

## 4. 信息架构

```text
动态题材
├── 今日总览
│   ├── 状态变更
│   ├── 强度 / 热度 / 扩散 / 拥挤排行
│   ├── 新催化与风险
│   └── 我的订阅
├── 题材库
│   ├── 搜索 / 筛选 / 对比
│   └── 题材详情
│       ├── 概览
│       ├── 产业链
│       ├── 成员
│       ├── 证据
│       ├── 时间轴
│       └── 版本与审计
├── 产业图谱
│   ├── 产业链模板
│   └── 公司 / 产品 / 环节关系
├── 监测中心
│   ├── 订阅规则
│   ├── 告警流
│   └── 运行状态
└── 审核队列
    ├── 新题材候选
    ├── 成员增删 / 角色变化
    ├── 合并 / 分裂 / 别名
    └── Agent 提案
```

## 5. 页面规格

### 5.1 今日总览

第一屏回答“今天哪里发生了变化”，不展示营销式欢迎区。

固定区域：

- 交易日、数据新鲜度、运行状态；
- 新增题材、状态迁移、严重告警、待审核数量；
- 题材列表，默认按“变化重要度”而非绝对涨幅排序；
- 每行展示状态、强度、热度、扩散、拥挤、涨停数、核心标的和主催化；
- 右侧事件流按催化/市场/证据/风险分色。

关键交互：

- 选择题材后主区域原位更新，保留列表滚动位置；
- `1D / 5D / 20D` 切换只改变观察窗口，不改变成员 as-of 日；
- 点击状态变化查看触发指标、阈值和前后版本；
- 一键订阅采用图标开关，告警规则在二级面板配置。

### 5.2 题材详情

页头：题材名、别名、状态、置信度、覆盖率、最近更新、订阅状态。

概览页：

- 题材定义：一句话边界、“包括什么/不包括什么”；
- 当前催化与反向风险；
- 生命周期轨迹与强度构成；
- 产业链结构；
- 核心/跟随/观察成员；
- 今日变化说明，由规则生成，可由 Agent 补充引用摘要。

成员页：

| 字段 | 说明 |
| --- | --- |
| 公司 | ticker、简称 |
| 链路角色 | 上游材料、核心部件、设备、整机、应用等 |
| 业务相关度 | 0～100，必须显示证据覆盖率 |
| 市场共振度 | 0～100，显示计算窗口 |
| 身份 | 核心 / 跟随 / 情绪 / 观察 |
| 加入来源 | 供应商、规则、人工或 Agent 提案 |
| 首次/最近观察 | 不能冒充真实业务生效日 |
| 证据状态 | 已验证 / 待验证 / 有争议 / 已失效 |

证据页：

- 按公司、来源等级、主张类型、支持/反对、状态筛选；
- 展示来源、发布时间、可用时间、原文片段、主张和判断；
- “批准/驳回”只处理提案，不修改原始来源；
- 矛盾证据并列展示，不通过覆盖旧记录解决冲突。

版本页：

- 题材定义、别名、成员、角色、状态和分数版本时间线；
- 任意两个版本可比较；
- 显示变更主体（source/rule/human/agent）、原因和关联运行批次。

### 5.3 产业图谱

MVP 不做自由拖拽的大画布，采用“链路列 + 关系表”以保证扫描效率：

```text
催化/需求
  → 上游材料
  → 核心部件
  → 设备/制造
  → 整机/平台
  → 下游应用
```

每个节点显示：公司数、已验证率、近 5 日强度变化、供需/价格事件。点击节点过滤成员表。复杂网状关系进入二期图谱视图。

### 5.4 监测中心

订阅规则由“对象 + 条件 + 严重度 + 频率 + 渠道”组成：

```text
对象：题材 / 公司 / 产业环节
条件：状态变化 / 新催化 / 成员变化 / 分数阈值 / 证据冲突 / 数据中断
严重度：信息 / 注意 / 重要 / 紧急
频率：实时(二期) / 每小时 / 收盘 / 每日摘要
渠道：站内（MVP）/ 邮件或 Webhook（二期）
```

告警详情必须包含“发生了什么、为什么触发、使用哪些数据、与上次相比变化什么、跳转到哪里验证”。

### 5.5 审核队列

- 左侧按严重度、来源等级和等待时间排序；
- 中间展示提案前后差异；
- 右侧展示支持证据、反证、相似历史决策和 Agent 推理摘要；
- 操作包括批准、驳回、要求补证、合并到已有题材；
- 批量批准仅适用于确定性规则，不适用于 Agent 自由文本提案。

## 6. 可点击原型

[打开 prototype.html](./prototype.html)

原型覆盖以下主流程：

- 搜索并切换题材；
- 切换观察窗口和详情标签页；
- 查看成员双轴相关度；
- 审核证据提案；
- 开关订阅；
- 打开 Agent 研究面板并生成带引用的模拟结果。

原型中的名称和数值仅用于交互表达，不代表真实行情或研究结论。

## 7. 关键状态

| 状态 | 页面行为 |
| --- | --- |
| 首次加载 | 骨架保持固定尺寸；数据新鲜度单独加载 |
| 空结果 | 保留筛选条件，提供清空筛选，不创建虚假推荐 |
| 部分数据缺失 | 指标显示 `--` 并展示覆盖率，剩余模块继续可用 |
| 来源延迟 | 顶部数据状态变黄，相关指标标记旧快照，不静默沿用 |
| 计算失败 | 保留上次成功值并明确时间，提供运行批次详情 |
| 权限不足 | 显示字段级不可用原因，不把 403 当作空数据 |
| 冲突证据 | 展示“有争议”，支持和反对证据并列 |
| Agent 超时 | 保留已返回引用，允许重试，不提交半成品提案 |

## 8. 搜索与筛选

统一搜索覆盖题材名、别名、公司、ticker、产业环节和催化关键词。搜索结果按实体类型分组，不混成一个平铺列表。

题材筛选：

- 生命周期；
- 行业/产业链；
- 业务证据覆盖率；
- 市场强度、扩散度、拥挤度；
- 今日是否有催化、状态变化或成员变化；
- 数据来源与完整度；
- 是否订阅。

筛选条件可编码到 URL，支持分享和恢复。

## 9. 权限与操作边界

| 角色 | 查看 | 创建提案 | 批准事实变更 | 配置来源/阈值 |
| --- | --- | --- | --- | --- |
| Viewer | 是 | 否 | 否 | 否 |
| Researcher | 是 | 是 | 自己的笔记，不含标准事实 | 个人告警 |
| Reviewer | 是 | 是 | 成员/题材提案 | 否 |
| Maintainer | 是 | 是 | 是 | 是 |
| Agent | 受控工具范围 | 是 | 否 | 否 |

即使当前 QRP 是个人产品，也建议保留角色语义，避免以后把人工操作与自动流程混在同一身份下。

## 11. 产品指标

### 11.1 北极星指标

**每周被用户验证或用于复盘的有效题材变化数**。

它比页面停留时长更贴近研究价值：变化必须被打开、查看证据、订阅、写笔记、比较版本或进入研究任务之一。

### 11.2 质量指标

- 高严重度变化的人工确认率；
- 成员关系证据覆盖率；
- PIT 历史回放一致率；
- 告警重复率与静默率；
- 题材合并/别名误判率；
- Agent 主张引用完整率、引用支持率和提案采纳率；
- 每日任务准时完成率、数据新鲜度和补算成功率。

### 11.3 防护指标

- 无证据成员进入“核心”数量必须为 0；
- 使用未来可用信息生成历史快照数量必须为 0；
- 数据源失败时静默沿用旧值数量必须为 0；
- Agent 直接写入标准事实数量必须为 0。

## 12. MVP 验收场景

### 场景 A：发现与解释

```text
盘后任务完成
→ 今日总览出现一个“萌芽→活跃”题材
→ 用户打开状态解释
→ 看到触发指标、催化事件、产业链节点和核心成员
→ 每条关键主张可跳转证据
```

### 场景 B：成员审核

```text
供应商新增成员
→ 系统生成候选关系而非直接认定
→ 规则/Agent 找到支持证据与一条反证
→ Reviewer 查看差异并批准为“观察成员”
→ 新版本从批准后的 available_at 起生效
```

### 场景 C：历史回放

```text
选择历史交易日 T
→ 页面恢复 T 当时可见的题材定义、成员、事件和指标
→ T+1 之后才发布的证据不可见
→ 与保存的 T 日快照哈希一致
```

### 场景 D：Agent 研究

```text
用户询问“本周题材增强的驱动和最大争议是什么”
→ Agent 只调用允许的检索和指标工具
→ 输出驱动、反证、未知项和逐主张引用
→ 用户将其中一条转为成员审核提案
→ Agent 不能自行批准
```
