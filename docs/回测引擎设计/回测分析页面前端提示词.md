你现在在 qrp-atlas 项目中进行一次全栈开发。

本次任务目标：

实现“回测分析页面 0.1”的前端 + 后端闭环，让用户可以在 Web 页面中查看一次回测结果。

重要边界：

1. 不新增数据库表。
2. 不修改现有数据库 contracts。
3. 不重构回测引擎核心逻辑。
4. 不做复杂策略配置器。
5. 不做参数寻优。
6. 不做多策略对比。
7. 不做任务队列。
8. 不做复杂权限系统。
9. 本次只要求“回测结果能从后端读出来，并在前端页面正常展示”。

本次页面定位：

回测分析页面 0.1 是“回测结果审计页”，不是策略开发平台。

它需要回答：

* 这次回测跑了什么？
* 核心收益风险指标是多少？
* 净值曲线和回撤曲线如何？
* 每笔交易的进出场、收益、MAE/MFE、退出原因是什么？
* 哪些信号被 skipped？
* 回测配置是什么？

后端数据来源：

本次不新增数据库表。

请优先使用以下数据来源顺序：

1. 如果当前回测引擎已经有结果输出文件，请读取现有输出文件。
2. 如果没有统一输出目录，请新增一个轻量级 backtest result 文件目录。
3. 如果当前没有真实回测结果文件，请提供 mock result 文件，保证接口和页面可运行。
4. 后端 API 结构要保持稳定，未来可以无痛切换到 DuckDB 持久化表，但本次不要建表。

建议结果文件目录：

data/backtest_runs/
sample_run_001/
run_meta.json
summary.json
equity.json
trades.json
skipped.json
config.json

如果项目已有更合适的本地数据目录，请遵循项目现有约定，不要强行新增冲突目录。

后端需要实现的 API：

GET /api/backtest/runs

返回可选择的回测 run 列表。

返回示例：

[
{
"run_id": "sample_run_001",
"name": "Sample Backtest Run",
"strategy_name": "limit_up_trend_v01",
"universe": "A_SHARE",
"start_date": "2024-01-01",
"end_date": "2024-12-31",
"created_at": "2026-07-09T15:30:00",
"status": "success"
}
]

GET /api/backtest/runs/{run_id}

返回单个 run 的元信息。

GET /api/backtest/runs/{run_id}/summary

返回总体指标。

返回示例：

{
"run_id": "sample_run_001",
"total_return_pct": 42.5,
"annual_return_pct": 12.3,
"max_drawdown_pct": -8.7,
"win_rate_pct": 46.2,
"profit_loss_ratio": 1.58,
"trade_count": 128,
"avg_holding_days": 3.4,
"max_trade_loss_pct": -9.8,
"max_trade_profit_pct": 31.2,
"skipped_count": 14
}

GET /api/backtest/runs/{run_id}/equity

返回净值和回撤曲线。

返回示例：

[
{
"date": "2024-01-02",
"equity": 1.0,
"drawdown_pct": 0.0
},
{
"date": "2024-01-03",
"equity": 1.012,
"drawdown_pct": 0.0
}
]

GET /api/backtest/runs/{run_id}/trades

返回交易明细。

返回示例：

[
{
"trade_id": "T0001",
"asset_id": "000001.SZ",
"signal_date": "2024-03-01",
"entry_date": "2024-03-01",
"entry_price": 10.12,
"exit_date": "2024-03-05",
"exit_price": 10.84,
"holding_days": 4,
"return_pct": 7.11,
"mae_pct": -2.35,
"mfe_pct": 9.44,
"exit_reason": "CLOSE_BELOW_MA5_2D",
"status": "CLOSED"
}
]

GET /api/backtest/runs/{run_id}/skipped

返回 skipped / 异常记录。

返回示例：

[
{
"asset_id": "000001.SZ",
"signal_date": "2024-03-01",
"reason": "INVALID_PRICE",
"detail": "non-finite high/low in MAE/MFE window"
}
]

GET /api/backtest/runs/{run_id}/config

返回当前 run 的配置 JSON。

后端实现要求：

1. 后端使用项目现有 FastAPI 风格。
2. API 路由文件、service 文件、schema/model 文件应遵循项目现有目录结构。
3. 不要把读取文件的逻辑直接塞进 router。
4. 建议拆分为：

   * router：负责 HTTP 接口
   * service：负责 run 查询逻辑
   * repository / loader：负责读取本地 JSON 文件
   * schemas：负责响应结构
5. 如果项目已有统一 API response 格式，请遵循现有格式。
6. 如果项目没有统一格式，直接返回 JSON 即可。
7. 日期使用 ISO 字符串。
8. 百分比字段统一使用 pct 后缀，数值单位为百分数，例如 5.25 表示 5.25%。
9. 后端需要处理：

   * run_id 不存在，返回 404
   * 文件缺失，返回合理错误
   * 空 trades / empty skipped，也应返回空数组，不要报错
10. 添加最小测试，至少覆盖：

* runs 列表可以返回
* summary 可以返回
* equity 可以返回
* trades 可以返回
* skipped 可以返回
* 不存在 run_id 返回 404

BacktestRunSelector 要求：

展示 run 列表，并允许选择某个 run。

字段：

* run_id
* name
* strategy_name
* universe
* start_date
* end_date
* created_at
* status

如果只有一个 run，则默认自动选中。

BacktestSummaryCards 要求：

展示以下指标：

* total_return_pct
* annual_return_pct
* max_drawdown_pct
* win_rate_pct
* profit_loss_ratio
* trade_count
* avg_holding_days
* max_trade_loss_pct
* max_trade_profit_pct
* skipped_count

格式化要求：

* 百分比保留 2 位小数，并显示 %
* 天数保留 1 位
* 次数显示整数
* 缺失值显示为 -

EquityCurveChart 要求：

展示 date + equity。

优先使用项目已有图表库。

如果项目没有图表库，不要擅自引入重型依赖。可以先用简单 SVG、轻量组件或表格占位，保证页面可运行。

DrawdownChart 要求：

展示 date + drawdown_pct。

drawdown_pct 通常为负值，按百分比格式展示。

TradesTable 要求：

字段：

* trade_id
* asset_id
* signal_date
* entry_date
* entry_price
* exit_date
* exit_price
* holding_days
* return_pct
* mae_pct
* mfe_pct
* exit_reason
* status

功能：

1. 支持 asset_id 搜索。
2. 支持 status 筛选。
3. 支持 exit_reason 筛选。
4. 支持按以下字段排序：

   * return_pct
   * mae_pct
   * mfe_pct
   * holding_days
   * entry_date
   * exit_date
5. 表格必须支持横向滚动。
6. 横向过宽时，滚动条必须出现在表格容器内部，不能导致整个页面横向滚动。
7. 如果实现 sticky 表头或 sticky 列，sticky 必须基于实际滚动容器生效。
8. 不要为了 sticky 效果破坏表格滚动。
9. 如果 sticky 难以一次实现正确，0.1 版可以先保证容器内横向滚动和表格可读。

RiskDistribution 要求：

0.1 版可以从 trades 数据前端计算，不需要后端新增接口。

展示三个简单分布：

1. return_pct 分布
2. mae_pct 分布
3. holding_days 分布

实现方式可以很轻量：

* 简单柱状图
* 分桶列表
* 小型表格

不要为了这个模块引入复杂依赖。

SkippedTable 要求：

字段：

* asset_id
* signal_date
* reason
* detail

功能：

* 支持按 reason 筛选
* 空数据时显示“无 skipped 记录”或类似 empty state

要求：
