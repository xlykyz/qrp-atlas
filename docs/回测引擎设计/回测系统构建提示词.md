你是 qrp-atlas 项目的后端开发 Agent。请基于当前仓库，开发 `qrp_atlas.backtest` 通用回测引擎 v0.1。

## 一、任务目标

实现一个稳定、通用、可测试、可扩展的后端回测引擎。

本次只开发后端核心能力，不做前端，不做策略发现，不做市场解释，不做 Ryan 专属交易系统规则。

核心输入：

```python
price_df + signals_df + config
```

核心输出：

```python
BacktestResult = trades + summary + skipped + equity_curve
```

v0.1 的目标是：

1. 给定标准行情数据 `price_df`
2. 给定标准信号数据 `signals_df`
3. 给定回测配置 `BacktestConfig`
4. 模拟交易过程
5. 输出交易明细、跳过记录、汇总指标

## 四、数据结构要求

### 1. PriceFrame 标准行情输入

必需字段：

```text
trade_date
asset_id
asset_name
asset_type
open
high
low
close
```

可选字段：

```text
volume
amount
turnover
market_cap
float_cap
is_st
is_limit_up
is_limit_down
```

字段含义：

```text
asset_id    统一资产代码，例如股票 ticker、指数 index_code
asset_name  资产名称
asset_type  stock / index / sector / fund / future / custom
trade_date  交易日期
open/high/low/close 行情价格
```

注意：

1. `trade_date` 应统一转成 pandas datetime 或可稳定排序的日期类型。
2. `asset_id` 必须作为字符串处理。
3. 行情必须按 `asset_id + trade_date` 排序。
4. 不要求写入数据库。

### 2. SignalFrame 标准信号输入

必需字段：

```text
signal_date
asset_id
direction
```

可选字段：

```text
asset_type
signal_name
score
weight
meta
```

字段含义：

```text
signal_date  信号触发日期
asset_id     信号对应资产
direction    long / short，v0.1 只支持 long
signal_name  信号名称，只作为标签，不影响引擎逻辑
score        信号强度
weight       建议权重
meta         外部信号模块附带的信息
```

注意：

1. v0.1 遇到非 `long` 信号，不要崩溃，应记录 skipped，reason 为 `INVALID_DIRECTION`。
2. `signal_name` 只能作为标签，不能影响引擎逻辑。
3. `score`、`weight`、`meta` 暂时不参与交易计算，只保留传递能力。

## 五、规则模型要求

请使用 dataclass 或 pydantic model。优先参考当前项目已有风格。

### 1. EntryRule

字段：

```python
timing: str
price_field: str
```

v0.1 支持：

```text
signal_close  信号日收盘买入
next_open     下一交易日开盘买入
next_close    下一交易日收盘买入
```

示例：

```python
EntryRule(
    timing="next_open",
    price_field="open",
)
```

### 2. ExitRule

字段：

```python
type: str
bars: int
price_field: str
```

v0.1 只支持：

```text
hold_n_bars
```

含义：

```text
入场后持有 N 根交易 bar，然后按指定价格字段出场。
```

示例：

```python
ExitRule(
    type="hold_n_bars",
    bars=5,
    price_field="close",
)
```

### 3. PositionRule

字段：

```python
initial_cash: float
position_pct: float
max_positions: int
allow_overlap: bool
compound: bool
```

解释：

```text
initial_cash   初始资金
position_pct   单笔交易占用资金比例
max_positions  最大同时持仓数
allow_overlap  同一资产是否允许重复开仓
compound       是否复利
```

v0.1 中，仓位规则主要用于记录和后续扩展，不要求实现完整组合资金曲线。

但请保留字段并参与 config 序列化或结果输出。

### 4. CostRule

字段：

```python
commission_rate: float
stamp_tax_rate: float
slippage_bps: float
```

计算方式：

```python
buy_cost = commission_rate + slippage_bps / 10000
sell_cost = commission_rate + stamp_tax_rate + slippage_bps / 10000
net_return = gross_return - buy_cost - sell_cost
```

### 5. BacktestConfig

示例：

```python
BacktestConfig(
    name="manual_test_hold_5d",
    entry=EntryRule(
        timing="signal_close",
        price_field="close",
    ),
    exit=ExitRule(
        type="hold_n_bars",
        bars=5,
        price_field="close",
    ),
    position=PositionRule(
        initial_cash=1_000_000,
        position_pct=1.0,
        max_positions=999999,
        allow_overlap=True,
        compound=False,
    ),
    cost=CostRule(
        commission_rate=0.00025,
        stamp_tax_rate=0.0005,
        slippage_bps=0,
    ),
)
```

## 六、回测流程要求

`BacktestEngine.run()` 流程：

```text
1. 校验 price_df
2. 校验 signals_df
3. 校验 config
4. 按 asset_id 建立行情索引
5. 遍历每条 signal
6. 找到入场 bar
7. 找到出场 bar
8. 计算单笔交易收益
9. 计算 MAE / MFE
10. 生成 Trade
11. 汇总 Metrics
12. 返回 BacktestResult
```

调用形式：

```python
engine = BacktestEngine()

result = engine.run(
    price_df=price_df,
    signals_df=signals_df,
    config=config,
)
```

## 七、Trade 输出结构

每一笔交易至少包含：

```text
asset_id
asset_name
asset_type
signal_date
signal_name
direction
entry_date
entry_price
exit_date
exit_price
holding_bars
gross_return
net_return
mae
mfe
meta
```

示例：

```python
{
    "asset_id": "000001.SZ",
    "asset_name": "平安银行",
    "asset_type": "stock",
    "signal_date": "2024-01-10",
    "signal_name": "manual_test",
    "direction": "long",
    "entry_date": "2024-01-10",
    "entry_price": 10.00,
    "exit_date": "2024-01-17",
    "exit_price": 10.50,
    "holding_bars": 5,
    "gross_return": 0.05,
    "net_return": 0.049,
    "mae": -0.03,
    "mfe": 0.08,
    "meta": {},
}
```

收益率统一用小数表示：

```text
0.05 = 5%
-0.03 = -3%
```

MAE / MFE 计算规则：

```python
mae = min(low_between_entry_and_exit / entry_price - 1)
mfe = max(high_between_entry_and_exit / entry_price - 1)
```

其中区间建议包含 entry bar 到 exit bar。请在代码注释和测试中明确这个约定。

## 八、Skipped 输出结构

当某条信号无法完成交易时，不中断整个回测，而是记录 skipped。

常见 reason：

```text
NO_PRICE_DATA
SIGNAL_DATE_NOT_FOUND
NO_NEXT_BAR_FOR_ENTRY
NO_EXIT_BAR
INVALID_DIRECTION
INVALID_PRICE
```

示例：

```python
{
    "asset_id": "000001.SZ",
    "signal_date": "2024-01-10",
    "reason": "NO_EXIT_BAR",
    "detail": "not enough future bars for hold_n_bars=20",
}
```

要求：

1. 单条信号失败不能导致整次回测失败。
2. skipped 需要尽量保留 `asset_id`、`signal_date`、`reason`、`detail`。
3. 空信号、空行情时不能崩溃。

## 九、Summary 指标

v0.1 输出：

```text
trade_count
skipped_count
win_count
loss_count
win_rate
avg_return
median_return
max_return
min_return
avg_win
avg_loss
profit_loss_ratio
avg_holding_bars
avg_mae
avg_mfe
worst_mae
best_mfe
```

说明：

1. 默认基于 `net_return` 计算 summary。
2. `win_count`：`net_return > 0`
3. `loss_count`：`net_return <= 0`
4. `win_rate = win_count / trade_count`
5. `profit_loss_ratio = avg_win / abs(avg_loss)`，当无法计算时返回 `None`。
6. 空交易时不报错，返回合理空值。

空交易示例：

```python
{
    "trade_count": 0,
    "skipped_count": 0,
    "win_rate": None,
    "avg_return": None,
}
```
