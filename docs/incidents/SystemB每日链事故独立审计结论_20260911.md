## 1. 总体结论

主事故链成立，当前 RCA 不需要推倒重来：

```text
同一 scheduled_at 的 market-daily-close / adj-factor-close
→ scheduler 依赖门禁未绑定“本次 occurrence / 本目标交易日”
→ adj-factor-close 可在当日 market 产出前抢跑
→ MARKET_DAILY_INPUT_STALE
→ system-b-readiness-daily BLOCKED
→ system-b-state-daily BLOCKED
→ state 历史整日缺口
→ episode 对过滤后的相邻行做差分，跨缺口形成假 transition
→ segment invariant 暴露 active sprint / reentry 不一致
→ segment 与 episode 共用事务和 fail-closed 总闸，导致 System B 旧业务被一并回滚
```

其中 scheduler 根因可进一步精确定义为：

> 当前 dependency gate 是 **latest-run dependency**，而该链实际需要的是 **same-occurrence / same-target-date dependency**。

源码中 `scheduler._eligibility()` 读取 `latest_run_before(dependency_id, scheduled_at)`；对应 store 查询允许 `scheduled_at <= 当前 scheduled_at`。当同一分钟到期的上游本次 run 尚未建立时，下游可能读取到上一轮 SUCCESS，从而被提前放行。

## 2. 已确认的代码层结论

### 2.1 Episode 存在缺口压缩语义

Episode rebuild 先过滤：

- `trend_state IS NULL`
- MA5/MA10 不完整行

随后 `calculate_system_b_episodes()` 将“上一条保留下来的记录”直接作为 `previous_state`，并据此生成 `state_transition`。

因此当中间 state 行缺失或被过滤时，下游会把不连续观测错误视为连续观测。该缺陷与 2026-08 的假 `BASE->ACTIVE` 现象一致。

### 2.2 Segment 扩大了 Episode 的失败域

现行实现中：

- Episode / Observation rebuild；
- Segment derive；
- Episode + Segment audit；

位于同一数据库事务内，且 segment invariant 被并入原有统一 `violations` 判定。

因此新增下游 Segment 可以否决原有 Episode / Observation 提交。该设计与“append-only downstream derivation / 不改变既有 Episode 业务结果”的设计边界不一致。

## 4. 早期历史数据边界

经人工跨源核验，2014 年及更早历史市场事实存在不可可靠消解的缺失和跨源不一致，包括交易日快照、停复牌区间等。问题不必继续归因到某一个数据供应商或历史制度环节。

本次审计采用以下工程边界：

> **2014 年及更早数据视为已知历史不可靠区间，不继续深挖具体源头；当前事故修复优先处理 2026 年生产链。**

是否对 Segment / Episode 设置历史有效起点、如何表达早期数据质量边界，留待后续独立决策。
