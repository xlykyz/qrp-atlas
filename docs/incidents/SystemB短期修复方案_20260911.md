# System B 短期修复方案（2026-09-11）

> 状态：短期恢复方案  
> 适用分支：`fix/v1.1-system-b-state-gap`  
> 目标：优先恢复 System B 当前生产链，最小化改动范围，不在本次修复中扩展到历史治理与调度系统重构。

---

## 1. 修复目标

本次短期修复仅解决两个直接问题：

1. **Segment 新能力不得继续阻断既有 System B Episode / Pool 业务链。**
2. **补跑 2026-09-10 因 Episode 失败而缺失的 System B 下游产出。**

本次不要求一次性解决全部历史问题，也不追求完整治理闭环。

---

## 2. 当前事故背景

2026-09-10 的 `system-b-episode-daily` 在首次加载 Segment 新逻辑后触发：

```text
INVARIANT_VIOLATION
active_sprint_count_mismatch = 929
```

Segment 派生与 Episode / Observation 重建位于同一事务，并共用统一 fail-closed 判定，因此 Segment invariant 失败导致整个事务回滚。

直接结果：

```text
system-b-episode-daily FAILED
        ↓
system-b-pool-height-daily BLOCKED
        ↓
system-b-pool-capacity-daily BLOCKED
        ↓
system-b-pool-recognition-daily BLOCKED
```

Segment 当前仍属于尚未正式上线的新能力，不应在此阶段拥有阻断既有 System B 业务链的能力。

---

## 3. 短期修复方案

### 3.1 拆分 Episode 与 Segment 的失败域

原结构：

```text
BEGIN
  rebuild episode
  rebuild episode_observation
  derive segment
  audit episode + segment
  任一 invariant 失败
ROLLBACK ALL
```

短期修复后：

```text
Transaction A
BEGIN
  rebuild episode
  rebuild episode_observation
  audit existing Episode / Observation invariants
COMMIT
```

Episode / Observation 成功后即形成独立有效提交。

Segment 改为独立下游阶段：

```text
Transaction B
BEGIN
  derive segment
  audit segment
COMMIT / ROLLBACK
```

其失败不得回滚已提交的 Episode / Observation。

### 3.2 当前生产路径暂不执行 Segment

由于 Segment 新能力暂未正式上线，当前 production Episode 路径默认：

```text
include_segments = False
```

即：

```text
system-b-episode-daily
    ↓
Episode + Observation 正常重建并提交
    ↓
Segment = SKIPPED
    ↓
后续 System B Pool 链继续运行
```

Segment 保留为可显式启用的独立下游阶段，后续完成历史数据与语义问题处理后再决定正式上线方式。

### 3.3 清理旧 Segment 版本数据

Episode 重建前仍清理当前 `segment_version` 的已有 Segment 数据，避免：

```text
新 Episode / Observation
+
旧 Segment
```

形成版本不一致的混合状态。

当前生产默认不重新生成 Segment，因此结果应为：

```text
Episode / Observation：有效
Segment：无当前版本产出 / SKIPPED
```

---

## 4. 2026-09-10 数据补跑

当前调查显示 2026-09-10 的上游 State 已正常产出，因此短期恢复从 Episode 开始，不重复执行 readiness / state。

补跑顺序：

```text
system-b-episode-daily
        ↓ success
system-b-pool-height-daily
        ↓ success
system-b-pool-capacity-daily
        ↓ success
system-b-pool-recognition-daily
```

建议逐项执行，上一项成功后再执行下一项；任何一步失败即停止继续向下游补跑。

参考命令：

```bash
qrp-atlas-jobs run system-b-episode-daily \
  --trade-date 2026-09-10 \
  --production-jobs "$QRP_HOME/pipeline/production-job-definitions.json"

qrp-atlas-jobs run system-b-pool-height-daily \
  --trade-date 2026-09-10 \
  --production-jobs "$QRP_HOME/pipeline/production-job-definitions.json"

qrp-atlas-jobs run system-b-pool-capacity-daily \
  --trade-date 2026-09-10 \
  --production-jobs "$QRP_HOME/pipeline/production-job-definitions.json"

qrp-atlas-jobs run system-b-pool-recognition-daily \
  --trade-date 2026-09-10 \
  --production-jobs "$QRP_HOME/pipeline/production-job-definitions.json"
```

执行补跑前必须确保生产 runtime 已加载本次修复代码；仅更新 worktree 而未重启 jobs 服务，不代表新逻辑已经生效。

---

## 5. 最小验收标准

本次短期修复只要求满足：

1. `system-b-episode-daily` 对 2026-09-10 补跑成功；
2. Episode / Observation 正常提交；
3. Segment 未执行或失败时，不影响 Episode job 成功；
4. `system-b-pool-height-daily` 补跑成功；
5. `system-b-pool-capacity-daily` 补跑成功；
6. `system-b-pool-recognition-daily` 补跑成功；
7. 不修改基础状态机、Episode 业务规则与 `ma5_reentry_count` 定义。

## 6. 明确延期事项

以下问题已经识别，但不纳入本次短期恢复：

- 2026-08 历史 state 缺口回填；
- scheduler same-occurrence / same-target-date dependency 根治；
- 958 次假迁移与 929 个 mismatch episode 的精确对账；
- Episode 对 state gap / NULL gap 的连续性感知改造；
- 2014 年及更早历史数据质量问题；
- 原事故 RCA 文档修订；
- governance 分支相关治理工作；
- Segment 新能力正式上线及独立 job 设计。

这些事项应在生产链恢复后分批处理，不阻塞当前 System B 恢复。

---

## 7. 短期原则

> **先恢复既有 System B，再治理历史欠账。**

本次修复不改变已有业务语义，只恢复原有 Episode / Observation / Pool 链的独立成功条件，并将尚未上线的 Segment 从旧业务失败域中隔离。
