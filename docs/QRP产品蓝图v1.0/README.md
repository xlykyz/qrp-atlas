## 一、本成果包的作用

`docs/核心架构v1.0/` 已经回答了：

> QRP 的能力应该放在哪里，模块之间如何依赖。

本成果包继续回答：

> QRP v1.0 应具备哪些现代量化研究能力，当前完成到哪里，后续按什么顺序开发，达到什么标准才算可交付。

它把以下三类依据统一为一套可执行产品蓝图：

1. `docs/核心架构v1.0/QRP_v1.0_核心架构文档.md`：架构边界锚点；
2. 《现代量化交易的经典策略分类研究》：现代量化能力广度锚点；
3. qrp-atlas 当前真实代码与测试：现状与可实施性锚点。

用户已确认：**本地 DuckDB 的表和字段与 `contracts` 严格一致**。因此本成果包直接以 `contracts` 作为本地数据库现状的可信清单，不再额外保留“本地库待核实”状态。

## 四、v1.0 的总体终点

QRP v1.0 不是“内置几个策略”即可完成，而是需要形成以下闭环：

```text
标准且具有时间可用性的数据
→ 可注册、可参数化、可复用的指标
→ 内置策略与声明式策略
→ 单标的与横截面组合回测
→ A 股现实成交约束与成本
→ 资金曲线、回撤、换手与稳健性分析
→ 策略 API、回测任务与前端配置
→ 结果可复现、可比较、可审计
```

## 五、v1.0 的策略覆盖原则

v1.0 不追求把所有学术策略都实现一遍，而是以代表性能力覆盖为标准：

- 价格行为：趋势、动量、突破、均值回归；
- 横截面：横截面动量、多因子 long-only；
- 信息驱动：至少一条标准事件驱动链路；
- 相对价值：至少具备残差/价差研究能力，完整多腿执行可作为增强项；
- 学习型策略：具备无未来函数的样本切分和接入边界，不要求 v1.0 内置复杂模型；
- 强化学习、高频订单簿和延迟套利：明确延后。

## 六、使用规则

1. 后续开发任务应从能力矩阵和任务包中领取，不再凭感觉增加功能；
2. 任何新增能力必须遵守已封版架构；
3. 新增基础字段和表先进入 `contracts`；
4. 任何二次计算值进入 `indicators`；
5. 交易算法进入 `strategies`；
6. 数据准备、组合、撮合、成本与验证继续扩充在 `backtest`；
7. 不因研究报告覆盖面广而引入新的顶级模块；
8. 每完成一个阶段，应同步更新能力矩阵状态和验收清单。
