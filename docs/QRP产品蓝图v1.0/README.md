## 一、本成果包的作用

`docs/核心架构v1.0/` 已经回答了：

> QRP 的能力应该放在哪里，模块之间如何依赖。

本成果包继续回答：

> QRP v1.0 应具备哪些现代量化研究能力，当前完成到哪里，后续按什么顺序开发，达到什么标准才算可交付。

它把以下三类依据统一为一套可执行产品蓝图：

1. `docs/核心架构v1.0/QRP_v1.0_核心架构文档.md`：架构边界锚点；
2. 《现代量化交易的经典策略分类研究》：现代量化能力广度锚点；
3. qrp-atlas 当前真实代码与测试：现状与可实施性锚点。

用户已确认：**本地 DuckDB 的表和字段与 `contracts` 严格一致**。因此本成果包直接以 `contracts` 作为本地数据库现状的可信清单，不再额外保留“本地库待核实”状态。

## 五、v1.0 的总体终点

QRP v1.0 不是“内置几个策略”即可完成，而是需要形成以下闭环：

```text
标准且具有时间可用性的数据
→ 可注册、可参数化、可复用的指标
→ 内置策略与声明式策略
→ 单标的、横截面与事件组合回测
→ A 股现实成交约束与成本
→ 资金曲线、回撤、换手与代表性稳健性分析
→ 策略 API、回测任务与前端配置
→ 结果可复现、可比较、可审计
```

## 六、v1.0 的策略覆盖原则

v1.0 不追求把所有学术策略都实现一遍，而是以代表性能力覆盖为标准：

- 价格行为：趋势、动量、突破、均值回归；
- 横截面：横截面动量、多因子 long-only；
- 信息驱动：`earnings_forecast_event` + `event_drift_basic` 为 v1.0 第一类标准事件链路；
- 相对价值：市场/行业残差研究与代表策略；完整多腿执行是增强项；
- 稳健性：代表性残差策略具备完整稳健性验证；全策略通用优化框架延后 v1.1；
- 学习型策略：边界保留，复杂内置模型不作为发布阻塞。

5. 每完成任务同步更新矩阵与验收勾选。

## 八、本校准明确修正

1. 不以泛化 `corporate_event` 表作为当前唯一验收对象；v1.0 第一类标准事件是已实现的 `earnings_forecast_event + EventFrame`。
2. “旧策略均可使用通用稳健性框架”调整为：v1.0 要求代表性残差策略具备完整稳健性验证；全策略通用优化框架延后到 v1.1。
3. short、多腿、借券、协整、机器学习、分布式回测和实盘 **不是** v1.0 发布阻塞。
4. 已完成但仍未勾选的项目按真实代码更新为已完成。
5. 未完成项明确归入 07-B2 / 07-C / 07-D / 08。
