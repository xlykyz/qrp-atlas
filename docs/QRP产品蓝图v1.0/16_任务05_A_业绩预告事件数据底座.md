# 任务 05-A：业绩预告事件数据底座

状态：**实现完成，等待 PR 验收**
分支：`feature/earnings-forecast-event-foundation`
范围：通用事件时间 / PIT 语义 + 第一种标准结构化事件 `earnings_forecast` 的获取、清洗、入库、版本保存与 as_of 查询。

本任务不是把“事件”定义为“业绩预告”。
QRP 事件能力是可扩展通用体系；本 PR 仅落地：

```text
event_type = earnings_forecast
```

## 1. 事件能力总体定位

未来可扩展事件类型包括但不限于：

- 业绩预告
- 业绩快报
- 分红送转
- 股份回购
- 股东增减持
- 限售股解禁
- 重大合同
- 资产重组
- 监管处罚
- 高管变动
- 股权激励

本 PR 明确**未实现**除 `earnings_forecast` 外的其他事件类型。
也未建立通用 `corporate_event` 物理万能表。

## 2. 本任务交付边界

### 实现

1. 通用事件时间与 point-in-time 语义（通过字段与查询输出体现）
2. Tushare `forecast_vip` / `forecast` 双通道访问同一数据集
3. raw / cleaned Parquet 归档（复用任务 03 的 parquet 原子写与 corrupt quarantine）
4. DuckDB 业务表 `earnings_forecast_event`
5. append-only / revision-aware 入库
6. `query_earnings_forecast_as_of` 公开查询
7. 稳定 EventFrame 投影，供 05-B 直接消费

### 不做

- 其他事件类型
- 通用 corporate_event 物理主表
- 事件指标 / surprise / event age / event window
- 事件策略、forward return、研究回测闭环
- API / 前端
- 全市场全部年份真实回补
- 新顶级模块或架构级重构

## 3. 数据源固定

| 项目 | 值 |
|---|---|
| 提供方 | Tushare Pro |
| 数据集 | 业绩预告 |
| 业务来源 | `tushare.earnings_forecast` |
| 历史批量入口 | `forecast_vip(period=YYYYMMDD)`，约 5000 积分 |
| 调试 / 定向补漏 | `forecast(ts_code=...)`，约 2000 积分 |
| 公告日增量候选 | `forecast(ann_date=YYYYMMDD)` |

`forecast` 与 `forecast_vip` 是同一数据集的不同 endpoint：

- 共用同一 mapping / contract / 业务表
- endpoint 只进入 fetch diagnostics / raw 元信息 / 运行结果
- **不进入** `source_record_id` / `revision_id` / 业务去重

权限不足、接口不存在或字段不一致时：

1. 保留真实错误
2. 停止对应真实验收
3. 不切换 AkShare / 巨潮 / 东方财富 / 爬虫

| Tushare | QRP |
|---|---|

| ann_date | announcement_date |
| first_ann_date | first_announcement_date |

### 4.3 数据单位

| 字段 | 单位 |
|---|---|
| net_profit_min / net_profit_max | 万元（Tushare 文档） |
| profit_change_min / profit_change_max | 百分比数值（例如 10.5 = 10.5%） |
| last_parent_net | 样本数量级与 net_profit 一致，倾向万元；库内原样保存，不换算 |

`last_parent_net` 代码常量仍标记为 `unconfirmed_raw`（未做单位换算逻辑）。
样本核验支持与 `net_profit_*` 同口径（万元），但 05-B **不得**仅依赖该字段直接计算 surprise。

## 5. 表结构：`earnings_forecast_event`

仅新增这一张 DuckDB 业务表。
原始响应与 cleaned 中间结果使用 Parquet，不建 raw/staging 业务表。

### 字段

| 分组 | 字段 | 说明 |
|---|---|---|
| 身份 | ticker | 证券代码 |
| 身份 | event_type | 固定 `earnings_forecast` |
| 身份 | event_series_id | 同票同报告期事件系列 |
| 身份 | report_period | 报告期 |
| 时间 | announcement_date | 公告日 |
| 时间 | first_announcement_date | 首次公告日，可空 |
| 时间 | published_at | 固定 NULL（无可靠时刻） |
| 时间 | time_precision | 固定 `date` |
| 时间 | available_trade_date | 公告日后严格第一个开市日 |
| 内容 | forecast_type | 预告类型 |
| 内容 | profit_change_min/max | 净利润变动幅度区间 |
| 内容 | net_profit_min/max | 净利润区间（万元） |
| 内容 | last_parent_net | 上年同期净利润（原样） |
| 内容 | summary / change_reason | 文本 |
| PIT | source | `tushare.earnings_forecast` |
| PIT | source_record_id | 正式披露身份 |
| PIT | revision_id | 内容版本，物理主键 |
| PIT | ingested_at | 入库时间 |

物理主键：

```text
PRIMARY KEY (revision_id)
```

复用：

- `trading_calendar`：计算 `available_trade_date`
- `stock_info`：标的合法性 / 历史清单（调用侧使用，不冗余复制名称等字段）

## 6. 通用事件语义

所有未来结构化事件应能映射到：

```text
asset_id / ticker
event_type
event_series_id
event_date / announcement_date
available_trade_date

```

## 7. 身份与版本规则

### 7.1 event_series_id

同一股票、同一事件类型、同一报告期：

```text
sha1(ticker + event_type + report_period)[:20]
```

`first_announcement_date` 不参与系列身份。

### 7.2 source_record_id

标识一次正式公告披露：

```text
sha1(
  source
  + ticker
  + event_type
  + report_period
  + announcement_date
)[:20]
```

**不包含** forecast_type / 数值 / summary / change_reason。
因此同源内容修正不会被误判为全新公告。

若真实数据出现同 ticker + report_period + announcement_date 的多条独立记录：

- 不得静默 keep first / keep last 到单一业务行并丢内容
- 相同规范化内容：按 revision 去重
- 不同内容：作为不同 revision 保留；若未来需要额外稳定键，再在验收中升级

### 7.3 revision_id

基于规范化业务内容确定性哈希，至少覆盖：

```text
source_record_id
forecast_type
profit_change_min / max
net_profit_min / max
last_parent_net
first_announcement_date
summary
change_reason
```

语义：

| 情况 | 结果 |
|---|---|
| 不同 announcement_date | 不同 source_record_id |
| 相同 source_record_id 且内容变化 | 不同 revision_id，追加保留 |
| 内容完全相同 | 相同 revision_id，重复加载 0 行新增 |

## 8. 时间可用性规则（SSOT）

Tushare 业绩预告只有公告日期，没有可靠时刻：

```text
announcement_date = ann_date
published_at = NULL
time_precision = date
available_trade_date = announcement_date 之后严格第一个 is_open=true 交易日
```

含义：

- 公告日当天不可用于策略
- 不区分盘前 / 盘中 / 盘后
- 周末 / 节假日公告映射到下一交易日
- 最早只能影响下一个合法交易日

禁止：

- 猜测公告时刻
- 默认 00:00 可交易
- 因 ann_date 为交易日就设 `available_trade_date = ann_date`
- 用回测结果倒推可用时间

## 10. Pipeline 入口

模块：

```text
src/qrp_atlas/pipeline/earnings_forecast/
  fetch.py
  clean.py
  load_duckdb.py
  run.py
```

CLI：

```bash
python -m qrp_atlas.pipeline.earnings_forecast.run \
  --mode period --periods 20231231 --tickers 000001.SZ

python -m qrp_atlas.pipeline.earnings_forecast.run \
  --mode ticker --tickers 000001.SZ --start-date 20200101 --end-date 20261231

python -m qrp_atlas.pipeline.earnings_forecast.run \
  --mode ann_date --ann-dates 20240131

python -m qrp_atlas.pipeline.earnings_forecast.run \
  --from-raw data/raw/earnings_forecast/.../batch.parquet --db-path data/db/quant.db
```

### 10.1 强制审计留痕

真实 fetch **不得**默认直接进库。每次运行自动生成：

- `batch_id`
- raw parquet（默认路径，无需手动传 `--raw-path`）
- cleaned parquet
- manifest（jsonl）：endpoint、请求参数、fetch/clean/load 状态、fetched/cleaned/invalid/inserted、路径、错误

默认路径：

```text
data/raw/earnings_forecast/<run_tag>/
data/canonical/earnings_forecast/<run_tag>/
data/state/earnings_forecast/<run_tag>/manifest.jsonl
```

复用任务 03 的 parquet 原子写 / corrupt quarantine / ManifestStore，不另建大型回补框架。
`--from-raw` 离线恢复继续保留。

### 10.2 数据质量失败规则

非空 API 响应必须包含核心列：

```text
ts_code, ann_date, end_date, type
```

缺少核心列：直接失败。
核心字段值为空：抛 `EarningsForecastDataQualityError`，不得静默 drop；manifest 记录 invalid / failed。
仅可选数值/文本字段可自动补 `None`。

链路：

```text
forecast_vip / forecast
→ raw parquet + manifest
→ clean / mapping / IDs / available_trade_date
→ append-only DuckDB load by revision_id
→ as_of query
```

## 12. as_of 查询语义

公开接口：

```python
from qrp_atlas.backtest import (
    query_earnings_forecast_as_of,
    to_earnings_forecast_event_frame,
)
```

### 12.1 市场可用时间（正式披露）

```text
available_trade_date <= as_of_date
```

该条件只控制**正式公告**是否已可用于交易/研究输入。
`available_trade_date` 由 `announcement_date` 映射得到，**不是**技术修订的 knowledge-time。

### 12.2 披露与 revision 选择

| 模式 | 行为 |
|---|---|
| 默认 | 每个 `event_series_id` 返回截至 as_of 已可用的**最新正式披露**，并取该披露当前 canonical revision |
| `include_all_disclosures=True` | 返回所有已可用正式披露；每个 `source_record_id` 只保留 canonical revision |
| `include_all_revisions=True` | 返回所有已可用正式披露的**全部技术 revisions**（审计接口） |
| `as_event_frame=True` | 投影为 05-B 稳定事件输出 |

### 12.3 技术 revision 边界（重要）

源接口不提供可靠的 revision 发布时间。

因此：

- **不**实现 `ingested_at <= as_of_date` 过滤（否则历史回补数据会全部不可见）；
- **不**声称“未来技术 revision 不污染历史查询”；
- 默认返回当前库内 canonical revision；
- 历史版本保留用于审计（`include_all_revisions=True`），不作为 knowledge-as-of 研究时点语义。

硬约束：

```text
available_trade_date > as_of 的正式披露绝不返回
```

## 14. 真实数据验证与权限缺口

本地受控真实验证（执行时 Tushare 代理可用）：

| 项 | 结果 |
|---|---|
| `forecast(ts_code=000001.SZ)` | 返回 0 行（该票样本期无预告，不代表接口失败） |
| `forecast(ts_code=688298.SH)` | 成功，7 行，含多次报告期与同报告期多次 ann_date |
| `forecast_vip(period=20231231)` | 成功，5837 行；字段完整，另含 `update_flag` |
| `forecast(ann_date=20240131)` | 成功，2210 行；**可作为日常增量候选** |
| endpoint 一致性 | 同票 `688298.SH` + `20231231`：forecast 与 forecast_vip cleaned 后 `source_record_id`/`revision_id` 完全一致 |
| 多次正式披露 | `688298.SH` 对 `20231231` 有 3 个 ann_date：20230428 / 20231031 / 20240131；同一 `event_series_id`，不同 `source_record_id` |
| 同日 update_flag 双行 | vip 中大量同日 `update_flag=0/1`；内容相同时 clean 后同一 revision，不重复入库 |
| 时间边界 | 样本 `300190.SZ` ann=`2024-01-31` → available=`2024-02-01`；as_of 公告日不可见，available 日可见 |
| 重复 load | 子集 5 行：inserted=5，再 load inserted=0 |
| 权限 | 本次 forecast / forecast_vip / ann_date 均未出现权限错误 |
| last_parent_net 单位 | 与 net_profit_min 数量级一致（样本比值中位约 0.93），倾向同为万元；代码不换算，原样入库 |

权限与数据缺口：

- 本环境积分足够完成受控验证；未跑全市场全历史回补。
- `update_flag` 存在于原始响应，但**不**进入 `source_record_id`；内容变化走 `revision_id`。
- 日常增量：`forecast(ann_date=YYYYMMDD)` 本次验证可稳定返回全日数据，实现为 `mode=ann_date`。
