## 3. Eligibility 契约

输入列：

| 字段 | 含义 |
|---|---|
| `trade_date` | 信号日可用的资格判断日期 |
| `asset_id` | 资产标识 |
| `eligible` | 是否允许进入 Top N |
| `reason_code` | 可选审计原因 |

语义：

- eligibility 使用 **signal date 当时已可用** 的数据；
- 未提供 eligibility panel 时，股票池资产默认可参与，但仍需通过有限 score 校验；
- 提供 panel 后，缺失的 `(date, asset)` **默认不合格**（`MISSING_ELIGIBILITY`）；
- `eligible=False` 不得进入 Top N；
- 无效 / 缺失 / 非有限 score 不得进入 Top N（`INVALID_SCORE`）；
- 过滤只做标注，不删除原始研究行；
- 调用方可预先准备 ST / 停牌 / 上市天数 / 流动性 / 价格 / 市值 / 自定义禁入标记，但本任务不负责从数据库抓取或用当前状态反推历史。

## 4. 调仓日历与 T / T+1 语义

`build_rebalance_schedule(trading_days, frequency=...)` 支持：

```text
daily
weekly
monthly
explicit
```

规则：

- 只基于调用方提供的真实交易日序列；
- **不**假定自然日、周末或节假日；
- 周度 / 月度默认取该周期 **最后一个实际交易日** 作为 `signal_date`；
- 因子使用 `signal_date` 收盘后可见信息；
- 目标组合在下一实际交易日执行：

```text
signal_date = T
execution trade_date = next trading day after T
```

- 禁止使用 T 日收盘因子在 T 日成交；
- 最后一个 signal 若没有下一交易日，不生成执行任务；
- 输入日期规范化、去重并稳定排序；
- explicit 日期不在交易日历时 **显式失败**，不得静默漂移；
- 不得读取未来因子来决定历史调仓。

输出列：

```text
signal_date
trade_date
```

## 5. Top N 与并列规则

`select_top_n(...)` 按交易日独立选择。

规则：

- 默认 score 越大越优，支持 `ascending=True`；
- 非有限 score 排除；
- 先应用 eligibility；
- 合格数不足 N 时选择全部合格资产；
- 默认 tie-break：

```text
score
→ asset_id 字典序
```

- 不依赖输入行顺序；
- `(signal_date, asset_id)` 唯一；
- 输出稳定排序；
- 空截面返回稳定空结构。

输出至少包括：

```text
trade_date
asset_id
score
rank
selected
eligible
reason_code
```

## 6. 等权目标权重与现金缓冲

参数：

```text
top_n
max_positions
max_weight_per_asset
cash_buffer
```

语义：

```text
target_gross = 1 - cash_buffer
raw_weight = target_gross / selected_count
target_weight = min(raw_weight, max_weight_per_asset)
```

若单票上限导致权重和低于 `target_gross`：

- 剩余保留为现金；
- **不得**突破单票上限重新放大；
- 权重总和 ≤ 1；
- 正权重数量 ≤ `max_positions`。

快照列：

```text
trade_date
asset_id
target_weight
priority
```

完整快照需表达：

- 新入选；
- 继续持有；
- 被剔除资产目标归零；
- 空选股可清仓；
- 同一执行日只有一个完整目标状态。

`priority` 使用确定性 score / rank，供组合引擎资金不足时的买入优先级。

现有 adapter：

```python
strategy_decisions_to_target_weights(..., cash_buffer=0.0)
```

已扩展 `cash_buffer`，并保持与策略侧 equal-weight 语义一致：不超过 1 时不重放大。

## 7. 决策状态转换

两项策略区分：

```text
signal_date：观察因子并形成决策
trade_date：组合引擎执行目标快照
```

`StrategyDecision.trade_date` 使用执行日；`evidence.signal_date` 保留信号日。

每次调仓：

| 情况 | 动作 |
|---|---|
| 新入选 | `ENTER` |
| 上期与本期均入选 | `HOLD` |
| 上期入选、本期未入选 | `EXIT` |
| 从未持有且未入选 | 不生成决策 |

每条决策 evidence 至少记录：

```text
signal_date
execution_trade_date
score_column
score
rank
top_n
rebalance_frequency
eligible / eligibility_reason
```

## 8. 策略定义

### 8.1 `cross_sectional_momentum_long_only`

- 输入：已准备好的横截面动量分数 Frame；
- 默认 score 列：`momentum`，也可指定 `momentum_neutral` / `momentum_zscore` 等；
- 不在策略内重算行情、财务或行业因子；
- 在 signal date 读截面 → eligibility → Top N → 下一交易日 long-only 等权决策。

### 8.2 `multifactor_long_only`

- 输入：多个已准备好的横截面分数；
- 参数通过 JSON 字符串配置：

```text
factor_columns_json
factor_weights_json
```

- 默认确定性线性复合：

```text
composite_score =
sum(factor_score_i × factor_weight_i)
/
sum(abs(factor_weight_i))
```

- complete-case：任一必需因子缺失 / 非有限，该资产不进入当期排序；
- 不隐式填零、不隐式反转方向；
- 因子方向须由调用方在进入策略前统一为“越大越优”；
- 无机器学习、优化器或协方差矩阵。

## 13. 返修说明（PR #14）

边界语义返修：

- 调仓 schedule 在所有频率（含 explicit）下对 `signal_date` 规范化、去重后 **严格升序**；并校验 `trade_date` 唯一、严格升序且 `trade_date > signal_date`。
- `strategy_decisions_to_target_weights(..., emit_unchanged_snapshots=True)`：横截面路径每个执行日都输出完整目标快照，用于修正漂移与重试未成交目标；旧策略默认仍跳过无变化日期。
- 最终 `rank` 是容量裁剪与买入优先级的唯一权威：`priority = -rank`；raw score 仅作审计字段。
- `previous_assets_by_trade_date` 已实现：可从中途持仓构造清仓零目标，空 selection + prior holdings 不再返回空 Frame。
- `cash_buffer` 约束 fallback / default / 显式权重：总和不超过 `1 - cash_buffer`，超额按比例缩小，不足不放大。
- `score_column` 不得与保留字段冲突（`trade_date/asset_id/rank/selected/eligible/reason_code/selection_eligible`）；`score` 本身允许作为 canonical 分数列。
- EXIT `eligibility_reason` 区分：`NOT_TOP_N` / `INELIGIBLE` / `MISSING_ELIGIBILITY` / `INVALID_SCORE` / `MISSING_SIGNAL_ROW`。
