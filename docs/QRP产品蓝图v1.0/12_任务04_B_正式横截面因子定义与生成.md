## 3. Factor Frame 契约

输出至少包含：

- `trade_date`
- `asset_id`
- 明确命名的因子列

并遵循 04-A 契约：

- `trade_date` 统一为 timezone-naive 午夜 Timestamp；
- `(trade_date, asset_id)` 唯一且非空；
- 稳定排序：`trade_date`, `asset_id`；
- 不修改调用方输入；
- 空股票池 / 空日期返回稳定空结构（保留列）；
- 非法值和缺失值使用 NaN，不得隐式填零；
- 价格 / 市值输入面板若存在重复 `(trade_date, asset_id)`，正式入口显式报错，不静默 `keep="last"`。

数据层次：

| 层次 | 含义 | 位置 |
|---|---|---|
| 原始数据字段 | close / market_cap / 版本化财务 | contracts / pipeline / backtest 查询 |
| 已对齐财务面板 | `trade_date, asset_id, roe, bps` | `prepare_financial_factor_panel` |
| 原始因子值 | momentum / log_market_cap / roe / book_to_price | `generate_factor_frame` |
| 横截面标准化结果 | rank / winsorize / z-score | 04-A |

## 4. 正式因子族

### 4.1 动量因子 `momentum`

- **公式**：`close[T] / close[T - lookback] - 1`
- **实现**：标准 N-bar 行偏移（按资产排序后 `shift(lookback)`）
- **参数**：`lookback`（整数，默认 20，最小 1）
- **方向**：越大 = 近期涨幅越强
- **时间可用性**：只使用 `trade_date <= T`；**包含 T 日收盘**；面向 **T+1 或之后执行**
- **缺失值语义**：
  - 窗口需要 `lookback + 1` 个 bar；
  - 两个端点必须有限且为正；
  - **中间缺失值仍占 bar 位置**，不会被跳过折叠；
  - 当前端点或滞后端点无效 → NaN。
- **默认输出列**：`momentum`；非默认 lookback 时为 `momentum_lookback_{N}`

### 4.2 市值因子 `log_market_cap`

- **公式**：`ln(field[T])`
- **字段**：默认 `market_cap`，可选 `float_cap` / `total_mv` / `circ_mv`
- **方向**：越大 = 规模越大
- **时间可用性**：仅同日市值记录
- **NaN 语义**：零 / 负 / NaN / ±inf / 缺失 → NaN

### 4.3 质量因子 `roe`

- **公式**：`financial_panel.roe[T]`
- **方向**：越大越好
- **输入**：已由 backtest 准备好的财务面板列 `roe`
- **NaN 语义**：面板缺行或 ROE 非有限 → NaN

### 4.4 价值因子 `book_to_price`

- **公式**：`financial_panel.bps[T] / close[T]`
- **方向**：越大越便宜
- **输入**：同一财务面板的 `bps` + 同日 `close`
- **NaN 语义**：BPS 或 close 缺失 / 非有限 / 非正 → NaN

## 5. 统一生成入口

```python
generate_factor_frame(
    factors,
    *,
    trade_dates=None,
    asset_ids=None,
    universe=None,
    prices=None,
    size_panel=None,
    financial_panel=None,
)
```

能力：

- 单因子 / 多因子；
- 因子参数与 alias；
- alias 与自动输出名均禁止保留列 `trade_date` / `asset_id`；
- 空股票池、空日期；
- 部分资产缺数据时保留资产并返回 NaN；
- 多日期隔离；
- 稳定因子列顺序；
- 未知因子 / 非法参数 / 重复输入键显式报错。

## 6. PIT 与审计语义

| 概念 | 含义 | 负责层 |
|---|---|---|
| 行情数据日期 | 价格 / 市值面板 `trade_date` | indicators 输入 |
| 财务报告期 | `report_period` | backtest 准备 |
| 财务 `available_trade_date` | 版本最早可用交易日 | backtest 准备 |
| 横截面 `trade_date` | 因子截面日 T | indicators 输出 |

目标交易日 T 的财务对齐规则：

```text
available_trade_date <= T
```

同一报告多次修订时，复用任务 03 的 `select_latest_available_records`。
开发与测试使用内存 fixture / 临时 DuckDB，不依赖 Linux 全量回填。
