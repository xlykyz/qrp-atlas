# 任务 01：参数化指标与经典单标的策略

## 一、公开指标接口

参数化指标能力由 `qrp_atlas.indicators` 公开：

```python
from qrp_atlas.indicators import IndicatorRequest, calculate_indicators

requests = (
    IndicatorRequest("sma", {"window": 20}, alias="fast_sma"),
    IndicatorRequest("sma", {"window": 60}, alias="slow_sma"),
)
prepared = calculate_indicators(price_df, requests)
```

`IndicatorRequest` 包含：

- `code`：计算注册 code；
- `parameters`：指标参数，可使用 `IndicatorParameterBinding` 绑定策略参数；
- `alias`：请求的稳定身份，单输出指标默认也以 alias 作为输出列；
- `output_fields`：将计算器的标准输出名显式映射为 DataFrame 列名。

`get_calculation_definition(code)` 可读取参数 schema、所需基础字段和标准输出。当前公开计算 code 如下：

| code | 参数（默认值、范围） | 输入 | 输出 | 时点语义 |
|---|---|---|---|---|
| `sma` | `window=20`，2..10000 | close | value | 含当前 bar |
| `period_return` | `lookback=20`，1..10000 | close | value | 当前 close / N bar 前 close - 1 |
| `donchian_high` | `window=20`，2..10000 | high | value | 先 shift(1)，严格排除当前 bar |
| `donchian_low` | `window=20`，2..10000 | low | value | 先 shift(1)，严格排除当前 bar |
| `rolling_mean` | `window=20`，2..10000 | close | value | 含当前 bar，只用当时可见值 |
| `rolling_std` | `window=20`，2..10000 | close | value | 总体标准差 `ddof=0` |
| `rolling_zscore` | `window=20`，2..10000 | close | value | `(close - mean) / std`，含当前 bar |

所有时间序列计算先按 `ticker, trade_date` 稳定排序，再按 ticker 独立 rolling/shift。完整窗口形成前输出 `NaN`；区间收益除零、z-score 的零标准差以及其他非有限计算结果也输出 `NaN`。指标层不填造数值，策略把这些值视为 warm-up，不产生虚假入场或退出。

## 二、alias 与输出规则

- 显式 alias 必须是稳定标识符，只允许字母、数字和下划线，且不能以数字开头；
- 未提供 alias 时，由 `code` 和按名称排序的规范化参数确定性生成，例如 `sma_window_20`；
- 策略参数绑定会在不同运行中改变参数值，因此这类策略声明必须显式提供稳定 alias；
- 单输出指标默认使用 alias 作为输出列；多输出指标默认使用 `<alias>_<标准输出>`；
- `output_fields` 可覆盖所需标准输出的列名；未知标准输出会被拒绝；
- 同一批请求中的重复 alias、重复输出列、与输入基础字段同名的输出列均抛出 `IndicatorConflictError`；
- 未知 code 抛出 `UnknownIndicatorError`；缺失、未知、类型错误或越界参数抛出 `IndicatorRequestError`。

旧 `required_indicators` 字符串声明继续兼容。MA5 趋势和 System B 状态由 indicators 层转换为普通请求并从同一 `calculate_indicators()` 入口计算，runtime 不再知道这些指标的实现或依赖。

## 三、内置策略

| code | version | 参数 | 逻辑 |
|---|---|---|---|
| `time_series_momentum` | `1.0.0` | `lookback=20`，`threshold=0.0` | 区间收益高于阈值入场，回落至阈值或以下退出 |
| `dual_sma_trend` | `1.0.0` | `fast_window=20`，`slow_window=60` | 快线高于慢线入场，不再高于时退出；要求 fast < slow |
| `donchian_breakout` | `1.0.0` | `entry_window=20`，`exit_window=10` | close 突破历史上轨入场，跌破历史下轨退出；两条通道均排除当前 bar |
| `rolling_zscore_mean_reversion` | `1.0.0` | `lookback=20`，`entry_z=2.0`，`exit_z=0.0` | z-score <= -entry_z 入场，回归至 >= -exit_z 退出；要求 exit_z < entry_z |
| `system_b_basic` | `1.0.0` | 无 | 保持原有 System B 状态策略与接口兼容 |

所有策略只实现 long-only，按 ticker 独立维护一次运行内的持仓状态。未持仓时不会重复 ENTER，持仓时不会重复 EXIT；每个输入 bar 都稳定输出 `ENTER / HOLD / EXIT / NO_ACTION` 之一，并提供固定 reason code。策略不访问数据库、不计算指标、不模拟成交。

## 四、runtime 准备链路

`StrategyBacktestRuntime` 的准备过程为：

```text
读取 StrategyDefinition
→ 解析策略参数默认值与类型/范围
→ 转换旧 required_indicators 声明
→ 绑定 indicator_requests 中的策略参数
→ calculate_indicators() 通用计算
→ 仅选择策略声明的字段和指标输出
→ 运行策略
→ 将决策交给原 BacktestEngine 执行组件
```

runtime 不 import 具体指标计算器，也不按策略 code 或指标族分支。新增参数化指标时在 indicators 注册计算定义；新增策略时声明 `indicator_requests`，无需修改 runtime。

最小新增策略流程：

1. 在 indicators 注册缺少的客观计算；已有计算直接复用；
2. 创建稳定 `StrategyDefinition`，声明基础字段、参数 schema 和带稳定 alias 的指标请求；
3. 策略只读取准备好的 alias 列并输出标准决策；
4. 在策略注册表注册版本；
5. 增加指标时点、策略状态机和 runtime 集成测试。

## 五、已知限制

- 本阶段仅支持单标的逻辑的 long-only 决策；多 ticker 可独立运行，但尚无共享组合资金账户；
- `StrategyBacktestRuntime` 继续复用现有交易级执行语义，不提供 T+1、涨跌停、停牌、整手或最低佣金；
- 未实现横截面指标、因子、事件、short、多腿、真实回测任务 API 或前端策略配置；
- 指标版本快照、组合净值和完整结果复现由后续蓝图任务完成。
