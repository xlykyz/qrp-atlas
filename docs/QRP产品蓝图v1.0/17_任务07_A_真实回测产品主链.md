# 任务 07-A：真实回测产品主链

> **状态：✅ 已完成**（任务 00 校准 2026-07-15）
## 目标

把前端模拟工作流升级为第一条真实可运行产品链路：

```text
读取真实策略目录
→ 根据 parameter schema 配置策略
→ 配置股票、日期、资金、成本和执行规则
→ 创建真实回测任务
→ 后端准备本地标准数据
→ 运行策略和组合回测
→ 保存标准结果文件
→ 查询任务状态
→ 在现有结果页面打开真实 run
→ 刷新页面后仍能再次访问
```

07-A 只打通经典价格行为策略产品主链，不覆盖任务 07 的全部能力。

## Task 状态机

```text
pending → running → succeeded
                  ↘ failed
```

成功条件：

1. 策略与参数校验通过；
2. 本地行情准备成功；
3. 策略/组合执行成功；
4. 标准结果包原子写入成功。

任何一步失败都不得标记 `succeeded`。

## 执行时间语义

### signal date

策略使用正式区间内 bar 生成决策的日期，记为 `signal_date`。

### execution date

组合引擎 target / order / fill 使用的成交日期，记为 `execution_date`。

映射基于行情数据中的**市场交易日序列**（排序唯一），不是自然日 `+1`。

### `next_open`（默认）

```text
signal_date = T
execution_date = 严格晚于 T 的下一个市场交易日
execution_price = execution_date.open
```

T 日收盘信号不得按 T 日开盘成交。

### `next_close`

```text
signal_date = T
execution_date = 严格晚于 T 的下一个市场交易日
execution_price = execution_date.close
```

不得与 `same_close` 使用相同日期语义。

### `same_close`

```text
signal_date = T
execution_date = T
execution_price = T.close
```

该模式可保留，但：

- 不是默认值；
- 明确标记为同 bar 收盘执行；
- **不是严格 point-in-time 安全模式**；
- 不影响 `next_open` / `next_close` 验收。

### 区间末尾

若 `next_*` 在请求 `end_date` 内找不到下一交易日：

- 不得在 `end_date` 后成交；
- 不得扩大正式回测区间；
- 记录诊断原因码：`NO_EXECUTION_DATE_IN_RANGE`。

结果可审计约束：

- `trades.json.signal_date` = 真实策略信号日
- `trades.json.entry_date` = 实际成交日（next_* 时严格晚于 signal_date）
- 产品层 `NO_EXECUTION_DATE_IN_RANGE` 进入 `skipped.json` 并计入 `summary.skipped_count`

最终约束：

```text
orders / fills / equity / snapshots 的日期
全部满足 request.start_date <= date <= request.end_date
```

## Warmup 与正式区间隔离

1. 为指标计算加载 `start_date` 之前的预热行情；
2. `prepare_strategy_data` 可在全量预热数据上计算指标；
3. 策略 `run()` 仅接收正式区间 `[start_date, end_date]` 的 prepared rows；
4. 策略初始持仓固定为空；
5. 组合引擎只使用正式区间 price frame；
6. config 保存：
   - `requested_start_date` / `requested_end_date`
   - `effective_start_date` / `effective_end_date`

## 结果目录 SSOT

唯一产品结果目录环境变量：

```text
QRP_ATLAS_BACKTEST_RUNS_DIR
```

默认：

```text
data/backtest_runs
```

- writer 与 loader 统一使用该目录；
- fixture 目录：`tests/fixtures/backtest_runs`（`BACKTEST_FIXTURE_RUNS_DIR`）
- fixture 仅用于 mock / 显式测试，不进入默认产品结果 API。

任务持久化：

```text
data/backtest_tasks
QRP_ATLAS_BACKTEST_TASKS_DIR
```

## 配置快照

`BacktestRunWriter.write_portfolio_run(..., config_overlay=...)` 在临时目录内原子写入全部结果文件，包含：

- portfolio config；
- `product_request`；
- `strategy_params`；
- `entry_timing`；
- requested/effective 日期；
- execution_semantics（含 same_close 警告与 skipped signals）。

写入失败：

- 不提交 run 目录；
- task 标记 `failed`；
- 不返回成功 `run_id`。
