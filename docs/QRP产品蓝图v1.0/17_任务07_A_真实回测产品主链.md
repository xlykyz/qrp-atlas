# 任务 07-A：真实回测产品主链

## 目标

把前端模拟工作流升级为第一条真实可运行产品链路：

```text
读取真实策略目录
→ 根据 parameter schema 配置策略
→ 配置股票、日期、资金、成本和执行规则
→ 创建真实回测任务
→ 后端准备本地标准数据
→ 运行策略和组合回测
→ 保存标准结果文件
→ 查询任务状态
→ 在现有结果页面打开真实 run
→ 刷新页面后仍能再次访问
```

07-A 只打通经典价格行为策略产品主链，不覆盖任务 07 的全部能力。

## API

### 目录 API

- `GET /api/indicators`
  - 指标目录：注册表指标 + 参数化计算入口 + 横截面因子元数据
- `GET /api/strategies`
  - 默认仅返回 07-A 产品支持策略
  - `?all=true` 可返回完整 registry（含横截面策略，但产品执行链仍不开放）
- `GET /api/strategies/{code}?version=...`
  - 返回 code/version/name/description/family/scope/required_fields/
    required_indicators/parameter_schema/indicator_requests

目录直接复用 `qrp_atlas.strategies` 与 `qrp_atlas.indicators` 注册表，不维护第二套策略清单。

### 回测任务 API

- `POST /api/backtest/tasks`
- `GET /api/backtest/tasks`
- `GET /api/backtest/tasks/{task_id}`

请求体与前端 `CreateBacktestTaskRequest` 对齐，核心字段：

- strategy_code / strategy_version / strategy_params
- universe_mode / tickers
- start_date / end_date
- position: initial_cash, max_positions, max_weight_per_symbol
- cost: commission_rate, stamp_tax_rate, slippage_bps
- execution.entry_timing: next_open | same_close | next_close

任务响应包含：

- 稳定状态
- 失败原因 `error_message`
- 成功后的 `run_id`
- 完整 `request_snapshot`

### 结果 API（复用既有）

- `GET /api/backtest/runs`
- `GET /api/backtest/runs/{run_id}`
- `GET /api/backtest/runs/{run_id}/summary`
- `GET /api/backtest/runs/{run_id}/equity`
- `GET /api/backtest/runs/{run_id}/trades`
- `GET /api/backtest/runs/{run_id}/skipped`
- `GET /api/backtest/runs/{run_id}/config`

## Task 状态机

```text
pending → running → succeeded
                  ↘ failed
```

说明：

- 创建后立即落盘为 `pending`
- 07-A 默认同步执行（inline），请求返回前完成 `running → terminal`
- 前端兼容读取历史 mock 的 `queued/success`，HTTP adapter 会归一到产品状态枚举
- 不引入 Redis / Celery / 分布式队列

## 持久化方式

### 任务

目录：

```text
data/backtest_tasks/<task_id>.json
```

可用环境变量覆盖：

```text
QRP_ATLAS_BACKTEST_TASKS_DIR
```

### 结果

目录：

```text
data/backtest_runs/<run_id>/
  run_meta.json
  summary.json
  equity.json
  trades.json
  skipped.json
  config.json
  orders.json
  fills.json
  snapshots.json
```

可用环境变量覆盖：

```text
QRP_ATLAS_PRODUCT_BACKTEST_RUNS_DIR
```

结果读取层 `BacktestRunsLoader` 支持多根搜索：

1. `QRP_ATLAS_BACKTEST_RUNS_DIR`（若设置）
2. `data/backtest_runs`
3. `tests/fixtures/backtest_runs`

因此产品 run 与历史 fixture 可共存，结果 API 无需第二套格式。

## 真实执行链

```text
CreateBacktestTaskRequest
→ validate_create_request（后端权威校验）
→ BacktestTaskStore.create (pending)
→ load_stock_prices（本地 DuckDB 标准行情 + 停牌字段）
→ run_strategy_portfolio_backtest
   ├─ prepare_strategy_data / indicators
   ├─ strategy registry + parameters
   └─ PortfolioBacktestEngine
→ BacktestRunWriter.write_portfolio_run
→ task.status=succeeded + run_id
```

失败路径：

- 非法策略 / 参数 / 配置 → HTTP 400（创建前）
- 数据不足 / 执行异常 → task.status=failed + error_message（可查询）

## 当前支持策略

产品默认目录与执行链支持：

- `dual_sma_trend`（主验收）
- `system_b_basic`
- `time_series_momentum`
- `donchian_breakout`
- `rolling_zscore_mean_reversion`

不在 07-A 产品入口默认开放：

- 横截面 `cross_sectional_momentum_long_only`
- 横截面 `multifactor_long_only`
- 声明式策略编辑 / 任意 Python

## mock / http 切换

前端：

```text
VITE_BACKTEST_WORKFLOW_SOURCE=http|mock   # catalog + tasks，默认 http
VITE_BACKTEST_RESULT_SOURCE=http|mock     # results；未设时跟随 workflow
VITE_API_BASE_URL=...
```

实现：

- `web/src/api/adapters/mode.ts`
- mock adapters 保留
- 新增：
  - `strategy-catalog.http.ts`
  - `backtest-task.http.ts`
- 结果继续复用既有 `backtest-result.http.ts`

真实模式行为：

- 策略目录来自后端
- 创建任务/状态来自后端
- 成功任务跳转真实 `run_id` 且 `source=http`
- 结果页读取真实结果 API
- 不再默认写死 `sample_run_001/002`
- 任务与结果文件持久化，刷新后仍可访问
- 页面明确区分 mock / 真实模式

## 配置与校验

前端：

- schema 参数表单校验
- 股票列表、日期、资金、成本、仓位上限基础校验

后端（权威）：

- 策略 code/version 是否支持
- parameter schema + 策略关系约束（如 fast < slow）
- tickers 必填（07-A）
- 日期格式与区间
- initial_cash / max_positions / max_weight_per_symbol
- 成本与 entry_timing

07-A 明确限制：

- `universe_mode=preset` 暂不执行，需改为 tickers
