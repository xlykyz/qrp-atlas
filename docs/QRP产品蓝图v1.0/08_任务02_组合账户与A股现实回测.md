## 二、目标权重契约

`target_weights_df` 必需字段：

- `trade_date`
- `asset_id`
- `target_weight`

可选字段：

- `priority`：同一调仓日资金不足时的买入优先级，数值越大越优先；相同优先级按目标权重、资产代码稳定排序。

某个日期只要出现在目标权重输入中，就代表该日完整的目标组合快照；当前持仓中未出现在该日快照内的资产，其目标权重视为 0。没有目标快照的交易日只进行持仓盯市，不自动调仓。

`strategy_decisions_to_target_weights()` 已连接现有 `StrategyDecision`：

- `ENTER` 加入候选；
- `EXIT` 移出候选并生成零权重；
- `HOLD` 可更新分数和权重；
- `score` 用于超过持仓容量时的稳定排序；
- 显式正 `weight` 优先，否则使用默认权重或等权；
- 单资产权重封顶，总权重超过 1 时按比例缩放；
- 当前仅支持 long-only；
- 组合账户目前只支持纯现金起始，禁止只给策略注入已有持仓而不给账户注入，避免状态不一致。

## 三、组合账户能力

已实现：

- 单一共享现金账户；
- 多资产同时竞争同一份现金，禁止逐信号无限使用初始资金；
- 完整目标权重快照与卖出优先、买入后置的调仓顺序；
- 单资产最大权重、最大持仓数量和每日目标权重总和校验；
- 退出被跌停或停牌阻塞时，新增买单仍受真实持仓数量上限约束；
- 订单、成交、持仓和逐日账户快照；
- 现金、持仓市值、总权益、日收益、回撤和换手；
- 佣金、印花税、滑点及累计成本拆分；
- 净值由逐日真实现金和持仓市值生成，而不是拼接独立 Trade 收益。

## 四、A 股现实约束

已实现：

- 100 股整数手，手数由 `lot_size` 配置；
- 正目标不足一手时显式记录 `BELOW_LOT_SIZE`，不静默忽略；
- 买入最低佣金；
- 卖出印花税；
- 双边滑点直接进入实际成交价；
- T+1 可用数量：当日买入持仓在当日快照中不可卖，下一交易日解锁；
- 停牌禁止买卖；
- 涨停禁止买入；
- 跌停禁止卖出；
- 资金不足时按整手缩减为部分成交，完全无法成交时稳定拒绝；
- 缺行情、非法价格、停牌、涨跌停、资金不足、持仓数超限等拒绝原因可审计；
- 成交字段与盯市字段分离：例如按开盘价成交时，目标规模不会使用当日收盘价，收盘价仅用于成交后的日终盯市。

现实约束依赖行情输入中的可选字段：

- `is_limit_up`
- `is_limit_down`
- `is_suspended`，或非空 `suspend_type`

引擎不自行猜测涨跌停或停牌状态；数据层提供什么事实，执行层就按什么事实撮合。

## 五、结果与现有 API 契约

`PortfolioBacktestResult` 包含：

- `summary`
- `orders`
- `fills`
- `snapshots`
- `equity_curve`

`BacktestRunWriter` 原子写入现有结果层已经读取的六个文件：

- `run_meta.json`
- `summary.json`
- `equity.json`
- `trades.json`
- `skipped.json`
- `config.json`

因此现有 `/api/backtest/runs/...` 路由无需修改即可读取组合回测的元信息、汇总、净值、交易、拒单和配置。

同时保留三个组合审计文件：

- `orders.json`
- `fills.json`
- `snapshots.json`

买卖成交按 FIFO 转换为现有 `BacktestTrade` 契约；未平仓买入保留为 `open`，拒绝订单进入 `skipped.json`。订单、成交和账户快照的专用 API 留到任务 07，不属于任务 02 的阻塞项。
