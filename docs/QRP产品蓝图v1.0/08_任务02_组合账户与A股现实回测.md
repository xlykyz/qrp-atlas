## 一、本轮完成内容

本轮在既有 `backtest` 模块内新增组合级执行入口，不修改原有逐笔交易引擎的语义。

实现位于 `src/qrp_atlas/backtest/portfolio/`，按职责拆分为公开模型、输入校验、A 股执行辅助和组合引擎，没有新增顶级模块。

公开入口：

```python
from qrp_atlas.backtest import (
    PortfolioBacktestConfig,
    PortfolioBacktestEngine,
    PortfolioExecutionRule,
)
```

执行接口：

```python
result = PortfolioBacktestEngine().run(
    price_df=price_df,
    target_weights_df=target_weights_df,
    config=config,
)
```

`target_weights_df` 的必需字段为：

- `trade_date`
- `asset_id`
- `target_weight`

可选字段：

- `priority`：同一调仓日资金不足时的买入优先级，数值越大越优先；相同优先级按目标权重、资产代码稳定排序。

某个日期只要出现在 `target_weights_df` 中，就代表该日完整的目标组合快照；当前持仓中未出现在该日快照内的资产，其目标权重视为 0。没有目标快照的交易日只进行持仓盯市，不自动调仓。

## 二、组合账户能力

已实现：

- 单一共享现金账户；
- 多资产同时竞争同一份现金，禁止逐信号无限使用初始资金；
- 完整目标权重快照与卖出优先、买入后置的调仓顺序；
- 单资产最大权重、最大持仓数量和每日目标权重总和校验；
- 退出被跌停或停牌阻塞时，新增买单仍受真实持仓数量上限约束；
- 订单、成交、持仓和逐日账户快照；
- 现金、持仓市值、总权益、日收益、回撤和换手；
- 佣金、印花税、滑点及累计成本拆分；
- 可直接供现有结果层使用的标准净值曲线：`date / equity / drawdown_pct`。

## 三、A 股现实约束

已实现：

- 100 股整数手，手数由 `lot_size` 配置；
- 正目标不足一手时显式记录 `BELOW_LOT_SIZE`，不静默忽略；
- 买入最低佣金；
- 卖出印花税；
- 双边滑点，直接进入实际成交价；
- T+1 可用数量：当日买入持仓在当日快照中不可卖，下一交易日解锁；
- 停牌禁止买卖；
- 涨停禁止买入；
- 跌停禁止卖出；
- 资金不足时按整手缩减为部分成交，完全无法成交时稳定拒绝；
- 缺行情、非法价格、停牌、涨跌停、资金不足、持仓数超限等拒绝原因可审计；
- 成交字段与盯市字段分离：例如按开盘价成交时，目标规模不会使用当日收盘价，收盘价仅用于成交后的日终盯市。

现实约束依赖行情输入中的可选字段：

- `is_limit_up`
- `is_limit_down`
- `is_suspended`，或非空 `suspend_type`

引擎不自行猜测涨跌停或停牌状态；数据层提供什么事实，执行层就按什么事实撮合。

## 四、结果对象

`PortfolioBacktestResult` 包含：

- `summary`
- `orders`
- `fills`
- `snapshots`
- `equity_curve`

核心汇总字段包括：

- `initial_cash`
- `final_equity`
- `total_return / total_return_pct`
- `max_drawdown / max_drawdown_pct`
- `turnover`
- `order_count / fill_count / trade_count / skipped_count`
- `commission / stamp_tax / slippage_cost / total_cost`

净值不是根据独立 Trade 收益拼接，而是由每日真实现金和持仓市值生成。

## 五、兼容性边界

原有接口保持不变：

```python
BacktestEngine().run(price_df, signals_df, config)
```

原有 `BacktestConfig / BacktestResult / Trade / Skipped` 未修改。旧逐笔引擎仍适合信号研究、单笔 MAE/MFE 和固定持有测试；新组合引擎负责共享资金、目标权重、真实成交和资金曲线。
