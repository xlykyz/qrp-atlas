## 二、目标权重契约

`target_weights_df` 必需字段：

- `trade_date`
- `asset_id`
- `target_weight`

可选字段：

- `priority`：资金不足时的买入优先级；相同优先级按目标权重、资产代码稳定排序。

某个日期只要出现在目标权重输入中，就代表该日完整的目标组合快照；当前持仓中未出现的资产，其目标权重视为 0。没有目标快照的交易日只进行持仓盯市。

`strategy_decisions_to_target_weights()` 已连接现有 `StrategyDecision`：

- `ENTER` 加入候选；
- `EXIT` 移出候选并生成零权重；
- `HOLD` 可更新分数和权重；
- `score` 用于超过持仓容量时的稳定排序；
- 显式正 `weight` 优先，否则使用默认权重或等权；
- 单资产权重封顶，总权重超过 1 时按比例缩放；
- 当前仅支持 long-only；
- 组合账户只支持纯现金起始，禁止只给策略注入已有持仓而不给账户注入。

## 三、组合账户与 A 股现实成交

已实现：

- 单一共享现金账户，多资产竞争同一份现金；
- 完整目标权重调仓，卖出优先、买入后置；
- 单资产最大权重、最大持仓数和每日权重总和校验；
- 退出被跌停或停牌阻塞时，新增买单仍受真实持仓数限制；
- 100 股整数手，低于一手显式拒绝；
- 最低佣金、卖出印花税、双边滑点；
- T+1 可用数量；
- 停牌禁止买卖；
- 涨停禁止买入；
- 跌停禁止卖出；
- 资金不足按整手部分成交；
- 缺行情、非法价格、停牌、涨跌停、资金不足、持仓数超限等稳定拒单原因；
- 成交字段与日终盯市字段分离，开盘成交不会使用当日收盘价定仓；
- 订单、成交、持仓和逐日账户快照；
- 现金、持仓市值、总权益、日收益、回撤、换手和成本拆分。

现实约束依赖行情输入中的可选字段：

- `is_limit_up`
- `is_limit_down`
- `is_suspended`，或非空 `suspend_type`

`load_stock_prices()` 已从本地 DuckDB 的 `daily_market_snapshot` 读取涨跌停字段，并通过 `trade_date + ticker` 左联聚合后的 `suspend_d` 补充：

- 有停牌记录：`is_suspended=True`
- 无停牌记录：`is_suspended=False`
- 同一交易日多条 `suspend_type` 先按 `(trade_date, ticker)` 聚合，再关联行情，保证每个 `(trade_date, ticker)` 仅一行
- 聚合后的 `suspend_type` 使用稳定排序后的可审计字符串，例如 `R,S`

引擎不自行猜测涨跌停或停牌状态，执行层只使用数据层提供的事实。

## 四、结果与现有 API 契约

`PortfolioBacktestResult` 包含：

- `summary`
- `orders`
- `fills`
- `snapshots`
- `equity_curve`

净值由逐日真实现金和持仓市值生成，不拼接独立 Trade 收益。

`BacktestRunWriter` 写入现有结果层已经读取的六个文件：

- `run_meta.json`
- `summary.json`
- `equity.json`
- `trades.json`
- `skipped.json`
- `config.json`

因此现有 `/api/backtest/runs/...` 路由无需修改即可读取组合回测结果。

同时保留三个审计文件：

- `orders.json`
- `fills.json`
- `snapshots.json`

买卖成交按 FIFO 转换为现有 `BacktestTrade` 契约；未平仓买入保留为 `open`，拒绝订单进入 `skipped.json`。全胜样本的 `max_trade_loss_pct`、全亏样本的 `max_trade_profit_pct` 均保持为空，不混淆盈亏极值语义。

订单、成交和账户快照的专用 API 留到任务 07，不属于任务 02 的阻塞项。
