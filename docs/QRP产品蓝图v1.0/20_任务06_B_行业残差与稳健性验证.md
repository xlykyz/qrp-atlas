## 3. 行业残差 PIT 语义

### 3.1 数据准备入口

```python
from qrp_atlas.backtest import prepare_industry_residual_panel
```

每个资产日期 T 的行业：

```text
query_industry_as_of(as_of_date=T)
# 或等价 industry_panel / industry_query
```

通过 `prepare_cross_section_exposure_panel` 复用正式 PIT 语义。

禁止：

- 用当前行业回看历史；
- 使用 T 之后生效/可用的行业记录；
- 行业归属 backward fill；
- 缺失行业默认归入其他行业或市场；
- 同日多行业静默保留一条。

### 3.2 行业基准契约

两种互斥输入：

1. 价格面板：`trade_date, industry_code, close`
2. 收益面板：`trade_date, industry_code, benchmark_return`

对齐规则：

```text
asset @ T
→ PIT industry_code
→ exact (trade_date=T, industry_code)
```

禁止 forward/backward fill、邻近交易日替代、市场 benchmark fallback。

### 3.3 输出

交给既有 `calculate_market_residuals`：

- `benchmark_id = industry_code`
- 保留 `preparation_diagnostic_code` 与 `indicator_diagnostic_code`
- 指标诊断不被准备层覆盖

准备层诊断至少：

- `MISSING_INDUSTRY`
- `MISSING_INDUSTRY_BENCHMARK`

### 3.4 研究入口

```python
from qrp_atlas.backtest import run_industry_residual_research
```

复用 residual z-score 分组、forward return、极端负残差对比。  
**不注册**行业残差交易策略；`market_residual_mean_reversion` 仍为市场残差代表策略。

## 4. Walk-forward 与参数选择

### 4.1 切分

```python
WalkForwardConfig / WalkForwardSplit / build_walk_forward_splits
```

- 全部长度按唯一排序交易日计数；
- fold 内 `train → validation → test` 连续、不重叠、不倒序；
- rolling：固定长度 train 前移；
- expanding：train 起点固定，终点扩展；
- `step_size >= test_size`，否则拒绝；
- 不足完整 test 的尾部丢弃并记 diagnostics。

### 4.2 参数网格

只允许 `market_residual_mean_reversion` 已声明参数。  
笛卡尔积 + canonical JSON candidate id；默认最大 256。

### 4.3 选择

- train：资格与 diagnostics；
- validation：唯一参数选择来源；
- test：正式 OOS，初始现金重置、空仓、可用 prior history warmup；
- 目标：`net_total_return` / `net_sharpe` / `net_calmar`（默认 `net_calmar`）；
- tie-break：目标降序 → |max_drawdown| 升序 → trade_count 降序 → candidate_id 升序；
- 全候选无效：`selection_failed`，不跑 test，不偷偷用默认参数。

### 4.4 防未来函数

- 运行 segment 时输入最大日期 `<= segment_end`；
- 修改 test 数据不改变 selected parameters；
- 修改 test 之后数据不改变该 fold 结果；
- cost stress 不重新选择参数；
- 参数敏感性只汇总 validation。

## 5. 收益、成本、OOS

### 5.1 gross-before-recorded-costs

```text
gross_pnl_before_recorded_costs
= final_equity - initial_cash + total_recorded_cost
```

这是同一成交路径上“加回已记录成本”的成交前成本口径，**不是**重新模拟的零成本组合。

### 5.2 net / cost drag

- net：组合实现权益路径；
- `cost_drag = total_recorded_cost / initial_cash`；
- JSON 中无 NaN / Inf，不可计算为 `None`。

### 5.3 OOS 拼接

- 仅 test 日期；
- 不重叠；
- 统一净值从 1.0 链式累计，跨 fold 不重置。

### 5.4 滚动表现

交易日窗口由调用方传入（默认 20/60/120），只基于统一 OOS。

### 5.5 成本压力

同一 selected parameters，在不同成本配置下重跑组合。  
策略 decisions / signal targets 应相同；fills 数量可因成本改变。  
**不保证**净收益对成本单调。
