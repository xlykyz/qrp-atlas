# QRP v1.0 产品终点

> 任务 00 状态校准：2026-07-15。研究与底座任务 01～06、07-A、07-B1 已完成；剩余 07-B2/07-C/07-D/08。不宣告发布完成。

## 一、产品终点定义

QRP v1.0 完成的判定标准不是“模块目录齐全”，也不是“回测出过一条收益曲线”，而是：

> 用户能够基于本地标准数据，选择内置策略或创建受限自定义策略，完成无未来函数的回测，得到包含真实 A 股约束、成本、组合净值、风险和复现快照的结果，并在前端比较和迭代。

完整用户路径：

```text
选择数据范围和股票池
→ 选择内置策略或编辑声明式策略
→ 设置参数、成交和成本规则
→ 运行回测
→ 查看组合净值、回撤、交易、换手、成本和暴露
→ 比较不同 run
→ 修改策略或参数
→ 重复验证
```

## 二、v1.0 必须完成的能力

### 2.1 数据底座

必须具备：

- 日线行情、复权因子、交易日历、股票基础信息；
- 估值、市值、换手、涨跌停、停牌；
- 指数行情；
- 财务三表和标准财务指标；
- 历史行业归属；
- 至少一类结构化公司事件（v1.0 第一类标准：`earnings_forecast_event + EventFrame`，不以泛化 `corporate_event` 为唯一验收对象）；
- 数据来源、发布时间、实际可用时间、入库时间和修订信息；
- 回测能够严格按 `available_at` 或等价口径使用数据。

### 2.2 指标层

必须具备：

- 参数化指标请求、alias 和统一计算注册；
- 通用时间序列指标；
- 横截面排名、去极值、标准化；
- 基础行业/市值中性化；
- 价值、质量、盈利、成长、投资、动量、波动率、流动性等代表性因子；
- 事件年龄、事件窗和 surprise 类指标；
- rolling beta、残差、残差 z-score 等相对价值指标；
- 所有指标按标的和时间稳定计算，不产生未来函数；
- 指标版本可以进入回测快照。

### 2.3 策略层

必须保留统一策略契约，并至少覆盖：

#### 价格行为类

- `system_b_basic`
- `time_series_momentum`
- `dual_sma_trend`
- `donchian_breakout`
- `rolling_zscore_mean_reversion`

#### 横截面类

- `cross_sectional_momentum_long_only`
- `multifactor_long_only`

#### 信息驱动类

- 至少一个基于 `earnings_forecast_event` 的 `event_drift_basic`（研究链路已完成，产品闭环见 07-B2）；

#### 相对价值类

- 至少一个 `market_residual_mean_reversion` 或等价研究策略。

要求：

- 每个策略有稳定 code、version、参数 schema、输入声明和目录元数据；
- 相同输入与参数输出完全一致；
- 所有策略可通过统一回测运行器运行；
- 内置策略与声明式策略共享标准输出；
- 不把指标计算复制进策略。

### 2.4 回测系统

必须具备：

- 原简单信号回测继续兼容；
- 动态 ENTER/HOLD/EXIT；
- 多标的并行持仓；
- 初始资金、现金、目标权重、最大持仓数、单票上限；
- 定期和信号驱动调仓；
- 组合资金竞争和复利；
- 真实组合净值和回撤曲线；
- T+1；
- 涨停买入限制、跌停卖出限制；
- 停牌不可成交；
- 100 股整数手和现金不足；
- 佣金、最低佣金、印花税、滑点；
- 可选成交量容量限制；
- 换手和成本统计；
- 代表性残差策略具备 train/validation/test 与基础 walk-forward（全策略通用稳健性框架延后 v1.1）；
- 所有 skipped 和成交拒绝均有稳定原因码。

### 2.5 结果与验证

必须输出：

- 组合资金曲线和回撤；
- 总收益、年化收益、最大回撤；
- Sharpe、Sortino、Calmar；
- 胜率、盈亏比、持仓周期、MAE/MFE；
- 换手率；
- 毛收益、费用、滑点和净收益拆分；
- 股票、行业、市值和市场 Beta 暴露的基础视图；
- 滚动收益和滚动回撤；
- 代表性残差研究的样本内/样本外结果（标准产品 run 的通用 OOS 标签不作为全策略强制门禁）；
- 参数、策略定义、指标版本、数据区间、成本与成交配置快照。

### 2.6 API 与前端

必须完成：

- 指标目录 API；
- 策略目录与版本 API；
- 声明式策略校验 API；
- 创建并运行回测任务；
- 回测任务状态查询；
- 结果查询和 run 对比；
- 前端内置策略选择；
- 基于 schema 的参数表单；
- 受限声明式策略编辑器；
- 股票池、日期、成本和执行规则配置；
- 组合净值、回撤、交易、成本、换手和配置快照展示。

## 三、v1.0 增强项

以下能力有价值，但未完成时不阻塞 v1.0 发布：

- 完整 long-short 市场中性；
- 多腿配对同步成交；
- 借券、融资、保证金；
- ETF 申赎、期现和期权波动率套利；
- 监督学习参考策略；
- 更完整因子归因和容量模型；
- 自动参数扫描和组合优化。

## 四、明确排除项

以下能力不属于 v1.0：

- 强化学习交易环境；
- 高频做市；
- Level-2/订单簿微结构预测；
- 延迟套利；
- 微秒级撮合；
- 分布式回测集群；
- 任意 Python 上传执行；
- 协整完整多腿交易产品化；
- 分布式回测集群以外的超高性能扩展；
- 实盘自动下单；
- 面向第三方多租户的 SaaS 权限与计费。

## 五、发布阻塞条件

出现以下任一情况，v1.0 不得标记完成：

1. 回测组合净值仍由示例文件伪造或无法从真实交易流水生成；
2. 财务/事件回测无法证明数据在当时已经可用；
3. 策略在同一输入下不可复现；
4. 多标的回测未真正执行资金约束；
5. 涨跌停、停牌和 T+1 仍完全忽略；
6. 成本后结果无法与毛收益拆分；
7. 前端只能查看结果，不能创建一次完整策略回测；
8. 结果缺少策略、指标、数据和执行快照；
9. 代表性横截面策略和事件策略没有端到端样例；
10. 完整测试不通过。

## 六、v1.0 最终演示场景

发布前至少完成三条可重复演示：

### 场景 A：单标的经典策略

```text
选择 dual_sma_trend
→ 修改 fast/slow 参数
→ next_open + A 股成本
→ 运行多个股票
→ 查看交易、净值和回撤
```

### 场景 B：横截面组合策略

```text
选择 cross_sectional_momentum_long_only
→ 设置股票池、Top N、调仓频率和单票上限
→ 运行组合回测
→ 查看换手、成本、行业和市值暴露
```

### 场景 C：事件驱动策略

```text
选择 event_drift_basic
→ 基于 earnings_forecast_event 配置过滤与持有期
→ 只使用当时已发布/可用的信息
→ 运行产品回测
→ 查看事件交易、skipped、净值与配置快照
→ 证明无未来公告或修订泄漏
```

三条场景均能由前端发起、后端运行、结果层保存并再次打开，才说明 QRP 已从后端研究组件升级为可交付产品。
