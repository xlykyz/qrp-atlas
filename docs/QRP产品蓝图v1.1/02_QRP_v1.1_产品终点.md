# QRP v1.1 产品终点

> 状态：范围基线草案，等待蓝图 PR 验收。  
> 基线：main `a307e58e138677cadcc38a0da2148639b1f99a5c`。  
> 本文件定义 v1.1 完成条件；中间任务、原型或单次成功下单均不能替代最终验收。

## 一、产品终点定义

QRP v1.1 完成的判定标准是：

> 用户能够基于每日更新的标准数据和版本化规则，在收盘后得到市场授权、主线题材、核心身份、System B 候选、完整目标组合和次日订单计划；系统能够在无人盘中点击买卖的前提下，通过 QMT 执行、恢复和对账，并把每一项决定和结果保存为可回测、可比较、可重放的审计记录。

完整生产路径：

```text
数据更新与水位确认
→ 市场状态与策略授权
→ 产业—题材周期与主线识别
→ M1/M2/M3 核心身份
→ 全市场 System B 趋势状态
→ 资格与硬否决
→ 评分、排序与容量选择
→ 账户目标组合
→ 次日订单计划冻结
→ QMT 自动执行
→ 订单、成交与持仓对账
→ 持仓持续管理与退出
→ 日结、归因、复盘和历史回放
```

## 二、生产范围

### 2.1 正式生产策略

v1.1 只把 `System B` 建设为正式实盘生产策略。

必须具备：

- 全市场状态检测；
- 市场授权；
- 题材授权；
- M1—M3 核心身份；
- 可交易性与风险硬否决；
- 评分、排名和容量选择；
- 完整目标组合；
- 入场、持有、退出和异常优先级；
- 回测、纸面、仿真和实盘一致的策略语义。

`system_b_basic@1.0.0` 保留兼容，但不作为正式生产版本。

### 2.2 判断层

判断层必须输出：

```text
market_phase
new_position_authorized
strategy_authorizations
veto_reasons
confidence
rule_version
evidence
```

边界：

- 只决定是否允许新增仓位；
- 收盘后计算并冻结至下一次正式更新；
- 盘中不因价格波动临时切换；
- 不直接清除已有持仓；
- 不覆盖 System B 的正式退出规则；
- 全局紧急风险门属于 trading 风控，不属于市场判断层。

### 2.3 System A、System C 与治理文档

- System A：`LEGACY`，保留历史规则资产、旧交易归因和研究回放，不进入 v1.1 实盘授权链；
- System C：不属于 v1.1；
- 第一性原理：治理层方向校准和系统审计依据；
- 时间约束：治理与版本评估依据；
- 任何旧规则只有在任务 00 被裁决为 `CURRENT` 后，才能进入代码。

## 三、v1.1 必须完成的能力

### 3.1 规则与版本治理

必须具备：

- 规则资产清单；
- 来源文档和原始表述；
- `CURRENT / LEGACY / EXPERIMENTAL / DISABLED / REJECTED` 状态；
- 冲突裁决；
- 规则优先级；
- 参数定义和参数集版本；
- 策略版本；
- 变更单；
- 审批和生效时间；
- 历史版本不可变；
- 决策能够关联当时使用的规则与参数版本。

### 3.2 数据与 PIT

必须具备：

- 历史全 A 活跃股票池；
- 上市、退市、ST、风险警示、停复牌；
- 涨跌停和价格限制；
- 日线、成交额、换手、市值、量比等；
- 严重异常交易监管事实；
- 指数和市场宽度；
- 产业、产业链、题材、题材周期和成员；
- 催化、证据、来源、反证和修订；
- 角色、授权、资格、评分、目标组合、订单和对账事实；
- 所有历史查询使用当时可用数据；
- 数据缺失、延迟和覆盖率不得静默当作正常。

### 3.3 指标与状态

必须具备：

- System B 完整生命周期；
- 趋势确认、运行、首次跌破、恢复、退出和重启；
- 趋势斜率、拟合度、效率、动量、波动、回撤、量价、流动性；
- 相对市场、行业和题材强度；
- 指数节点和市场风险扩散；
- M1—M6 客观组成指标；
- 题材强度、扩散、核心、资金、拥挤、风险和生命周期；
- 每项指标的公式、窗口、方向、时点、coverage、诊断和 calculation version；
- 指标不生成交易动作。

### 3.4 动态产业—题材库

必须把现有预研正式代码化，至少覆盖：

- 行业、产业链和题材分模；
- 标准实体、别名和版本；
- 题材周期；
- 公司—产业关系；
- 题材—产业关系；
- 题材成员事实；
- 成员业务相关度和市场共振度分离；
- 来源文档、证据和反证；
- 生命周期状态机；
- 变化事件；
- proposal / review / canonical commit；
- owner 私有研究空间；
- PIT 查询和历史回放；
- Agent 默认只读，只能提交带引用提案。

### 3.5 核心身份

必须识别并记录：

- M1 容量核心；
- M2 空间前排；
- M3 辨识度；
- 同一标的多角色；
- 同一题材多个候选；
- 角色分数、置信度、证据和否决；
- 首次确认和失效时间；
- 与 `theme_cycle` 绑定；
- 人工提案和受控审核；
- 历史时点可重放。

### 3.6 资格、硬否决和评分

资格链必须为：

```text
市场授权
∩ 题材授权
∩ M1/M2/M3 身份
∩ System B 趋势状态
∩ 可交易性
∩ 风险约束
= eligible pool
```

要求：

- eligibility 与 rank 分离；
- 硬否决不能被高分覆盖；
- 空池子合法；
- 缺失不自动按 0；
- 资格和否决原因稳定；
- 评分不受账户容量影响；
- 排名和容量选择确定性；
- 每日保存全部候选、淘汰原因、分数组成和排名变化。

### 3.7 策略与组合

必须输出完整账户目标，而不是孤立买卖提示：

```text
target_date
asset_id
target_weight
priority
source_strategy
reason_code
evidence
rule_version
parameter_set_id
```

必须覆盖：

- 最大持仓数；
- 单票权重；
- 题材集中度；
- 新增仓位上限；
- 现金缓冲；
- 同日退出和入场顺序；
- 不可成交后的处理；
- 已有持仓与新候选竞争；
- 刚性退出、结果保护和异常退出的优先级；
- 目标组合冻结和取消规则。

具体阈值必须在任务 00 裁决，不得在任务 07 临时决定。

### 3.8 全系统验证

必须完成：

- 全市场 PIT 回测；
- 完整主线周期；
- 不同市场阶段；
- 全链资格、评分、组合和成交；
- walk-forward；
- 参数敏感性；
- 成本和容量压力；
- 规则边际贡献；
- 合法错过和非法错过；
- 空池子；
- 涨跌停、停牌和严重异动；
- 数据缺失；
- 题材、角色和阶段归因；
- 与旧 System B 基础策略对照；
- replay 和数据指纹。

### 3.9 每日运行产品

每天必须提供一个可重新打开的运行包：

```text
readiness
market_state
strategy_authorization
themes
theme_cycles
roles
asset_states
eligibility
scores
ranks
portfolio_target
order_plan
holdings
risk
execution
reconciliation
diagnostics
reproducibility
```

前端必须解释：

- 为什么允许或禁止交易；
- 为什么某题材是主线；
- 为什么某股票获得角色；
- 为什么合格、被否决或未入选；
- 分数由什么组成；
- 目标仓位如何形成；
- 订单为什么成功、失败、撤回或未发送；
- 当前持仓的退出状态；
- 数据是否完整。

### 3.10 实盘交易核心

必须具备券商无关的：

- 账户、持仓、目标、订单、成交模型；
- 订单计划生成；
- 下单前风险门；
- 幂等键；
- 订单状态机；
- 部分成交；
- 撤单与超时；
- 重试边界；
- 断线和重启恢复；
- 外部人工成交检测；
- 持仓和资金对账；
- 日内计划冻结；
- 全局暂停和 kill switch；
- 全部动作审计。

### 3.11 QMT / xtquant

必须实现：

- 连接和账户选择；
- 资产、持仓、委托和成交查询；
- 下单、撤单；
- 回调归一；
- 状态码映射；
- 断线重连；
- 仿真、纸面和实盘模式；
- QRP 订单与券商订单映射；
- 对账和异常处理；
- 不把券商 SDK 细节泄漏到策略和通用交易核心。

### 3.12 调度、监控与恢复

必须具备：

- 日历和任务依赖；
- 数据水位；
- 盘前、盘后和交易时段任务；
- 失败重试；
- 超时；
- 告警；
- 结构化日志；
- 健康检查；
- 备份和恢复；
- 决策、订单和成交不可丢失；
- 重启后恢复当前订单与持仓状态；
- 日结和周结报告。

## 四、正式运行时序

### 4.1 收盘后

```text
更新行情与研究数据
→ 数据质量和水位检查
→ 计算市场、题材、角色和个股状态
→ 运行判断层和 System B
→ 生成完整目标组合
→ 生成次日订单计划
→ 冻结版本与输入快照
→ 人工只读复核
```

### 4.2 次日盘前与开盘

```text
核对交易日、账户、资金和持仓
→ 检查计划是否仍有效
→ 运行实盘风险门
→ 提交允许发送的订单
→ 监听回调和状态变化
```

### 4.3 盘中

- 程序维护订单和成交状态；
- 执行已冻结的策略计划；
- 不接受临时主观选股和价格追逐；
- 只允许制度化暂停、撤单和 kill switch；
- 任何人工动作必须记录并进入对账。

### 4.4 收盘后日结

```text
查询最终资产、持仓、委托和成交
→ 对账
→ 标记异常
→ 保存执行结果
→ 更新持仓状态
→ 生成复盘和归因
```

## 五、发布阻塞条件

出现以下任一情况，不得标记 v1.1 完成：

1. 规则冲突尚未正式裁决；
2. System B 仍只是两个布尔状态；
3. 市场授权、题材和角色仍依赖临时人工口头输入；
4. eligible 与 rank 混在一个不可解释分数中；
5. 目标组合不能从历史输入复现；
6. 回测和实盘使用不同策略语义；
7. 策略或指标直接访问 QMT；
8. 订单没有幂等、状态机或恢复；
9. 部分成交、拒单、断线或重启会导致重复下单；
10. 实盘持仓无法与 QRP 对账；
11. 数据缺失被当成无信号；
12. 前端不能解释授权、否决、评分、目标和执行；
13. 无完整周期和全链系统验证；
14. 全量测试、构建、仿真和小资金验收未通过；
15. 未经人工授权即开启正式资金自动交易。

## 六、正式演示场景

### 场景 A：历史完整回放

```text
选择历史主线周期
→ 以当时可用数据重建市场、题材、角色和趋势
→ 生成每日资格、评分和目标组合
→ 执行现实 A 股回测
→ 查看收益、回撤、错过、归因和 replay
```

### 场景 B：每日盘后计划

```text
完成数据更新
→ 输出市场授权和主线
→ 输出 System B 候选与否决
→ 输出完整目标仓位和次日订单计划
→ 冻结规则、参数和数据快照
```

### 场景 C：QMT 仿真执行

```text
加载冻结计划
→ 风险门
→ QMT 仿真下单
→ 部分成交/拒单/撤单
→ 重连和恢复
→ 日终对账
```

### 场景 D：小资金实盘

```text
严格受限账户和仓位
→ 无人工盘中买卖
→ 自动执行与退出
→ 异常只触发制度化暂停
→ 日结对账无差异
→ 结果进入复盘与回放
```

四个场景均可重复、可审计且可由标准产品重新打开，才说明 v1.1 达到产品终点。
