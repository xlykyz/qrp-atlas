# 任务 09：每日运行产品与前端

## 一、目标

把任务 04—08 的能力编排成可每日稳定运行、可重新打开、可解释、可冻结订单计划的生产产品，并在前端形成交易驾驶舱。

本任务不发送真实订单；它的终点是生成经过数据和规则审计的次日订单计划。

## 二、前置

- 任务 04—08 已验收；
- 完整 System B 目标组合可生成；
- 全系统验证已通过人工批准的生产规则和参数集；
- production run、artifact 和 order plan contracts 已完成。

## 三、每日生产运行

正式流程：

```text
create production run
→ readiness
→ market state / authorization
→ themes / cycles
→ roles
→ asset states
→ eligibility / veto
→ scores / ranks
→ portfolio target
→ order plan
→ freeze
```

每个阶段具有：

```text
PENDING
RUNNING
SUCCEEDED
PARTIAL
FAILED
BLOCKED
CANCELLED
```

阶段失败不得把整个运行伪装为成功。

## 四、readiness 门禁

检查：

- 交易日历；
- 行情完整性；
- daily basic；
- 停牌、涨跌停、ST；
- 严重异常监管；
- 题材/证据来源；
- 规则和参数版本；
- 数据库只读/写入能力；
- 当前账户/持仓快照（订单计划需要时）；
- 任务依赖和 watermarks。

输出：

```text
READY
READY_WITH_WARNINGS
NOT_READY
```

`NOT_READY` 不得生成可执行计划。

## 五、运行产物

每日运行包至少保存：

```text
run.json
readiness.json
market_state.json
authorizations.json
themes.json
roles.json
asset_states.json
eligibility.json
scores.json
ranks.json
portfolio_targets.json
order_plan.json
diagnostics.json
reproducibility.json
```

可使用标准数据库与对象存储/文件结果组合，但必须有单一运行索引和原子提交语义。

## 六、订单计划

从当前持仓与目标组合生成：

```text
BUY / SELL / NO_ORDER
asset_id
current_quantity
target_quantity
quantity_delta
planned_timing
priority
reason_code
source_target_id
```

要求：

- 只使用当时账户快照；
- 明确整数手和现金预估；
- 计划不是订单，不包含券商 order_id；
- 数据、规则或账户输入变更后生成新版本，不原地覆盖；
- 计划冻结后不可盘中随意编辑；
- 可正式取消整个计划或单项（是否允许以任务 00 为准）；
- 计划状态与后续执行状态分离。

## 七、API

至少提供：

- 创建生产运行；
- 查询运行列表、详情和阶段；
- 查询 readiness；
- 查询市场授权、题材、角色、状态、资格、评分和排名；
- 查询目标组合和订单计划；
- 冻结、取消计划；
- 查询规则、参数和输入快照；
- 比较两个生产运行；
- 基于同一历史输入 replay；
- 稳定错误码和 owner 隔离。

写操作需要认证、审计和明确权限。

## 八、前端信息架构

采用研究终端风格，至少包含：

### 8.1 今日总览

- readiness；
- 市场阶段；
- 明日是否允许交易；
- 主线题材；
- 目标持仓数和现金；
- 关键风险；
- 运行状态。

### 8.2 市场与题材

- M1—M6 和 V；
- 题材 activity/risk；
- lifecycle 和 cycle；
- 核心标的；
- 今日变化和证据。

### 8.3 System B 候选

表格必须展示：

```text
asset
role
state
eligible
veto
score
rank
current position
target weight
action
```

支持查看分数组成、证据和历史变化。

### 8.4 目标组合与订单计划

- 当前/目标权重；
- 买卖差额；
- 资金预估；
- 题材集中度；
- 计划状态；
- 冻结/取消；
- 规则和参数版本。

### 8.5 持仓管理

- 当前 System B 状态；
- 首次跌破/恢复/退出；
- 正式退出规则；
- 市场撤权但继续持有的解释；
- 数据和执行异常。

### 8.6 运行与诊断

- 任务阶段；
- 数据水位；
- partial/failed；
- 日志和错误；
- replay/compare。

## 九、解释标准

每个结论至少回答：

```text
what happened
which rule decided
which inputs contributed
what was missing
what version was used
what the next action is
```

不得只显示总分、颜色或“AI建议”。

## 十、交互限制

前端不得：

- 盘中添加临时股票到计划；
- 任意修改已冻结目标权重；
- 绕过市场授权或硬否决；
- 直接调用 QMT；
- 隐藏 partial 数据；
- 把 Agent 自然语言当正式决策。

允许：

- 查看和过滤；
- 运行盘后任务；
- 冻结/取消计划；
- 制度化暂停；
- 提交题材/角色/规则提案；
- 查看审计和对比。

## 十一、Agent 解释

Agent 可在结构化结果上生成摘要，但：

- 不成为权威数据源；
- 不改变资格、评分或目标；
- 每项陈述链接结构化事实和证据；
- Agent 失败不阻塞核心运行结果；
- 输出标注生成时间和模型/版本（适用时）。

## 十二、测试

覆盖：

- 完整生产 run；
- 每阶段失败/partial；
- readiness 阻塞；
- 原子保存；
- 重复运行和幂等；
- 同日多版本；
- 计划冻结和取消；
- owner 隔离；
- API 401/403/404；
- compare/replay；
- 前端 loading/empty/error/unavailable/success；
- 窄屏退化；
- 不伪造数据；
- 大型候选列表性能；
- 规则/参数/输入快照展示。

## 十三、禁止范围

- 不实现真实券商下单；
- 不在前端计算策略；
- 不把任务调度硬编码在页面；
- 不重新定义规则和评分；
- 不用 mock 作为正式模式；
- 不因 Agent 摘要失败将运行标记失败；
- 不实现原生移动 App。

## 十四、验收

- 每日从数据水位到冻结订单计划形成真实闭环；
- 所有结果可重新打开、比较和重放；
- 前端完整解释授权、题材、角色、资格、评分、目标和计划；
- 数据 partial/failed 不被掩盖；
- API、前端和生产 E2E 测试通过；
- 尚未发送真实订单；
- PR 等待独立验收。
