# QRP v1.1 总体验收清单

> 本清单用于 v1.1 最终发布候选复验。  
> 任何未勾选的必须项均阻塞 v1.1 完成；“后续版本”项目不作为门禁。

## 一、范围与治理

- [ ] 产品终点、生产范围和排除项已批准；
- [ ] 规则资产清单完整；
- [ ] 所有冲突已裁决或明确排除；
- [ ] System A 标记为 LEGACY，不进入生产授权；
- [ ] System B 正式生产版本已冻结；
- [ ] System C 明确不属于 v1.1；
- [ ] 判断层只控制新开仓；
- [ ] 规则、参数和策略版本不可变；
- [ ] 变更控制已生效；
- [ ] 每个生产决策可追溯规则和参数版本。

## 二、架构边界

- [ ] 核心抽象保持 `contracts → indicators → strategies`；
- [ ] `trading` 是唯一新增顶级业务模块；
- [ ] indicators 不输出交易动作；
- [ ] strategies 不访问数据库、不调用 backtest 或 QMT；
- [ ] backtest engine 不包含 System B、题材或券商知识；
- [ ] trading 不重新实现策略和指标；
- [ ] QMT SDK 类型不泄漏到 trading 核心；
- [ ] 前端只通过 API；
- [ ] 无循环依赖和第二套公共契约。

## 三、数据与 PIT

- [ ] 任意历史交易日可生成当时全 A 活跃股票池；
- [ ] 上市、退市、ST、风险警示、停牌可历史查询；
- [ ] 涨跌停和价格限制语义正确；
- [ ] 严重异常交易监管事实可查询；
- [ ] 数据缺失、延迟和覆盖率显式；
- [ ] 题材、成员、角色、授权和评分遵守 PIT；
- [ ] 来源、发布时间、可用时间、有效时间、观察时间和修订完整；
- [ ] 历史查询不使用当前 canonical 指针替代历史版本；
- [ ] 上游失败不会被解释为无信号；
- [ ] 数据水位可审计。

## 四、System B 状态

- [ ] 完整生命周期已实现；
- [ ] 状态与账户持仓无关；
- [ ] 全市场逐日可复算；
- [ ] 趋势确认、运行、首次跌破、恢复、退出和重启事件明确；
- [ ] 等于 MA5、缺失值、停牌和复牌语义明确；
- [ ] 多标的隔离和乱序输入确定性；
- [ ] `system_b_basic@1.0.0` 兼容；
- [ ] 正式生产版本使用新 code/version。

## 五、市场判断与授权

- [ ] A/B/C 阶段定义完整；
- [ ] M1—M6 客观组件完整；
- [ ] V 规则完整；
- [ ] 状态确认和滞回明确；
- [ ] 收盘后计算并冻结；
- [ ] 只授权新增仓位；
- [ ] 输出策略级授权、否决、置信度和证据；
- [ ] 历史回放无未来函数；
- [ ] 数据不足时 fail closed 或显式 unavailable。

## 六、动态产业—题材库

- [ ] 行业、产业链和题材分模；
- [ ] theme、version、cycle、alias 完整；
- [ ] 公司—产业、题材—产业和题材—公司关系分离；
- [ ] 事实层和评分层分离；
- [ ] 来源文档、证据、反证和血缘完整；
- [ ] 生命周期和实体治理状态分离；
- [ ] 复燃创建新 cycle；
- [ ] proposal/review/canonical commit 完整；
- [ ] owner 私有空间隔离；
- [ ] Agent 默认只读且不能直写 canonical；
- [ ] PIT 查询、历史回放和 API 完整。

## 七、M1—M3 身份

- [ ] M1、M2、M3 定义和输入冻结；
- [ ] 身份绑定 theme_cycle；
- [ ] 支持多角色和多核心；
- [ ] role eligibility 与 role score 分离；
- [ ] 置信度、证据、反证和 coverage 完整；
- [ ] 首次确认、变化和失效可追溯；
- [ ] 人工/Agent 只生成提案；
- [ ] 历史时点可重放。

## 八、资格、评分和组合

- [ ] eligibility 与 rank 分离；
- [ ] 市场、题材、角色、趋势、可交易性和风险链完整；
- [ ] 硬否决不能被分数覆盖；
- [ ] 空池子合法；
- [ ] 缺失不自动按 0；
- [ ] 全部候选和淘汰原因保存；
- [ ] 分数组成、coverage 和版本保存；
- [ ] 排名确定性；
- [ ] 账户容量不改变股票自身评分；
- [ ] 完整目标组合生成；
- [ ] 已有持仓、新候选和退出顺序明确；
- [ ] 目标组合绑定规则、参数和数据快照。

## 九、完整系统验证

- [ ] 全市场 PIT 回测；
- [ ] 多个完整主线周期；
- [ ] A/B/C 不同市场阶段；
- [ ] walk-forward 和参数隔离；
- [ ] 参数敏感性；
- [ ] 成本和容量压力；
- [ ] 规则边际贡献；
- [ ] 合法错过和非法错过；
- [ ] 空池子和无授权；
- [ ] 涨跌停、停牌、严重异动和数据缺失；
- [ ] 题材、角色、阶段和规则归因；
- [ ] 与 system_b_basic 对照；
- [ ] compare 和 replay 通过；
- [ ] 研究结果不能自动改写生产版本。

## 十、每日运行产品

- [ ] 数据水位到订单计划可一键/定时完整运行；
- [ ] 每日运行包原子保存；
- [ ] 运行阶段和失败原因可查询；
- [ ] 市场授权、题材、角色、资格、评分和目标可重新打开；
- [ ] 前端解释每项授权、否决和排名；
- [ ] 计划可冻结、取消且不可盘中随意修改；
- [ ] 持仓状态和退出条件可查看；
- [ ] 数据不完整有明确阻塞态；
- [ ] 不伪造或静默填充结果。

## 十一、实盘交易核心

- [ ] broker-neutral 领域模型完整；
- [ ] 订单计划和幂等键完整；
- [ ] 下单前风险门完整；
- [ ] 订单状态机完整；
- [ ] 部分成交、拒单、撤单、超时和未知状态完整；
- [ ] 重启恢复先查询券商；
- [ ] 断线不产生重复订单；
- [ ] 外部人工成交可识别；
- [ ] 账户、持仓、订单和成交可对账；
- [ ] 差异进入人工处理队列；
- [ ] 暂停和 kill switch 有效；
- [ ] 所有动作可审计。

## 十二、QMT / xtquant

- [ ] 连接和账户选择；
- [ ] 资产、持仓、委托和成交查询；
- [ ] 下单和撤单；
- [ ] 回调归一；
- [ ] 状态码映射；
- [ ] 断线重连；
- [ ] 纸面、仿真和实盘模式隔离；
- [ ] QRP/券商订单映射稳定；
- [ ] SDK 异常不会绕过风险门；
- [ ] 仿真端到端测试通过；
- [ ] 真实账户默认关闭，需显式授权。

## 十三、调度、监控和恢复

- [ ] 交易日历和任务依赖；
- [ ] 数据水位门禁；
- [ ] 盘前、盘后和盘中调度；
- [ ] 失败重试和超时；
- [ ] 结构化日志和健康检查；
- [ ] 数据、规则、计划、订单和成交备份；
- [ ] 灾难恢复演练；
- [ ] 进程重启恢复；
- [ ] 告警和日结报告；
- [ ] 远程访问不暴露交易端口到公网。

## 十四、正式演示与验收

- [ ] 历史完整周期回放；
- [ ] 每日盘后计划；
- [ ] QMT 仿真执行；
- [ ] 部分成交、拒单、撤单、断线和重启；
- [ ] 日终对账；
- [ ] 连续多日仿真；
- [ ] 受限小资金实盘；
- [ ] 无人工盘中买卖；
- [ ] 最终结果和异常均可复盘。

## 十五、工程门禁

- [ ] 专项测试通过；
- [ ] 全量 pytest 通过；
- [ ] compileall 通过；
- [ ] diff check 通过；
- [ ] 前端 lint/typecheck/test/build 通过；
- [ ] 无 skip 绕过；
- [ ] 无 rebase/force push；
- [ ] 文档、能力矩阵和迁移说明同步；
- [ ] 工作树干净；
- [ ] release PR 独立复验通过。

## 十六、明确不作为 v1.1 门禁

- [ ] System C；
- [ ] System A 恢复为生产策略；
- [ ] short、借券、保证金；
- [ ] 多腿同步交易；
- [ ] 期货、期权；
- [ ] 高频和 Level-2；
- [ ] 强化学习；
- [ ] 分布式回测；
- [ ] 面向第三方的多租户 SaaS 交易平台；
- [ ] 移动原生 App（轻量 Web/PWA 可作为前端增强）。

## 十七、发布结论

只有所有必须项完成、正式演示可重复、仿真和小资金实盘验收通过，并获得人工授权后，才允许：

```text
标记 QRP v1.1
创建 tag / GitHub Release
启用正式账户自动交易
进入下一版本主线
```

蓝图、单个任务或第一次代码下单成功均不能单独满足发布条件。
