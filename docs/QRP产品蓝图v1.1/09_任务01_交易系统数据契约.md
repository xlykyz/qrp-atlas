# 任务 01：交易系统数据契约

## 一、目标

把任务 00 已批准的规则、参数和产品输出翻译为正式 contracts、领域模型、主键、时间语义、版本语义和持久化边界。

本任务只定义“数据是什么”，不计算指标、不生成交易动作、不实现 execution，也不实现 qrp-trading 或 MiniQMT。

## 二、前置

- 任务 00 已验收；
- 初始规则版本集和参数集已冻结；
- v1.1 范围基线已生效；
- qrp-atlas execution 与独立 qrp-trading 的职责边界已批准。

## 四、时间语义

每类对象按适用范围明确：

```text
business_date
trade_date
event_time
published_at
available_at
available_trade_date
observed_at
ingested_at
effective_from / effective_to
valid_from / valid_to
submitted_at
acknowledged_at
occurred_at
received_at
created_at
```

要求：

- `created_at`不替代市场可用时间；
- 事实有效时间与QRP认可时间分离；
- 决策和目标保存当时输入快照；
- live order和gateway event使用timezone-aware时间戳；
- 交易日标签与事件时间分离；
- 所有时区显式，A股业务默认Asia/Shanghai；
- qrp-trading服务器时间、券商事件时间和QRP接收时间分别保存；
- 事件乱序不能通过覆盖时间戳静默修正。

## 五、身份与主键

必须定义稳定身份：

- rule/version/set；
- theme/version/cycle；
- membership/role observation；
- production run；
- target snapshot；
- order plan和plan item；
- order intent；
- QRP client order；
- gateway request；
- broker order；
- fill；
- reconciliation difference。

`client_order_id`必须可用于业务幂等，不得直接使用broker order id作为内部主键。

建议关系：

```text
portfolio_target_item
→ order_plan_item
→ order_intent
→ client_order_id
→ gateway_request_id
→ broker_order_id
→ live_fill
```

任一层允许一对多时必须显式建模，不通过字符串拼接隐藏。

## 七、错误和原因代码

定义分层稳定代码：

```text
business_reason_code
risk_gate_code
oms_transition_code
gateway_error_code
broker_status_code
reconciliation_code
diagnostic_code
```

要求：

- 不把自由文本作为唯一机器语义；
- qrp-trading错误码映射到QRP标准错误，但保留原始代码引用；
- UNKNOWN与REJECTED分离；
- 查询空结果与查询失败分离；
- 协议不兼容有独立错误；
- 所有错误可在前端安全展示且不泄漏凭证。

## 八、owner、账户与权限

- canonical市场、题材和派生事实按产品共享；
- 私有研究笔记、订阅、草稿、agent run和未提交proposal带`owner_id`；
- 生产运行、订单计划、账户、订单、成交和对账全部带owner/account边界；
- 不能仅凭可猜测ID访问其他owner数据；
- 账户只通过脱敏`account_alias`对外；
- qrp-trading真实账户号不进入普通QRP API；
- execution写操作权限与研究读权限分离；
- manual intervention记录操作者、权限、原因和时间。

## 九、幂等契约

至少定义：

```text
production_run_idempotency
order_plan_versioning
client_order_id
request_id
cancel_request_id
attempt_generation
gateway_idempotency_result
```

要求：

- 同一计划重复执行不重复生成订单；
- 同一`request_id`重复调用结果可恢复；
- 同一`client_order_id`不同payload冲突拒绝；
- UNKNOWN后不得复用同一业务身份盲目创建新订单；
- 新attempt使用新generation并保留来源；
- 幂等记录跨进程、跨QRP重启和网关重启持久化。

## 十、兼容与迁移

- 旧`market_phase`保留只读兼容，不继续加字段；
- 旧`trade_execution`保留历史查询，不作为OMS；
- `system_b_basic@1.0.0`和旧结果继续可读；
- 新contracts先增加，再迁移生产者和消费者；
- 提供migration、schema audit、backup和rollback；
- 不通过静默nullable放宽解决不一致；
- 不新增`trading`顶级包作为execution平行实现；
- 未来网关协议升级通过版本兼容记录迁移，不改写历史订单。
