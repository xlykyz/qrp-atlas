本哈希按上述 commit 中目标文件的原始字节计算。路径、commit 或哈希任一变化，都必须形成新的接入记录。

## 2. 来源优先级

工程解释严格遵循源文档 `0.1 规则优先级`：

1. `docs/15_交易系统2.0(初稿).md` 中明确确认的最新规则；
2. 量化重构阶段已确认模块规格；
3. 判断层最终执行规则；
4. System B 历史执行草案与补充条款；
5. 原始交易系统文档。

历史文件只用于证据追溯，不作为 qrp-atlas 的浮动执行输入。

## 3. 仓库职责

| 仓库 | 正式职责 | 禁止越界 |
|---|---|---|
| `MyTradingSystem` | 业务规则、裁决、版本来源 | 不承载 QRP 运行代码和交易网关 |
| `qrp-atlas` | 契约、指标、策略、组合、每日运行、execution、验证与审计 | 不重新定义规则，不补默认阈值 |
| `qrp-trading` | MiniQMT / xtquant 边缘网关、券商原始事实 | 不决定策略、评分和目标组合 |

## 4. 变更接入

```text
MyTradingSystem 裁决并提交
→ 锁定新 commit 与文档哈希
→ qrp-atlas 创建 change proposal
→ 分类为澄清、参数、规则版本或范围变化
→ 更新映射、契约、实现与测试
→ 人工批准后进入新的 rule_version_set
```

禁止仅引用浮动 `main`，禁止原地覆盖历史版本集。
