# 未裁决项与禁止推断

## 1. 全局阻断原则

任一输入不完整、规则版本不明确、参数未批准或评分模型未配置时：

```text
score_status = NOT_CONFIGURED
new_position_authorized = false
reason_code = RULE_OR_PARAMETER_NOT_APPROVED
```

不得把空值转换为 `0`、空身份、最低分或其他可继续下单的默认语义。

## 2. 当前未裁决项

- 最终评分指标集合、归一化、权重和综合分公式；
- M1—M3 的具体映射阈值；
- M4 阈值，M5 权重/衰减，M6 涨停溢价观察时点；
- 节点窗口与门槛、周期细化参数、龙头评分；
- 主线联合判断量化阈值；
- 多候选同批次容量占用算法；
- MA5 退出订单执行时点；
- 严重异动偏离值与监管期的数据契约；
- 严重异动自动下单；
- 多策略资金动态分配、自适应权重和机器学习。

## 3. 允许的工程动作

- 定义稳定枚举、原因码、接口和持久化字段；
- 保存原始 observation、输入快照与 `NOT_CONFIGURED` 状态；
- 建立拒绝路径、负向测试和人工处置审计；
- 为未来批准版本预留版本化扩展点。

## 4. 禁止的工程动作

- 从历史回测结果反推并直接写入生产默认参数；
- 使用现有 `system_b_basic@1.0.0` 的值填充 System B 2.0 空槽位；
- 将容量池、高度池、辨识度池直接等同于 M1、M2、M3；
- 将 M1—M3 反向作为自身评分输入；
- 将未配置评分按零分继续排名或生成目标组合；
- 因评分、身份、题材授权或新候选变化卖出已有持仓；
- 自动执行严重异动减仓或清仓；
- 在 qrp-trading 中实现策略判断或目标组合计算。

## 5. 裁决返回格式

需要 `MyTradingSystem` 裁决时，change proposal 至少包含：

```text
proposal_id
affected_rule_ids
current_source_commit
question
missing_or_conflicting_evidence
candidate_contract_impact
candidate_test_impact
production_blocking_behavior
```

裁决合并后，qrp-atlas 必须记录新 commit、文档哈希、规则/参数版本和生效审批，不得只修改实现。
