# 任务 00：蓝图与交易规则治理封版

## 一、目标

在任何 v1.1 运行代码开工前，把用户现行交易系统拆成正式、无冲突、可版本化的规则基线。

本任务回答：

> 哪些规则属于当前生产系统、它们位于哪一层、使用什么输入、优先级如何、冲突时谁覆盖谁、哪些旧规则只保留历史。

## 二、输入

至少审计：

- `交易系统.docx`；
- `交易第一性原理校准结论.md`；
- `判断层规则_最终执行版.md`；
- `时间约束条款.md`；
- `交易系统B.md`；
- `交易系统 B｜验证期补充条款（20260115草案）.md`；
- 交易系统路径管理图；
- 项目中后续已确认的口头规则与决策记录；
- QRP 当前 `system_b_basic`、市场指标和旧 contracts。

## 三、交付物

### 3.1 规则资产表

每条规则至少记录：

```text
rule_id
rule_name
source_document
source_locator
original_text
normalized_rule
system_layer
input_data
calculation_time
effective_time
output
priority
status
version
conflicts
open_decision
notes
```

状态枚举：

```text
CURRENT
LEGACY
EXPERIMENTAL
DISABLED
REJECTED
```

### 3.2 层级归属

必须把规则分入：

```text
governance
market_state
strategy_authorization
theme
role
asset_state
eligibility
veto
score
rank
portfolio
entry
hold
exit
execution
risk_control
audit
```

同一规则不得在多个层重复实现；需要组合时由上层引用下层事实。

### 3.3 冲突裁决表

至少裁决：

- System A 是否只保留 LEGACY；
- System B 是否存在刚性止损；
- 两日跌破 MA5 与其他退出规则的优先级；
- 浮盈达到 20% 后的结果保护是否进入生产；
- 回撤浮盈 40% 的计算口径；
- 严重异常交易监管是否为全局硬否决和最快退出；
- 市场判断撤权是否影响已有持仓；
- M1—M3 是硬资格、角色标签、评分还是组合；
- 多个 M1/M2/M3 同时存在时的优先级；
- “最先确认”是否继续作为最终排序规则；
- 买入时点、集合竞价未成交、涨停封死和未成交后的处理；
- 最大持仓数、单票仓位、题材集中度和现金缓冲；
- 同日退出和入场顺序；
- 盘中允许的人工控制；
- 全局 kill switch 与策略计划的优先级。

未裁决项不得以默认值进入后续代码。

### 3.4 参数注册表

每个参数记录：

```text
parameter_code
data_type
unit
default
allowed_range
owner_rule
rationale
validation_status
parameter_set_version
```

区分：

- 结构性规则；
- 可调参数；
- 环境配置；
- 账户配置；
- 实盘安全限制。

### 3.5 规则优先级

必须形成一张全局优先级表，例如：

```text
系统安全与 kill switch
> 监管/账户硬风险
> 不可成交与券商事实
> 正式退出规则
> 市场新开仓授权
> 资格与硬否决
> 排名与容量
> 目标权重
> 执行价格和订单策略
```

具体内容以人工裁决为准。

### 3.6 版本和生效

交付：

- 初始 `rule_version_set`；
- 初始 `parameter_set`；
- 生效日期；
- 被替代规则；
- LEGACY 兼容范围；
- 后续变更流程。

## 四、明确结论

本任务应确认但不重新讨论以下蓝图级决定：

- v1.1 唯一生产策略主线是 System B；
- System A 只保留历史资产和归因；
- System C 不属于 v1.1；
- 判断层只控制新增仓位；
- 盘中不允许临时主观下单；
- 生产规则必须可版本化、可回测和可审计。

## 五、禁止范围

本任务不：

- 修改 Python 运行逻辑；
- 新建数据库表；
- 调参或跑收益最优搜索；
- 提前实现 System B 状态机；
- 创建 QMT 下单代码；
- 用近期盈亏替代规则裁决；
- 将草案规则自动升级为 CURRENT。

## 六、验收标准

- 所有来源规则有唯一 `rule_id`；
- 所有冲突有明确结论或被排除出 v1.1；
- 没有两个 CURRENT 规则在同一条件下产生互斥动作；
- 每条 CURRENT 规则有输入、输出、时点和层级；
- 所有阈值进入参数表；
- 规则优先级完整；
- 初始规则与参数版本可供任务 01 建模；
- 范围基线和验收清单同步；
- docs-only 检查通过；
- PR 保持未合并等待独立复验。

## 七、完成定义

任务 00 完成后，后续 Agent 不再决定“交易系统应该是什么”，只负责把已经批准的规则翻译为契约、代码、测试和产品。
