# 任务 11：调度、监控与最终验收

## 一、目标

把 v1.1 全部能力组织为可持续生产运行的系统，完成调度、监控、告警、备份、恢复、连续仿真、小资金实盘和发布候选验收。

本任务不新增交易规则和策略能力，只验证已批准系统能稳定、安全地运行。

## 二、前置

- 任务 00—10-B 全部验收并合并；
- 正式生产规则和参数集已批准；
- 每日运行产品、trading 核心和 QMT 仿真可用；
- 真实账户 live mode 仍默认关闭。

## 三、生产调度

### 3.1 日历

- 使用正式交易日历；
- 处理周末、节假日、临时休市和半日/特殊安排（数据可得时）；
- 所有任务明确业务日期和时区；
- 不使用简单自然日加减替代交易日映射。

### 3.2 建议时序

具体时间可按环境调整并进入配置，职责顺序固定：

```text
盘前：日历、账户、连接、未结订单和前日对账检查
盘中：执行冻结计划、监听状态、健康检查和制度化风险控制
收盘后：行情/研究数据更新、水位、状态、授权、题材、角色、策略、目标和计划
日结：订单/成交/持仓/资金对账、复盘和备份
```

### 3.3 依赖

任务 DAG 必须明确：

```text
source data
→ contracts validation
→ watermarks
→ indicators
→ authorization/theme/roles
→ strategy/targets
→ order plan
→ trading execution
→ reconciliation
→ closeout
```

上游未成功，下游不得无条件运行。

## 四、运行器

支持：

- 手动受控触发；
- 定时触发；
- 幂等业务日期；
- 阶段重试；
- 从安全检查点恢复；
- 取消；
- 超时；
- 单实例/锁；
- 运行历史；
- owner/account 隔离。

交易执行阶段重试必须遵守 OMS 幂等，不能把普通任务重试等同重新下单。

## 五、监控

至少监控：

### 数据

- 来源成功率；
- 行情/题材/监管 coverage；
- 数据延迟；
- schema drift；
- PIT 查询异常；
- 水位。

### 决策

- 市场授权状态；
- 候选和空池子；
- 规则/参数版本；
- 目标总暴露；
- 计划冻结状态；
- 异常数量变化。

### 交易

- QMT 连接；
- 回调新鲜度；
- 活动订单；
- UNKNOWN 订单；
- 拒单率；
- 部分成交；
- 对账差异；
- 账户/持仓快照新鲜度；
- kill switch/control state。

### 系统

- 进程；
- CPU/内存/磁盘；
- DuckDB/PostgreSQL；
- 文件锁；
- API；
- 前端；
- 备份；
- 日志错误率。

## 六、告警

分级：

```text
INFO
WARNING
ERROR
CRITICAL
```

CRITICAL 至少包括：

- 真实交易期间 QMT 断线且有活动订单；
- UNKNOWN 订单；
- 对账重大差异；
- 重复订单风险；
- 账户不匹配；
- 数据水位不足但计划被尝试执行；
- kill switch 失败；
- 订单/成交持久化失败；
- 备份和恢复关键失败。

告警需去重、聚合、带 run/order/account 引用和处理状态。

## 七、日志与审计

- 结构化日志；
- trace/run/order correlation id；
- 规则、参数和代码版本；
- 不记录敏感凭证；
- 关键业务事件追加审计；
- 人工操作明确操作者、原因和时间；
- 日志轮转和保留策略；
- 发生事故时可重建决策与订单时间线。

## 八、备份与恢复

备份至少覆盖：

- contracts 数据库；
- 题材和证据；
- 规则和参数版本；
- production runs；
- targets 和 plans；
- orders、events 和 fills；
- reconciliation；
- auth/users 必要数据；
- 配置（不含明文秘密）。

演练：

- 数据库恢复；
- 运行结果恢复；
- 订单事件恢复；
- QMT 重连后恢复；
- 进程中断点恢复；
- 备份损坏检测；
- 恢复后数据指纹和对账。

## 九、安全与远程访问

- 交易服务只绑定受控网络；
- 外出访问通过加密虚拟局域网或认证隧道；
- 不直接暴露 QMT/交易服务端口到公网；
- 最小权限；
- 写操作认证和审计；
- 真实账户控制与研究前端权限分离；
- secrets 使用环境/安全存储；
- 依赖和配置安全审计。

## 十、验收阶段

### 10.1 历史发布验收

- 完整周期回放；
- 多阶段和多题材；
- 全系统 E2E；
- compare/replay；
- 无未来函数；
- 规则和参数快照。

### 10.2 纸面连续运行

至少连续多个交易日：

- 自动数据更新；
- 盘后计划；
- paper OMS；
- 日结和对账；
- 人工不盘中修改目标；
- 无未解释任务失败。

### 10.3 QMT 仿真连续运行

覆盖：

- 正常成交；
- 撤单；
- 拒单；
- 部分成交或等价模拟；
- 断线；
- QMT/服务重启；
- UNKNOWN 恢复；
- 外部人工操作识别；
- 日终对账。

### 10.4 小资金实盘

前置人工授权后，使用受限配置：

- 单账户；
- 严格总资金和单票上限；
- 有限标的/持仓数；
- 仅已冻结计划；
- 明确 kill switch；
- 每日人工只读复核；
- 任一关键异常自动暂停新增订单；
- 完整日结。

实盘验收看系统正确性、安全性和一致性，不以短期盈利作为唯一标准。

## 十一、事故演练

至少演练：

- 数据源缺失；
- DuckDB 被占用；
- PostgreSQL 不可用；
- 计划生成中断；
- 计划冻结后数据修订；
- QMT 未启动；
- QMT 盘中断线；
- submit 超时；
- 重复回调；
- 本地进程崩溃；
- 磁盘空间不足；
- 订单持久化短暂失败；
- 对账不一致；
- kill switch。

每个演练有预期行为、证据和恢复结论。

## 十四、禁止范围

- 不在验收阶段增加新功能；
- 不修改规则以让近期结果更好；
- 不因一次成功下单跳过连续运行；
- 不因一次盈利宣告完成；
- 不带未解释对账差异发布；
- 不自动打 tag、创建 Release 或扩大实盘资金；
- 不绕过人工最终授权。

## 十五、完成定义

只有在：

- 全部蓝图必须项完成；
- 历史、纸面、仿真和受限实盘通过；
- 调度、监控、恢复和安全边界通过；
- 最终 PR 独立复验通过；
- 用户明确授权；

才允许标记 v1.1 完成、创建正式 tag/Release，并将自动交易从验收状态转入稳定生产。
