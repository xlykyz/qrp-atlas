# 架构与跨仓边界

## 1. 核心依赖方向

QRP v1.1 继续保持：

```text
contracts → indicators → strategies
```

扩展后的产品链为：

```text
pipeline
→ contracts
→ indicators
→ strategies
→ portfolio target
→ production run
→ execution
→ gateway adapter
→ qrp-trading
```

底层不得反向依赖上层；通用回测引擎不得包含 System B、题材、五日线或具体业务规则知识。

## 2. qrp-atlas 模块职责

### contracts

定义标准字段、领域对象、持久化表、主键、PIT 时间语义、版本和 owner 语义。

### pipeline

采集、清洗、标准化、版本化和读取市场及研究事实，不生成策略动作。

### indicators

计算客观状态与事实，包括：

- 基础趋势状态；
- 行情轮次；
- 涨停状态池；
- 容量、高度和辨识度事实；
- 题材指数与题材指标；
- M4、M5、M6 所需客观观察；
- 严重异动事实与监管状态。

指标不输出 ENTER、EXIT 或目标仓位。

### strategies

消费已准备的事实，输出：

- 新增仓授权结果；
- eligible / veto / score / rank；
- ENTER / HOLD / EXIT / NO_ACTION；
- 完整目标组合。

评分公式未冻结前，只实现稳定接口、显式缺失状态和可插拔版本，不得暗置权重。

### backtest

负责数据准备、历史运行、现实成交模拟、组合资金、T+1、停牌、涨跌停、整数手、成本、持仓和绩效评价。

### production product

负责每日运行状态机、输入快照、阶段产物、失败恢复、结果查询和审计。

### execution

`qrp-atlas.execution` 是 v1.1 唯一允许新增的顶级业务模块，负责：

- 目标之后的业务风险；
- 订单计划；
- order intent；
- OMS 状态；
- 幂等；
- 撤单与恢复；
- 账户、持仓、委托和成交快照；
- 三方对账；
- 网关适配。

execution 不直接 import `xtquant`，不管理 MiniQMT 生命周期。

## 3. MyTradingSystem 边界

MyTradingSystem 负责：

- 第一性原理和系统定位；
- System B 业务规则；
- 规则冲突裁决；
- 参数业务含义；
- 历史沿革；
- 新规则批准。

MyTradingSystem 不负责：

- DuckDB schema；
- Python 模块设计；
- API 和运行编排；
- 回测引擎；
- OMS；
- MiniQMT 网关。

## 4. qrp-trading 边界

qrp-trading 是 Windows 边缘网关，负责：

- xtquant / MiniQMT 生命周期；
- 券商账户订阅；
- 原始资产、持仓、委托、成交和行情事实；
- 版本化 REST / WebSocket 窄协议；
- READONLY / TRADE / ADMIN 权限；
- IP 白名单、脱敏和本地审计；
- 接收标准化订单请求并返回网关与券商结果。

qrp-trading 不决定：

- 市场状态；
- 交易策略；
- 买卖标的；
- 方向和数量；
- 目标仓位；
- 业务风险政策；
- 组合替换规则。

## 5. 服务协作

```text
qrp-atlas target snapshot
→ order plan
→ execution business checks
→ versioned gateway request
→ qrp-trading
→ MiniQMT / broker
→ gateway event
→ QRP OMS state
→ reconciliation
```

两仓通过版本化 HTTP / WebSocket 协议连接：

- 不共享数据库；
- 不共享内部 Python 对象；
- qrp-trading API Key 不进入 QRP 数据库或结果包；
- broker order id 不作为 QRP 内部主键；
- `client_order_id` 负责业务幂等；
- 网关 SQLite 审计库不作为 QRP 常规业务查询依赖。

## 6. 回测与实盘一致性

一致的部分：

- 规则版本；
- 参数版本；
- 输入事实；
- eligible / score / rank；
- 策略决定；
- 目标组合；
- 订单计划语义。

分离的部分：

- 回测由通用执行引擎模拟；
- 实盘由 execution + qrp-trading + 券商执行；
- 券商事件、网络失败、幂等恢复和对账只属于实盘链。
