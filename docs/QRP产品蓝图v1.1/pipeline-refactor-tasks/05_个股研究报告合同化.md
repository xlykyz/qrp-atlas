# 任务提示词｜个股研究报告合同化

## 工作目标

将 `src/qrp_atlas/pipeline/research_report/` 中的个股研究数据及报告生产能力正式接入 PipelineContract。

本任务按独立业务逻辑识别 Pipeline，不按 Hermes 的晨间、晚间触发时刻拆分。历史 `research-stock-0700`、`research-stock-1900` 只用于了解旧调用参数和运行事实，不能直接成为正式 `pipeline_id`。

默认目标是一条个股研究报告 Contract。只有源码证明存在与触发时间无关的不同输入、算法、输出或完成语义时，才允许拆成多条。

## 调查范围

重点调查：

- `src/qrp_atlas/pipeline/research_report/`
- 相关研究表 contracts、报告文件格式、CLI、service 和 tests
- 旧 CLI 的日期范围、增量模式、PDF 下载和文件落盘行为
- 历史 wrapper 仅作为调用证据，不作为 Contract 身份或日期策略
- Pipeline 正式开发规则、结果日志和已有 Contract 模式

必须区分确定性数据采集、研究记录入库、CSV/PDF 文件输出、消息发送和可选 LLM 解释。LLM、Hermes 或通知不能成为 Pipeline 成功条件。

## 必须完成

1. 先确定模块内独立业务能力数量。若晨间和晚间只是同一逻辑使用不同日期参数或触发时间，则只建立一条稳定业务 ID 的正式 `PipelineContract`。
2. Contract 名称与 ID 表达个股研究数据/报告生产，不包含 `morning`、`evening`、`0700`、`1900` 等调度标签。
3. 将目标日期或日期范围建模为 `PipelineInvocation` / `TargetDatePolicy` / `ParameterContract` 的业务参数，不从历史 shell 时刻推导。
4. 列清真实外部数据源、输入表和 freshness。不得以模糊的“quant.db”作为输入声明，也不得把 Hermes Agent 伪装成业务依赖。
5. 明确数据库结果、raw/canonical CSV、PDF 和任何投递动作的边界：
   - 只有正式 outputs 才参与 completion；
   - 可选通知或解释失败不影响数据任务结果；
   - 不属于 Pipeline 的投递能力保持在边界外。
6. 明确唯一键、增量/覆盖方式、同一日期范围重跑、历史保留、文件覆盖和部分输出恢复。
7. 涉及 `quant.db` 写入时使用 `quant_db_writer`；实际只读表使用准确 `resource_reads`。文件输出必须采用当前范围内可证明安全的提交方式。
8. 将同一个 `ExecutionControl` 贯穿外部请求、输入读取、批量处理、文件生成和写事务；取消后不得继续请求、生成或提交新结果。
9. 输出标准 `PipelineResult`，包括请求数、处理标的、读取/写入行数、报告文件、阶段耗时和 completion checks。
10. 建立代表性标的规模的本地性能基线，避免逐标的重复全表扫描；不得仅通过提高 timeout 掩盖明显退化。
11. 完整验收后加入 source catalog，并在注册表中明确：多个历史 Hermes Job 可以映射到同一正式业务 Contract。

## 测试要求

至少覆盖：

- 单一业务 Contract 的注册、稳定 ID、显式日期/范围参数；
- 输入缺失、字段缺失、数据过期、无符合条件记录；
- 正常数据库结果和正式报告文件输出；
- 同一目标重跑不产生冲突有效版本或重复历史；
- 数据库、CSV、PDF 之间的真实提交和失败边界；
- provider 失败、部分下载、文件写入失败和事务失败；
- 可选通知、Hermes 或 LLM 不可用时不影响正式 completion；
- 取消/deadline 在请求前、计算中、文件提交前和数据库写入前生效；
- 指标、outputs 和实际文件/表行数一致；
- 已有正式 Contract 不回归。

测试不得访问生产数据库、真实消息渠道或真实 LLM。

## 边界

- 不决定晨间、晚间或任何生产运行时刻，不修改 Hermes cron 或 wrapper。
- 不为了保留两个历史 Job 而复制两个业务 Contract。
- 不重新设计个股研究算法、评分、内容模板或产品展示。
- 不把 Agent/LLM 接入 Pipeline 成功路径。
- 不建设通用报告平台、消息总线或通知中心。
- 不触及行业研究、CNINFO、IRM、手动入库或 System B。
- 对历史 wrapper 与当前源码不一致之处，以当前可执行源码、contracts 和已封板业务文档为依据；无法证明的事实保持 `UNRESOLVED`。

## 完成后汇报

汇报独立业务能力数量、最终 Contract ID、日期/范围参数、确定性输入输出、文件与投递边界、完成/幂等/原子性、性能基线、测试结果、修改文件、历史 Job 映射和未解决事实。不得部署或合并目标分支。
