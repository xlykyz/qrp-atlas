# 任务提示词｜行业研究报告合同化

## 工作目标

将 `src/qrp_atlas/pipeline/research_industry/` 中的行业研究数据及报告生产能力正式接入 PipelineContract。

本任务按独立业务逻辑识别 Pipeline，不按 Hermes 的晨间、晚间触发时刻拆分。历史 `research-industry-0700`、`research-industry-1900` 只用于了解旧调用参数和运行事实，不能直接成为正式 `pipeline_id`。

默认目标是一条行业研究报告 Contract。只有源码证明存在与触发时间无关的不同输入、算法、输出或完成语义时，才允许拆分。

## 调查范围

重点调查：

- `src/qrp_atlas/pipeline/research_industry/`
- 行业分类、成员关系、行情及研究输出对应 contracts
- 相关 CLI、service、tests、报告文件和历史 wrapper
- 旧 CLI 的日期范围、增量模式和文件落盘行为
- 个股研究报告工作包已证明可复用的报告生命周期边界
- Pipeline 正式开发规则

必须确认行业分类来源、成员快照时点、目标日期/范围和聚合完成条件，确保不引入未来可见数据。历史晨间/晚间参数只可作为调用样本，不得成为 Contract 身份。

## 必须完成

1. 先确定模块内独立业务能力数量。若晨间和晚间只是同一逻辑使用不同日期范围或触发时刻，则只建立一条稳定业务 ID 的正式 `PipelineContract`。
2. Contract 名称与 ID 表达行业研究数据/报告生产，不包含 `morning`、`evening`、`0700`、`1900` 等调度标签。
3. 将目标日期或日期范围建模为 `PipelineInvocation` / `TargetDatePolicy` / `ParameterContract` 的业务参数，不从历史 shell 时刻推导。
4. 精确声明行业成员关系、行情、研究或其他输入表及 freshness，确保成员关系和价格数据符合 point-in-time。
5. Hermes Agent、LLM 解释、总结或发送不得成为正式业务输入或成功条件。
6. 明确行业聚合结果、数据库表、raw/canonical 文件和可选投递之间的边界；所有正式 outputs 必须有 completion 和质量检查。
7. 明确同一目标范围重跑、行业成员变化、空行业、无有效成员、部分行业失败和历史保留语义。
8. 写 `quant.db` 时使用 `quant_db_writer`；成员、行情和其他只读表按实际对象进入 `resource_reads`。文件输出采用当前范围内可证明安全的提交方式。
9. 将同一个 `ExecutionControl` 贯穿外部请求、输入读取、行业循环、聚合、文件生成和写事务；取消或到期后不得继续下一个行业或提交结果。
10. 输出标准 `PipelineResult`，至少记录行业数、成员数、读取/写入行数、文件 outputs、阶段耗时和质量检查。
11. 建立代表性全市场行业规模的本地性能基线，重点检查是否存在逐行业重复扫描全表的退化。
12. 完整验收后加入 source catalog，并在注册表中明确：多个历史 Hermes Job 可以映射到同一正式业务 Contract。

## 测试要求

至少覆盖：

- 单一业务 Contract 的注册、稳定 ID、显式日期/范围参数和 PIT 成员语义；
- 行业成员表缺失、过期、空行业、无有效成员和成员跨期变化；
- 行情/研究输入缺失、字段错误和未来数据隔离；
- 正常数据库与正式报告文件输出；
- 同一目标重跑、部分行业失败和提交中断；
- 数据库与文件 outputs 的 completion 一致性；
- 可选通知、Hermes 或 LLM 不可用时不影响正式结果；
- 取消/deadline 在请求前、读取前、行业循环中、文件提交前和写事务前生效；
- 全市场代表规模性能测试；
- 已注册全部正式 Contract 不回归。

测试不得访问生产数据库、真实外部服务、消息渠道或 LLM。

## 边界

- 不决定晨间、晚间或任何生产运行时刻，不修改 Hermes cron、wrapper 或 deploy 启用配置。
- 不为了保留两个历史 Job 而复制两个业务 Contract。
- 不重新设计行业研究算法、行业分类体系、评分或展示模板。
- 不顺手修改 `industry_membership_ingest` 的业务规则；发现输入契约问题时只报告或做当前运行必需的最小兼容修复。
- 不建设通用报表平台、通知中心或 LLM 工作流。
- 不触及 System B，也不为未来题材、概念或多分类体系提前扩展当前 Contract。

## 完成后汇报

汇报独立业务能力数量、最终 Contract ID、日期/范围参数、PIT 成员与输入 freshness、确定性输出、文件/投递边界、完成和幂等、性能基线、测试结果、修改文件、历史 Job 映射及未解决事实。不得部署或合并目标分支。
