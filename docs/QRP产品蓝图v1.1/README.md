# QRP 产品蓝图 v1.1

> 状态：工程实施基线草案  
> 日期：2026-07-26  
> 目标分支：`develop/v1.1`  
> 业务规则来源：`xlykyz/MyTradingSystem`

## 1. 定位

QRP v1.1 的唯一正式生产策略主线是 System B。

本目录只回答：

> 已批准的 System B 业务规则，如何在 qrp-atlas 中被翻译为契约、指标、策略、组合、每日运行产品、执行编排、测试和验收。

本目录不重新定义交易系统，不复制完整业务规则，也不替代 `MyTradingSystem`。

## 2. 双仓职责

```text
MyTradingSystem
= 交易理念、业务规则、规则裁决与版本来源

qrp-atlas
= 数据契约、指标、策略、回测、产品运行与业务执行编排

qrp-trading
= Windows / MiniQMT / xtquant 边缘网关与券商原始事实
```

规则冲突时，必须先回到 `MyTradingSystem` 完成裁决，再进入 qrp-atlas 实现；Agent 不得自行补全阈值、权重或交易规则。

## 3. 当前规则基线

初始接入基线：

```text
repository: xlykyz/MyTradingSystem
commit: 82369650d16914e42c03da7635f410b12a38220e
primary_document: docs/15_交易系统2.0(初稿).md
```

后续实施不得仅引用浮动的 `main`。每个生产规则版本必须保存来源仓库、来源 commit、规则文档和生效日期。

## 4. v1.1 产品终点

```text
外部规则基线
→ 正式数据契约
→ 历史全 A 与可交易性事实
→ System B 状态与股票池
→ 题材和市场结构事实
→ 新增仓授权
→ 资格、评分接口和排名
→ 完整目标组合
→ 每日订单计划
→ qrp-atlas execution
→ qrp-trading 生产窄协议
→ 仿真、对账、小资金实盘与最终验收
```

评分指标、权重、归一化公式和 M1—M3 最终映射当前尚未冻结。v1.1 前期只建立稳定契约、可插拔接口和审计能力，不得用默认值冒充生产规则。

## 6. 分支治理

- `main`：v1.0 稳定维护线；
- `develop/v1.1`：v1.1 长期集成线；
- 所有 v1.1 工作包从 `develop/v1.1` 建分支，并向其提 PR；
- 禁止直接把工作包 PR 提向 `main`；
- 禁止对 `develop/v1.1` rebase 或 force push；
- v1.1 完整验收时创建 `release/v1.1-acceptance`，最终以版本级 PR 合入 `main`。

## 7. 实施原则

1. 主线默认串行，不并行制造多套未验收语义；
2. 事实、决策、组合、执行和评价分离；
3. 回测与实盘消费同一策略决定和目标组合语义，但执行实现分离；
4. 所有历史能力遵守 PIT；
5. 所有用户业务数据遵守 owner 隔离；
6. 生产规则、参数、计算版本和输入快照必须可复现；
7. 未裁决规则不得进入生产代码。
