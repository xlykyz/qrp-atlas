# QRP 产品蓝图 v1.1

> **文档状态：产品终点与实施范围基线草案，等待本 PR 验收**  
> **形成日期：2026-07-22**  
> **审计基线：main `a307e58e138677cadcc38a0da2148639b1f99a5c`**  
> **适用项目：qrp-atlas**  
> **版本定位：在 v1.0 后端产品基线上，完成个人交易系统量化、日常运行产品化与 QMT 程序化执行**

## 一、本成果包的作用

`docs/QRP产品蓝图v1.0/` 已经完成量化研究平台的后端产品闭环，回答了：

> 标准数据、指标、策略、组合回测、结果、API 与前端如何形成可复现的研究产品。

本成果包继续回答：

> 如何把用户现行交易系统完整翻译为可计算、可回测、可审计、可每日运行并可由 QMT 执行的生产系统。

本蓝图不是先做一个最小版本再临时追加规则，而是先冻结完整终点、模块边界、工作分解结构、依赖和验收标准，再按任务包逐步交付。

## 二、v1.1 的唯一主线

```text
全市场与外部信息更新
→ 市场状态与策略授权
→ 动态产业—题材周期
→ M1/M2/M3 核心身份
→ System B 全市场趋势状态
→ 资格与硬否决
→ 评分、排序与目标组合
→ 次日订单计划
→ QMT 程序化执行
→ 成交、持仓与账户对账
→ 日结、复盘、归因与回放
```

生产策略范围：

- `System B`：v1.1 唯一实盘生产策略主线；
- 判断层：只决定新开仓授权，不接管既有持仓退出；
- `System A`：标记为 `LEGACY`，保留历史研究与归因，不进入实盘授权链；
- `System C`：不属于 v1.1；
- 第一性原理、时间约束和规则版本：属于治理与审计层，不直接生成单笔交易信号。

## 三、受控架构扩展

v1.0 的核心量化抽象继续保持：

```text
contracts → indicators → strategies
```

v1.1 增加一个受控顶级模块：

```text
trading
```

其职责仅限实盘计划、风险门、订单生命周期、券商适配、回调、恢复与对账。`strategies` 不得直接调用 `xtquant`，`trading` 不得把券商状态写回为策略事实，通用回测引擎不得包含 QMT 知识。

## 五、状态标记

| 标记 | 含义 |
|---|---|
| ✅ 已完成 | main 中已有稳定代码、公开接口和测试 |
| 🟡 部分完成 | 已有可复用基础，但不能独立满足 v1.1 场景 |
| ⚪ 契约或设计已有 | 文档、字段或原型存在，尚未形成正式运行链 |
| ⛔ 未实现 | 当前 main 没有稳定实现 |
| 🔒 范围冻结 | 已进入范围基线，不得在任务中临时改变 |
| ➡ 后续版本 | 明确不阻塞 v1.1 |

## 六、使用方式

1. 先读 [01](./01_QRP_v1.1_当前能力审计与能力矩阵.md) 确认地基和缺口；
2. 用 [02](./02_QRP_v1.1_产品终点.md) 判断需求是否属于 v1.1；
3. 用 [07](./07_QRP_v1.1_范围基线与变更控制.md) 处理新增想法和规则变更；
4. 严格按 [04](./04_QRP_v1.1_开发路线图.md) 和 [05](./05_QRP_v1.1_Agent任务包.md) 逐包执行；
5. 每个任务完成后同步能力矩阵和 [06](./06_QRP_v1.1_总体验收清单.md)；
6. 未经人工验收，不得跨任务提前宣称 v1.1 可实盘运行。

## 七、蓝图封版含义

蓝图合并只表示：

- 产品终点、范围、模块和工作包获得批准；
- 可以按已批准顺序开始实现；
- 新想法必须通过变更控制进入后续版本或正式变更单。

它不表示任何 v1.1 运行能力已经完成，也不授权实盘下单。
