# 任务 10-A：实盘交易核心

## 一、目标

新增券商无关的 `trading` 顶级模块，将冻结订单计划安全地转换为受控订单生命周期，并完成风险门、幂等、恢复和对账核心。

本任务不依赖 QMT SDK，不发送真实券商订单。

## 二、前置

- 任务 01、07、09 已验收；
- 正式目标组合和订单计划契约稳定；
- 生产计划可以冻结；
- 任务 00 已冻结人工干预、未成交和退出优先级。

## 三、模块结构


## 五、BrokerProtocol

定义稳定协议：

```text
connect()
disconnect()
health()
query_account()
query_positions()
query_orders()
query_fills()
submit_order(command)
cancel_order(command)
subscribe_events(handler)
```

协议必须支持同步/异步适配策略，具体形态以项目技术选择为准，但核心 service 不依赖特定券商。

## 六、订单计划到订单意图

转换过程：

```text
frozen order plan
+ latest account snapshot
+ latest broker positions
→ delta validation
→ risk gates
→ order intents
```

要求：

- 计划版本不可变；
- 使用最新账户事实验证，但不反向修改策略目标；
- 差异超限时阻塞并要求重新生成计划；
- 数量、方向和优先级确定性；
- 整数手和特殊退出规则明确；
- 所有 intent 绑定 source plan item。

## 七、风险门

至少包括：

### 系统门

- trading enabled；
- control state；
- kill switch；
- 正确交易日和时段；
- production run 和计划已成功冻结；
- 数据和账户快照未过期；
- broker health 正常。

### 账户门

- 账户身份匹配；
- 可用资金；
- 当前持仓；
- 单票和总暴露；
- 题材集中度；
- 当日新增风险；
- 订单数量和金额上限；
- 目标与账户差异。

### 订单门

- asset 合法；
- side/quantity/price type 合法；
- 幂等键未使用；
- 无冲突活动订单；
- 不重复卖出超可用数量；
- 不重复买入已满足目标；
- 计划未取消或过期。

风险门 fail closed，并输出稳定 reason code。

## 八、幂等

`client_order_id` 必须由稳定业务身份生成，例如：

```text
account + plan_id + plan_item_id + attempt_generation
```

要求：

- 重复调用不重复发送；
- submit 超时后先查询/恢复，不盲目重发；
- broker order id 返回后建立唯一映射；
- 未知结果进入 `UNKNOWN`，等待查询和对账；
- 只有正式新 attempt generation 才允许再次提交。

## 九、订单状态机

至少支持：

```text
PLANNED
VALIDATED
BLOCKED
SUBMITTING
SUBMITTED
PARTIALLY_FILLED
FILLED
CANCEL_PENDING
CANCELLED
REJECTED
EXPIRED
UNKNOWN
```

要求：

- 每次迁移有事件、时间、来源和原始 broker payload 引用；
- 非法迁移拒绝；
- 回调可乱序和重复，处理必须幂等；
- 部分成交数量累积不可超过订单数量；
- 终态不可被普通旧事件回退；
- `UNKNOWN` 不能自动等价 `REJECTED`。

## 十、纸面执行适配器

实现 broker-neutral paper adapter：

- 不连接真实账户；
- 使用明确价格和成交规则；
- 可模拟全部成交、部分成交、拒单、延迟和断线；
- 复用相同 OMS、风险门、store、recovery 和 reconciliation；
- 不以 backtest engine 替代 live OMS 测试。

## 十一、持久化

必须原子保存：

- control state；
- 计划执行状态；
- orders；
- order events；
- fills；
- account/position snapshots；
- broker mappings；
- reconciliation；
- manual interventions。

支持跨进程锁、崩溃恢复和重复启动。

## 十二、恢复

启动顺序：

```text
load local state
→ connect broker
→ query account/positions/orders/fills
→ match broker references
→ replay missing events
→ reconcile
→ resolve UNKNOWN where possible
→ enable new submissions only after recovery gate
```

恢复期间禁止发送新订单。

## 十三、对账核心

比较：

- 目标组合；
- 订单计划；
- 本地订单/成交；
- broker 委托/成交；
- broker 持仓/资金。

差异分类：

```text
MISSING_LOCAL_ORDER
MISSING_BROKER_ORDER
FILL_MISMATCH
POSITION_MISMATCH
CASH_MISMATCH
EXTERNAL_MANUAL_TRADE
UNKNOWN_ASSET
STALE_SNAPSHOT
```

差异不可通过覆盖本地数据自动消除。

## 十四、人工控制

允许的制度化控制：

- enable/disable；
- pause new submissions；
- cancel pending plan；
- cancel active order（经权限和审计）；
- kill switch；
- 对账差异处置。

不得提供盘中临时增加标的、修改策略分数或绕过硬否决的接口。

## 十五、API

只暴露 broker-neutral API：

- control state；
- paper account；
- plans/orders/fills；
- execute frozen plan；
- cancel order/plan；
- reconciliation；
- recovery status；
- health；
- audit。

真实 broker 适配在任务 10-B 注册。
