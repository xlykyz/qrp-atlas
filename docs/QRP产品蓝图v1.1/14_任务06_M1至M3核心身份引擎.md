# 任务 06：M1—M3 核心身份引擎

## 一、目标

把容量核心、空间前排和辨识度从永久标签或主观口头判断，建设为绑定题材周期、可评分、可审计、可历史回放的角色观察系统。

## 二、前置

- 任务 03、05 已验收；
- 任务 00 已冻结 M1—M3 定义、硬条件和优先级；
- 题材周期、成员事实、市场与个股指标可用。

## 三、角色模型

正式角色：

```text
M1_CAPACITY_CORE
M2_SPACE_FRONT
M3_IDENTIFIABLE
```

角色是：

```text
theme_cycle × asset × observed_at
```

不是股票永久属性。

同一标的可以：

- 在一个周期内拥有多个角色；
- 在不同题材周期拥有不同角色；
- 随时间升级、降级或失效。

同一题材可有多个候选，但必须保存各自分数、置信度和证据。

## 四、输入

### M1 候选输入

按任务 00 定义，通常包括：

- 成交容量和持续性；
- 市值/流通市值；
- 题材成交贡献；
- 领涨贡献；
- 流动性；
- 趋势持续；
- 核心排名稳定；
- 承压和修复能力；
- 业务相关度和证据。

### M2 候选输入

通常包括：

- 连板/高度；
- 空间领先；
- 首次和持续领先日期；
- 封板质量、炸板和回封；
- 题材共振；
- 可交易性和监管风险。

### M3 候选输入

通常包括：

- 题材内关注度；
- 领涨辨识度；
- 历史人气和市场记忆；
- 新闻/社区注意力；
- 相对强度；
- 关键事件和业务逻辑；
- 角色持续性。

最终字段和权重必须来自任务 00 的批准版本。

## 五、eligibility 与 score

每个角色先判断角色资格，再评分：

```text
role_eligible
role_veto_reasons
role_score
role_rank
confidence
coverage
```

要求：

- 不用总分覆盖角色硬条件；
- 缺失不按 0；
- 业务证据不足与市场共振弱分别表达；
- 可交易性与角色身份分离；
- 严重异常等交易硬风险不能篡改历史角色事实，但可作为生产资格否决。

## 六、角色观察与事件

保存：

```text
role_first_confirmed
role_confirmed
role_upgraded
role_downgraded
role_invalidated
role_recovered
```

每次观察包含：

```text
cycle_id
theme_id
asset_id
role_code
eligible
score
rank
confidence
coverage
reason_codes
components
evidence_ids
calculation_version
rule_version_set_id
parameter_set_id
observed_at
valid_from / valid_to
```

## 七、确认、持续和失效

必须明确：

- 首次确认需要几日/几类信号；
- 单日异常是否改变角色；
- 最短持续时间；
- 分数下降和硬条件失效的区别；
- 题材进入 diverging/cooling 后角色如何保留历史；
- cycle 结束后角色自动结束；
- 新 cycle 不继承旧角色，只能把历史作为特征。

## 八、人工和 Agent 提案

人工/Agent 可以提交：

- 新角色候选；
- 角色升级/降级；
- 证据补充；
- 反证；
- 规则误判说明。

但不得直接覆盖模型观察。最终产品同时保存：

- model observation；
- approved override（如允许）；
- final role state；
- override 原因和 expires_at。

## 九、接口

至少提供：

- 某日/某周期全部角色；
- 某题材角色排行；
- 某股票历史角色；
- 当前有效角色；
- 角色组成和证据；
- 模型/人工最终状态；
- PIT as_of 查询；
- 变化事件；
- API DTO 和前端解释结构。

## 十、System B 边界

本任务只输出角色事实与角色政策结果，不生成 System B 最终资格或交易动作。

任务 07 将使用：

```text
market authorization
+ theme authorization
+ role observation
+ asset state
+ tradability
```

形成生产资格和排名。

## 十一、测试

覆盖：

- M1/M2/M3 正常确认；
- 多角色；
- 同题材多候选；
- 分数并列和稳定排序；
- 角色持续、升级、降级、失效；
- cycle 结束和新 cycle；
- 缺失、coverage 和 unknown；
- 证据和反证；
- 模型与 override 分离；
- override 到期；
- PIT 和修订；
- 多 owner 私有提案隔离；
- API 和历史回放；
- 不因账户持仓/容量改变角色分数。

## 十二、禁止范围

- 不生成最终 eligible pool；
- 不生成目标权重；
- 不把角色永久写入 stock_info；
- 不把题材 activity 直接当 M1/M2/M3；
- 不因实盘持仓给角色加分；
- 不允许 Agent 直接提交 canonical 角色；
- 不在本任务调整任务 00 已批准的角色定义。

## 十三、验收

- M1—M3 从主观标签升级为正式角色引擎；
- 角色绑定题材周期并可历史回放；
- 资格、分数、置信度和证据完整；
- 多角色和多核心可表达；
- 模型与人工覆盖可审计；
- 专项、全量、PIT 和 API 测试通过；
- PR 等待独立验收。
