# 蓝图文档模板

## 推荐目录

```text
docs/<产品或项目>产品蓝图<版本>/
├── README.md
├── 00_项目章程与启动决策.md
├── 01_当前能力审计与能力矩阵.md
├── 02_产品终点.md
├── 03_需求与追踪矩阵.md
├── 04_数据与模块扩充规划.md
├── 05_开发路线图与WBS.md
├── 06_Agent任务包与执行规则.md
├── 07_总体验收清单.md
├── 08_范围基线与变更控制.md
├── 09_风险登记与分级授权.md
└── tasks/
    ├── WP00_<名称>.md
    ├── WP01_<名称>.md
    └── ...
```

既有项目已有稳定编号体系时可以沿用，不必强制迁移。小项目可合并需求、风险和变更文档，但对应管理逻辑不得丢失。

## README 模板

```markdown
# <项目> 产品蓝图 <版本>

> 文档状态：
> 形成日期：
> 审计基线：
> 适用仓库：
> 架构状态：
> 批准状态：

## 一、成果包作用

回答：
- 当前真实状态是什么；
- 完整终点是什么；
- 哪些属于本版本；
- 如何分解和按什么顺序实施；
- 怎样才算完成；
- 如何管理变化。

## 二、目录

| 文档 | 用途 |
|---|---|

## 三、状态标记
## 四、核心范围决定
## 五、总体终点
## 六、使用顺序
## 七、合并语义
```
